## Current controls precede final publication

Properties Apply and Project Settings already prepare validated immutable document candidates and Undo deltas on workers. Their delivery callbacks previously also committed the edit, before the next footer could process Cancel/Escape. Both sessions now use one-slot CPU mailboxes and delivered-ready state. UI delivery alone changes no committed values, private draft, history or Settings-window lifetime. Queued callbacks hold request identifiers rather than prepared projects; retired completed candidates are released independently of callback draining.

Properties keeps its existing RUNNING phase and Cancel Apply action through readiness. Delivery does not change work version or action identity. The panel captures its shown work version, processes the footer and child-editor/reference controls, unwinds native window scopes and only then accepts that same work. Exact project/private/raw/selection/diagnostic and prepared checkpoint/history/policy checks remain authoritative around its blocker callback. Cancel Apply or Escape wins on its activation frame; collapse cancels pending work while retaining the private Properties resource for explicit retry. Accepted publication consumes before ordinary draft refresh, remains one Undo boundary and cannot repeat after a refresh failure.

Project Settings retains its three exact raw fields and applying state through delivery. The panel handles Cancel/Escape, Discard and Reload, Show Problem and current Apply before accepting the same session and shown work version. Acceptance independently verifies the complete displayed raw map still equals both captured input and session text; mismatches retire preparation and retain text for explicit correction/retry. A numeric-equivalent raw edit also retires old authority. Successful publication still updates only project seed/minY/maxY, consumes/closes the private settings form and preserves separate Properties draft identity, values, selection and provisional seed input. Ordinary Properties Apply instead commits its owned resource and refreshes that private draft.

No second confirmation or second Apply click is added. Synchronous direct constructors keep their existing behavior. Generation rules, inheritance, project/config schemas, headless APIs, explicit project Save and user preference domains are unchanged.

## Host suspension and recovery

Collapsing Properties cancels its pending Apply. Collapsing the shared Settings window calls ProjectSettingsPanel.suspendActions, retiring its queued/ready preparation while keeping private raw fields and buffers for reopening. Closing Project Settings, switching to another Settings page and final disposal retain the existing private-form cancellation policy. A ready result cannot close a window before its current-frame X/Cancel/Escape is handled.

Cancel, suspension, close, stale input and successors invalidate mailbox ownership and best-effort cancel/remove queued work. Late/duplicate deliveries cannot populate or consume another request. Worker failures and rejected candidates remain cancellable before their result feedback is accepted. Current failures/rejections retain bounded feedback and explicit retry; unchanged frames do not schedule more work. Changed source/checkpoint/history/policy, private inputs, diagnostics or blockers still reject old candidates. Successful equal-value publication consumes without discarding existing Redo.

Owner snapshot capture, full comparisons, diagnostics, native control processing, final history installation and draft refresh retain UI-thread cost. Cancellation does not interrupt every compiler phase, and a still-running retired worker may retain its own inputs until it exits. This does not change unrelated background-operation publication policies or claim measured latency/memory, physical input, DPI/OS or complete Windows 11 behavior.
