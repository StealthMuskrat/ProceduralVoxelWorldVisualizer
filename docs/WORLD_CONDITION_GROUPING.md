# World logical condition editing — unvalidated development

This main-branch implementation addresses specification 10.2 (atomic inherited settings), 10.5.4–10.5.7 (occupied-only negative tests, exact finite grouping and nonempty groups) and 10.7 (ordered same-cell evaluation). It is source development, not acceptance evidence. The owner testing pause remains active; no compilation, JUnit, engine replay, native probe or GitHub workflow was executed. The last observed validated baseline remains 922 tests / 120 suites.

## Authored grouping

WorldConditionEdits centralizes structural operations on private Predicate/Gate drafts. Selecting AND/OR for a basic condition retains an owned copy of that condition as the first clause. Switching AND and OR preserves every clause and its order. Selecting NOT for a gate retains the whole existing expression as exactly one child; switching NOT to AND/OR retains the negated expression rather than silently dropping its negation. Basic kind selection explicitly replaces subclauses. Predicate reference UUIDs survive changes inside the same type-reference or set-reference family; a different reference family starts unbound for deliberate selection.

The existing last clause cannot be removed. NOT cannot gain a second child. A malformed private NOT with extra children can remove them until one remains; an empty private group can add its first clause. Use Only Child explicitly removes a one-child group, including the negation of NOT. Copies own their mutable child trees, references remain UUIDs, and probability values/exact signed-long seed offsets remain unchanged inside retained clauses. Probability outcomes are not claimed invariant under regrouping: existing engine draws include the gate's structural path. Both the editor and central Help explain that consequence.

The editor supports the validator's existing root-depth-zero limit of 32 nested levels. A prospective wrapper checks the whole active subtree before changing the root, preventing a deep descendant from becoming depth 33. Rejected depth edits leave the authored tree intact and show feedback. Add is disabled at the limit. Deep tree headers stop adding visual indentation after three levels while retaining nested IDs and explicit level labels; the outer Properties body continues to scroll. Conditions deeper than the supported limit offer parent replacement for repair.

## Transaction and input ownership

These actions edit existing layer defaults or the already-enabled atomic placement override. Inherited settings still require the existing Override action. Reset still removes the sparse override key, and no resolved copies are added to other properties. Properties Apply remains one project transaction; Undo/Redo and explicit Save retain their existing authority. No preferences, engine evaluation, model fields, schema or file format changed.

Native value/action IDs include a structural version so numeric/seed controls cannot reuse a predecessor's ID after regrouping. Tree expansion IDs remain separate. Selection/draft replacement clears local feedback. Removal is applied after the child drawing loop, preventing shifted indices from skipping a row. Successful gate changes detach invalid raw seed text under the changed subtree using the existing seed ledger; the text remains visible in Properties problems and still blocks Apply until explicit repair/restoration. Rejected/no-op structural edits do not orphan text.

Predicate child controls now use complete indexed paths. Validator predicate paths likewise include every /children/index and end reference failures in /reference. Gate probability, comparison, field reference, threshold and maximum failures identify their specific leaf while preserving diagnostic codes. Candidate UUID context remains supplied by DiagnosticLocations. Historical collection-index navigation continues its existing fallback to the owning setting; an old index does not authorize selecting a current row.
