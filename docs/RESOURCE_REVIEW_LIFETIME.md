# Resource review document lifetime and publication

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. The validated baseline remains 922 tests / 120 suites. This extends [Import](IMPORT_WORKSPACE.md), [Export](EXPORT_WORKSPACE.md) and [portable file safety](RESOURCE_PACKAGE_FILES.md) for specification sections 2.8/3.4 and A07; it supplies no new passing evidence.

Import and Export reviews now capture the exact document session token alongside project UUID, canonical object and editor revision. Opening the same saved project again retires the previous review even if its UUID, values and revision match. Its immutable preview stays inspectable, but Reload and publication remain unavailable. Cancel and a fresh review establish authority in the new document. Import also checks logical project UUID before treating a preview as current.

Within one document, Save and failed Open preserve review authority. Ordinary edits and history still permit explicit Reload, which retains choices and requires the replacement preview to be displayed. Existing complete-value publication checks and stable reviewed COPY identities remain. Private Properties drafts, selected UUIDs and invalid raw seed text remain separate from committed resources.

An accepted Import stays busy through complete candidate validation and the single document transaction. Nested Apply returns an internal BUSY result; Cancel, choice changes, Reload and panel replacement cannot discard that publishing workspace. An accepted Export stays busy through validation, staging and replacement. Nested writes, selection changes and Reload reject; normal package/resource/export reset and Cancel entry points preserve the active session and selection. Resource transitions observe export busy state. Both fences release in finally blocks, allowing an explicit retry after failure with the same reviewed preview when its source remains current. Success consumes the review. Package completion releases only the export session owned by that package opening.

Editor Export supplies a live active-project path to the existing protection checks before directory creation, after parent preparation and after staging. A standalone Save As during staging can therefore make the destination protected before replacement. The writer then removes its temporary file and preserves the newly saved project. The existing value-path writer remains available for callers with a fixed protected path. Atomic replacement, strict envelope validation and version numbers are unchanged. The filesystem may still change after the final check; arbitrary storage-provider, validator or direct-model side effects are outside these guards.
