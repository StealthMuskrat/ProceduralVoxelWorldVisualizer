## Adopt only the current result and display Included again

An opaque request identity and FutureTask belong to the UI session. Rapid selections, Reload, reset, Cancel, Escape and lifecycle closure retire the old identity, cancel its task and remove queued work when the executor supports removal. Non-cooperative work can finish later, but its callback cannot install a catalog/payload or reopen a cancelled/successor review. A normal worker exit grants no publication authority: results wait for explicit UI delivery.

Adoption checks document lifetime, project object/UUID/revision, exact committed JSON values, saved path/dirty baseline, selected resource/siblings, Properties draft object/values and raw-seed ledger. The current private/project-action blocker is checked, then request and owner authority are checked again to contain reentrant cancellation, replacement and edits. Changed committed sources require explicit Reload. Private/input/blocker changes retire preparation and permit an explicit retry where the document still allows it.

Installing a result does not acknowledge it. Export remains disabled until the current Included preview has actually been displayed and its selected UUIDs match the desired selection. Old or foreign equal-value previews cannot acknowledge a replacement. The session repeats those requirements before returning an export snapshot, synchronous writing or publishing prepared staging. A caller that clears/replaces a compatibility prepared model causes background rebuilding and renewed review rather than synchronous reconstruction in the production session.

Missing selected UUIDs survive Reload as explicit unresolved selections. The new catalog is installed with no exportable preview. Remove Missing operates only against that source's catalog and schedules another closure; it never drops missing UUIDs silently. An empty selection can have an empty preview but cannot export. Missing status from an older catalog cannot enable removal while Reload is pending.
