# Workspace docking, visibility and normal window size

Status: implemented on `codex/development-phase`, uncompiled and untested. Compilation, native probes, schema/replay validation and GitHub testing remain deferred. Historical workspace evidence applies to its recorded baseline.

## Owned default layout requests

Both View > Reset Dock Layout and User Settings > Workspace > Restore Default Docking now use WorkspaceLayout. A reset remains pending independently of the saved INI string until the default builder succeeds. Periodic or shutdown capture cannot publish older native INI while that request is pending. A failed builder retains the request for retry, and a newer reset issued during a builder/capture callback cannot be consumed by the older operation. Loaded nonblank layouts do not trigger a default rebuild. This fixes the previous same-frame ordering in which periodic capture could write the old nonblank INI and prevent the requested reset.

WorkspaceDocking shares the production Resources-left/Properties-right/Visualizers-center builder with its deferred native scenario. PanelDockControls applies explicit actions before the following window Begin. Undock remembers the current numeric dock identity; Redock returns to it only if it still exists. Native node pointers are queried locally and never retained across frames. Removed pending targets are discarded rather than creating phantom floating nodes. ImGui can remove/merge empty nodes; when the former target is unavailable, the visible Redock (default layout) action explicitly restores the full three-panel default arrangement. Its tooltip names that scope. Global reset clears pending per-panel actions. Resources and Properties respect Begin visibility for their content; separate private dialogs retain their own lifetimes. Resource index synchronization still supports those dialogs, and collapsed Resources cannot retain shortcut focus/drag ownership.

These calls use the existing pinned imgui-java 1.89.0 docking API. Internal node APIs are not assumed stable across dependency updates; the [upstream builder guidance](https://github.com/SpaiR/imgui-java/blob/v1.89.0/imgui-binding/src/main/java/imgui/internal/ImGui.java) explicitly prohibits retaining node pointers. Actual gesture, split/merge/backend and OS-detached acceptance is still pending.

## Persisted tool visibility and size

User Config format 1 adds optional workspace.visibleWindows, a unique list from Find, Logs, Validation, Help, Notifications, Profiler and Themes. Missing historical lists mean those tools start closed. The schema, reflective contract generator and default/valid/invalid fixtures share the same public catalog; unknown/private/transient window names, duplicates and null lists reject. Reads do not rewrite old files. Settings > Workspace exposes the actual tool flags, and menu/shortcut/title-bar changes are captured into the same list. Unchanged captures retain the existing saved list instead of replacing it every frame.

Restoring tool visibility does not restore private editor drafts, file-transition decisions, update requests or resource selection. Showing Profiler does not start instrumentation; showing Themes begins from the active saved palette. No update-check result window is reopened from this list. Main Resources, Properties and Visualizers remain the fixed primary workspace. Their individual docking position/size continues to use ImGui's saved INI. Hiding/showing arbitrary private dialogs or the primary panels is not added by this list.

Desktop now captures actual logical GLFW main-window width/height and sets the same 400x300 minimum used by preference validation. Zero/subminimum, iconified and maximized measurements do not replace the last normal size. Existing width/height fields drive the next startup. Reused native argument buffers avoid per-frame array allocation. Periodic capture and shutdown persist current tool flags and native INI only after default layout publication. This batch does not add saved main-window physical X/Y, maximized state, monitor work-area recovery or per-monitor DPI handling. Independent scale overrides remain as previously implemented; complete scaling/layout acceptance is not claimed.

Workspace changes remain User Config only: no project dirty state, history, raw Properties seed or resource value is derived from docking, window visibility or size. Default reset does not apply/discard private authoring. User/App/Project format versions and engine APIs stay unchanged.

These definitions have not run.

WorkspaceProbe defines real Resources/Properties Undock/Redock or explicit default-layout fallback controls, the real Workspace visibility/default controls, a same-frame capture attempt after Reset, actual INI persistence and a fresh ImGui context with saved INI. It reopens a production Profiler panel without starting capture, retains private resource ID/raw seed/project/history in the first session, and starts a new empty project in the second. This scenario does not certify a full desktop launch, detached GLFW windows or physical monitor behavior.
