# Project history completion and successor ownership

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. The validated baseline remains 922 tests / 120 suites. This extends [project history ownership](PROJECT_HISTORY_OWNERSHIP.md), [shared decision delivery](NAVIGATION_DECISION_DELIVERY.md) and [named dialog scaling](DIALOG_OWNER_SCALING.md). No A01–A36 acceptance gate advances.

ProjectHistoryPanel previously called its session while the confirmation popup was still active. A blocker or successful history refresh therefore ran in that popup's native scope. History request/decision checks also invoked a supplied blocker without rechecking whether it had replaced the pending intent or changed private input. A successor could be overwritten or cleared by the earlier attempt. A refresh exception after a successful model step could escape without distinguishing a completed Undo/Redo from a failed move.

The panel now collects Discard/Cancel and Escape, ends child/ID/popup scopes through finally blocks, and then delivers the decision in the caller window. It uses exact opening/frame tickets and draws once per frame. The displayed admitted request version must still match before delivery. Terminal popup cleanup occurs in a separate balanced scope only when the model session has no successor pending. A new request opened by a blocker gets its own next-frame dialog identity; the older completion leaves it intact. Escape still takes precedence over a released Discard action.

ProjectHistorySession keeps admission versions separate from a transient retirement generation. Blocked/unavailable requests do not advance the admitted version. Request and decision gates retain their opening context, recheck exact ownership after the callback, and cannot overwrite/retire a reentrant successor. Changes to private input during a gate reject the old action. Gate runtime failures produce bounded PROJECT_HISTORY_GUARD_FAILED errors while preserving the appropriate private state and successor. Cancel remains independent of the blocker.

An accepted move retires the old pending intent before document reconstruction/validation and holds a busy flag through model movement and UI refresh. Nested history requests/decisions are unavailable during that interval. Desktop file and import/export blockers use the complete busy state rather than only pending confirmation state. This closes the interval between consuming the old decision and finishing its refresh. The underlying DocumentSession delta algorithm and validator behavior are unchanged.

Model failure reports PROJECT_HISTORY_FAILED, releases the busy state and retains the model/stacks/private input under the existing failure contract. Successful movement increments editor revision once. Refresh runs once afterward; if it throws, the result remains MOVED and PROJECT_HISTORY_REFRESH_FAILED explicitly identifies the completed Undo/Redo. The old confirmation cannot replay it. The user may initiate another explicit history action. Production refresh still uses the existing selection reconciler. This is not recovery from arbitrary side effects in a custom validator or a guarantee that every possible refresh failure leaves all presentation state reconciled.
