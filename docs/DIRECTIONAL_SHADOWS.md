# Bounded directional mesh shadows

User Settings > Visualization now offers opt-in Directional shadows and a maximum map resolution of 512, 1024 or 2048. Historical User Config v1 documents keep shadows disabled and default to 1024. The two new fields are optional in the current schema so historical files remain valid. Older readers that reject unknown fields require an update; an invalid resolution or coerced/null preference rejects in the strict reader. User Config remains outside project/history and compiled world data.

Fixed triangle meshes, scalar isosurfaces and streamed triangle meshes cast and receive shadows from the existing directional light towards `(0.4,1,0.3)`. Ambient illumination remains, with 3 x 3 percentage-closer filtering and a normal-dependent depth bias. Unlit display bypasses shadows. Point-only meshes, volumes and image/slice displays do not allocate a shadow map. Ray-marched volume self-shadowing, transparent shadows, cascades and lights beyond this one directional source are outside this implementation.

Every eligible viewport owns at most one depth texture, one depth-only framebuffer and one small depth program. Allocation is lazy. A depth24 texel is conservatively accounted as four bytes: 1, 4 or 16 MiB. The effective map resolution is reduced until it uses at most half the configured per-view GPU budget. The streamed vertex arena reserves the remaining bytes, so arena capacity plus shadow allocation stays within that budget. Disabling shadows or changing quality may resize/reupload the arena from retained meshes; this never resamples the canonical field or starts a new source epoch. Fixed meshes defer shadow allocation if their existing geometry plus the admitted map would exceed the budget. Driver-internal allocations/retirement and physical GPU residency are not measured by this accounting.

The light projection fits all complete, non-retiring triangle geometry in the displayed resident set, including casters outside the camera frustum. Packed half-cell voxels and 1/128-block scalar surfaces retain their own position scale; partial uploads do not become casters. Shadow draws traverse compaction segments without changing camera culling, draw/picking versions or detail metadata. Removed meshes stop casting according to the same arena retirement rules as their color geometry. Missing/unloaded geometry casts no shadow. Bounds are camera relative, so large signed world travel does not cast absolute positions to float.

A bounding sphere around the complete geometry fits the orthographic light frustum. Light-space X/Y centers snap to map texels with an explicit fit margin. The map is regenerated each eligible draw; only depth storage/programs are reused. Coverage/resolution changes, LOD approximations, PCF and bias can change visual detail. This is a single local resident-set map rather than unlimited world-space shadow coverage or a promise of shimmer-free cascaded shadows.

The implementation uses GLSL 130, depth textures and depth-only framebuffer objects available in the supported OpenGL 3.0 path. Both color paths share the same shadow sampling function; indirect color drawing retains a per-draw depth fallback. The depth pass scopes split read/draw FBO bindings, viewport, current program/VAO/generic offset, depth mask/function/range/clear state, cull/scissor/offset/discard enables. Texture allocation preserves active binding and pixel-unpack buffer ownership. Color sampling scopes texture unit 3. No depth readback, completion wait or glFinish is added to ordinary rendering. See the [Khronos framebuffer-object specification](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_framebuffer_object.txt).

A shadow allocation/shader/draw exception suspends only shadows and retains the lit color path. The error is exposed in User Settings and routed once to rendering diagnostics. Retry shadow rendering or a changed shadow setting clears the latch. Disabling a feature, switching to image/volume/points, releasing an inactive scene or closing the viewport retires its depth objects. The full graphics-device reset problem remains separate.

Profiler allocation gauges now include a distinct Shadow depth-map allocation series. Streaming GPU data totals and pressure measurements include depth-map bytes; vertex arena capacity/free-range metrics keep their original meaning. GPU_DRAW surrounds all offscreen commands, including the optional depth pass. Shadows do not alter configured fallback order, source/picking data or procedural results.

Validation covers independent projection/light-ray and resource-admission expectations, immutable matrices, texel snapping, historical/strict preference handling and project/history isolation. Native ordinary/strict-3.0 fixtures use an off-camera floating box to check analytical ambient/directional/fog pixels, complete-only uploads, mixed scales, indirect and every compaction step, negative coordinates beyond float integer precision, bounded combined allocation and actual GL state/name cleanup after an injected depth callback failure. Production Viewports exercise budget-reduced resolution, quality changes, explicit retry, disable/reupload, unchanged source identity and profile/preference exports. These are functional software-GL checks, not representative hardware performance or full Windows 11/DPI/GUI acceptance.
