# Private editor decisions and lifetime

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This follows [Curve layout](CURVE_LAYOUT.md), [expanded expression layout](EXPANDED_EXPRESSION_LAYOUT.md), [membership review](RESOURCE_REVIEW_LAYOUT.md) and [resource decisions](RESOURCE_DECISION_LAYOUT.md). The validated baseline remains 922 tests / 120 suites.

Expanded Expression, Membership and Curve now assign their persistent action controls a transient UUID scope for each opening. Resizing, changing user scales, switching pages or retrying a rejected decision retains that scope and native footer IDs. A new editor receives a distinct scope, so an Apply/Use Text click held from an obsolete editor cannot activate its successor on release. Only footer action identities change: existing expression field, member checkbox, curve-body and scrolling-child identities retain their established behavior. The scopes are not serialized and grant no model publication authority; every existing source/draft/selection/value check still runs at its actual boundary. This does not certify every held text-input/checkbox/keyboard/focus route.

Curve uses the shared measured settings chrome with one full-width Apply row and one full-width Cancel row outside the scrolling inspector. It retains the same two-row vertical budget, floating-window ownership and plot geometry policy. The shared chrome now accepts child flags, preserving Curve's NoScrollWithMouse body and its existing distinction between plot zoom and manual inspector scrolling. Native body/list window identities do not advance per editor opening. Logical control names and Curve focus/navigation routes remain. The shared chrome also exposes native action IDs to deferred probes without persisting them.

The Curve footer collects both actions before staging. Cancel wins before Apply; Escape prevents a simultaneous Apply. Curve Escape retains its existing local gesture policy: it rolls back an active point/tangent/pan gesture and keeps the editor available, rather than closing the entire private context. Escape in the expression and membership modals still cancels their temporary sessions. Accepted expression/curve staging is private to Properties and remains consumed before its refresh callback; a failed refresh still reports its distinct Application event once without reapplying. Explicit parent Apply remains the document transaction. Membership still commits members only and preserves a separately drafted ID.

Expression and Membership now close obsolete native modals when their sessions have already been cancelled externally. Membership exposes its terminal state and checks it before opening or drawing, including cancellation before the first draw, instead of keeping a disabled workspace alive. Their inactive DialogLayout path retains the existing queued-window-data behavior. Ordinary successful staging/Apply and native Cancel still close through their existing return/parent ownership path.

MembershipEditSession now captures the DocumentSession lifetime token in addition to the existing editor/project UUID, exact draft/selection and full resource values. Successful Open/New replaces that token, so opening the same saved project cannot adopt an earlier private selection even if the UUIDs, values and retained draft object match. Ordinary catalog edits, Save, Undo and Redo retain the token; unrelated catalog changes remain allowed when the opening membership and draft values still match. No project format, schema, engine/model API, generation, inheritance or persistence semantics change.

Three additional deferred MembershipEditSessionTest definitions cover cancellation/success terminal state and rejected repeated publication, identical-file reopening with a retained old draft, and an unrelated catalog edit plus Undo/Redo followed by a valid membership commit. PrivateEditorDecisionProbe defines eighteen production form/size cases: Expression, Membership and Curve, each retaining one opening across six wide/narrow/short/global/window-scale combinations including the 6.25 font product. It records exact native footer ID continuity through real reflow, followed by held predecessor replacement, simultaneous Escape/primary release, external cancellation and cancellation before first draw. Additional phases define private expression staging and private curve interior-point deletion, one failing consumed refresh for each, explicit parent Apply, a members-only commit retaining a private ID, and one exact Undo/Redo per committed change. Requests, source input and local curve deletion are explicit fixtures; native footer controls perform the decisions. Existing curve/field/member gesture and layout definitions remain queued. The context has no GLFW/OpenGL or physical OS input.

scripts/verify_private_editor_decisions.py defines independent work/window/body/footer containment, action order, per-request native ID continuity and complete saved-document comparisons across all three edits and their Undo/Redo states. PrivateEditorDecisionConsumer compiles against the headless engine JAR alone, strictly loads four saved states, samples x+1/x+2 and .25/.5 curves over signed coordinates, checks members-only counts/private ID isolation and EMPTY worlds at roots 2/4. Future Linux/Windows commands and artifacts are wired with workflow triggers unchanged. No compiler, JUnit, native probe, Python checker, schema/generator, engine consumer, build or GitHub workflow ran.

Complete text/checkbox/drag/keyboard/IME/focus/close/reentrant timing, every failure and stale-owner combination, representative latency, physical DPI/detached/GPU behavior and full GUI/Windows 11 acceptance remain pending. This does not advance A01–A36 or production sign-off.
