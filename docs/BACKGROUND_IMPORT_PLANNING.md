## Rebuild after a choice without blocking the review

The production Desktop import panel now uses the existing bounded editor executor and UI completion queue for subsequent COPY/REUSE/SKIP choices and explicit Reload. The earlier package loader still reads, validates and computes the initial plan on its worker. A choice captures desired resolutions and an independent model planning draft; the worker builds its conflict indexes, exclusion closure, candidate and validation results without accessing live EditorState or native controls.

ResourceImport.Session.withChoices(Map) creates that independent draft with the same private destination/incoming snapshots and COPY allocation. Its map replaces all choices, with omitted rows defaulting to COPY. Invalid choices reject before changing the original session. The immutable private inputs can be shared for reading; choice maps and cached plans are separate. A returned session may be planned on another thread while the original remains readable; a single Session is not made generally thread-safe. The original candidate/choice accessors retain their ownership contracts. This additive headless method does not change serialized fields, schemas, registry versions or the merge algorithm.

The review retains its last completed plan while work is pending and shows an explicit background message. Desired choices update immediately and may supersede older queued/completed work. Import and displayed-plan acknowledgement remain disabled until the latest result has been installed and then actually displayed in Resources. Worker completion alone never acknowledges a plan. Choice rebuilds preserve COPY identities; Reload takes an owned snapshot of the current destination and may allocate a new set, retaining desired choices and checking compatibility again.

## Completion, failure and cancellation ownership

Each worker has an opaque request identity and an editor-owned FutureTask. A new choice, reload, cancellation or closure retires the prior identity, cancels the FutureTask and removes queued work when the executor supports removal. A non-cooperative running planner may finish later; its callback has no authority to overwrite newer choices or another review.

Publication occurs only on UI delivery. It checks the captured document lifetime, project object/UUID/revision, committed JSON values, saved path/dirty baseline, selected UUID/sibling selection, Properties draft object/values and raw seed ledger. The current project/private-action blocker is checked again, followed by another ownership check to contain reentrant cancellation/replacement. The computed model must still match the destination. A changed committed destination requires explicit Reload; private/input/blocker changes retire the result and offer a fresh preview retry where the current document still permits it. No stale callback silently applies choices or commits resources.

Scheduler rejection, worker failure/cancellation and UI-handoff failure retain desired choices, keep the last completed plan visible and leave Import disabled. Bounded feedback offers Retry preview or Cancel. A successful retry still needs a newly displayed plan. Cancel and Escape remain usable during computation, and lifecycle teardown closes the import panel before editor resources are released. Filters, section navigation and inspection remain available; there is no automatic retry loop.

Explicit Import continues through the existing complete validated document transaction. It appends/reuses resources without changing existing definitions, preserves separate private Properties/raw input and publishes one Undo/Redo entry. Project saving remains explicit. The legacy synchronous session/panel constructors remain available for isolated direct workflows; Desktop selects background planning, and its prepared-open path does not rerun the initial plan.
