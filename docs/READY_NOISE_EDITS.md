## Current resolution and dialog controls before accepting a preview

NoiseEditSession previously adopted a computed structural plan or reported a captured planner failure from its queued UI callback. It now retains the plan/failure in a one-slot CPU mailbox. Delivery marks readiness only: phase RUNNING and request version remain stable, an initial preview stays private, and prior completed feedback remains visible while a resolution replacement is pending. Apply stays disabled until current acceptance. Delivery cannot change private Properties, commit a project or publish operational failure feedback.

NoiseEditDialog captures the exact dialog instance, shown work version and preview before drawing. Current resolution/replacement choices and Cancel/Escape, Retry and page controls decide first. Acceptance, private staging and focus delivery run only after the dialog's own body, ID and popup scopes unwind. A newly chosen inline request cannot be accepted as older shown work. An unavailable popup does not accept for absent controls. Each modal has a native identity for its opening, so cleanup for a closed predecessor cannot close a different opening with the same visible title.

An initially valid action still stages from its original request without another Apply click after current cancellation has had precedence. Invalid initial work remains a private resolution/Issues review. Choosing resolution ends automatic staging. Accepting a resolved plan installs its current preview but does not treat an earlier held Apply as confirmation: Apply Resolved Edit requires the exact version and plan shown by that decision. A later draw of that accepted plan can stage it explicitly. Cancel always wins the current decision, including ready valid or invalid results. Retry retains the existing automatic-versus-explicit policy; no frame retries unchanged work automatically.

Before adoption the session repeats complete opening project/draft JSON, document lifetime/project object/UUID/revision, private Noise object/UUID, selected resource/kind/ordered siblings and raw seed ownership. It repeats checks after presentation callbacks. A callback that chooses a ready successor cannot authorize or stale that successor through old acceptance, including a callback that throws afterward. A changed owner or unavailable opening requires Cancel and reopening; stale input is never silently incorporated into a new candidate. Final private Stage repeats the complete checks and the planner's unchanged-base guard.

Staging consumes the session before focus/index callbacks. It copies only the canonical structural changes into the same private Noise; committed values, document history and separate private/raw input retain their existing ownership. A focus callback failure is bounded feedback after consumption and cannot repeat the edit. Only explicit parent Properties Apply commits the full resource in one undoable transaction. Invalid raw seed input still blocks that parent Apply. Saving remains separate and explicit.

Ready success, invalid diagnostics, captured compiler failure and null planner result can all be cancelled before adoption or primary operational reporting. Accepted failures keep desired resolution/replacement and previous feedback for explicit Retry preview. FutureTask observation continues through readiness, so inline delivery followed by handoff/executor fault cannot silently install an unaccepted preview. Once accepted, the result detaches its completed task before retirement to avoid interrupting a worker finishing delivery. Consumed results are not undone by a later external fault. Infrastructure faults retain the existing refresh/failure policy.

Choice supersession, retry, staleness, Cancel and stage retire the CPU mailbox independently of draining callbacks. Late workers cannot refill retired slots. Queued callbacks hold identifiers rather than computed plan/failure payloads. Closing/staging closes the mailbox. Synchronous direct constructors retain immediate planning; direct asynchronous owners explicitly accept delivered plans. Non-cooperative compiler interruption still has its existing limits.

The canonical NoiseAuthoring planner, public engine/model APIs, schema/registry/project formats, dependency/type/UUID/pin rules and arithmetic are unchanged.
