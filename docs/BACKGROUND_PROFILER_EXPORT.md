## Frozen review, worker staging and current controls

Production Desktop Profiler JSON/CSV exports now prepare files on the bounded editor executor. Prepare Export still owns the exact immutable displayed Profiler.Snapshot. Live samples, replacement captures, Stop, Clear, measurement filters and document replacement do not retarget it. Public direct ProfilePanel constructors and synchronous ProfileExportSession/ProfileIO writes retain their existing behavior; production explicitly enables the background path and closes its owner during Desktop teardown.

An export reserves one review, raw destination string and format. The reservation blocks another write without consuming the review. A worker uses canonical ProfileIO JSON/CSV encoding, forced content and atomic private staging. ProfileIO writes into a reserved private sibling through its existing temporary/atomic protocol; final publication then moves that prepared sibling to the reviewed destination. This reuses the canonical serializer with one additional private rename rather than duplicating its format or changing the public engine API. Preparation creates no incomplete visible capture at the destination.

The closeable mailbox owns either staged output or a captured worker failure. UI delivery carries only request/epoch identities and marks readiness. Pending request version, Cancel Export identity, review reservation and prior destination bytes remain stable. Final acceptance requires successful executor admission, complete worker return, delivery and the request version shown by current Profiler controls. A handoff that delivers and then throws cannot authorize replacement. Already known future failure is handled at this same acceptance boundary even without successful delivery.

After the native window scope closes, current Cancel Export, Escape, Discard Review, Prepare Export, path edits, section changes and lifecycle suspension have priority over predecessor publication. Cancel/Escape and hiding/collapsing the Profiler retire pending staging and release the reservation while preserving its review. Leaving Export also retires it. Discard explicitly consumes the review; Prepare explicitly replaces it. The production footer reserves its persistent Cancel Export slot alongside the existing actions; its native identity stays stable through readiness. The original export finishes from a later owning frame without another confirmation. Starting/stopping/clearing live collection remains independent unless the user leaves the export workspace or replaces its review.

Acceptance rechecks the exact review reservation, raw path and current visible-owner gate. It then checks the **latest active project path**, including normalized aliases, hard links, symbolic/real parents and dangling aliases through the shared ExportPaths guard, immediately before final atomic replacement. A project opened/saved at that destination during staging prevents export rather than replacing the active project. A historical capture may still be exported after New/Open when its chosen destination remains safe. This is a publication-time guard, not filesystem locking against another process racing path/link changes.

Final replacement consumes the prepared file and review before status, cleanup or later actions. No validation, copying or callback lies between a successful rename and review consumption. Unsupported/failed atomic replacement retains old destination content and the frozen review for an explicit corrected path/format retry. Captured worker failures wait for current acceptance; cancellation can suppress their primary error. Queue/capture/admission failures can report from the explicit initiating action before a pending form exists. Guard errors retain bounded explicit recovery. Nothing retries unchanged frames.

Cancellation, stale gates, failure and closure invalidate mailbox ownership independently of queued callbacks. A late noncooperative worker cleans rejected staging rather than enqueuing a payload. Cleanup ownership is consumed before deletion, so an unlink failure is terminal for that pathname and produces a separate PROFILE_EXPORT_CLEANUP_FAILED event. Cleanup can fail and leave an unpublished sibling; interruption/queue removal is best effort. Accepted cleanup never unlinks a reused temporary name. Closing during an injected replacement callback waits for that publication boundary before disposal.

Original request fences surround gate and active-path callbacks. A callback-created ready successor cannot be consumed or failed by predecessor acceptance. Retirement clears the reservation before cleanup feedback; reporter-created work remains owned, while final close rejects new work. Frozen capture retention stays bounded by the existing Profiler capture limits and one pending attempt; no measured heap, provider, durability or latency guarantee is claimed. Owner path checks/rename/unlink, capture snapshot refresh, rendering and native consequences still cost UI time.

Capture files never apply private Properties, alter provisional seed corrections, change project/history/dirty state, modify preferences or change generated fields/voxels. Collection/aggregation, JSON/CSV version-1 shapes, public ProfileIO signatures, registry/schema formats and headless module independence are unchanged. Existing direct synchronous export review and layout/decision probes remain applicable.
