## Final review decision

Desktop's explicit Import action now prepares the reviewed candidate's complete document validation, frozen values and Undo delta on the existing bounded editor executor. Package reading/initial planning and later COPY/REUSE/SKIP/Reload planning already use workers. The final worker uses the exact accepted model plan and its COPY allocation; it does not rebuild choices or acknowledge an undisplayed plan. The existing synchronous session/panel constructors retain their direct behavior.

Committed resources and previews remain active while final preparation is pending. Import, choice changes, Reload and preview retry are disabled during that attempt. Resources, Filters and Issues remain inspectable. Cancel or Escape closes the review and retires preparation; lifecycle closure does the same. Cancel precedes any primary action. Another request cannot replace a pending review, and a late result cannot close or publish into its successor.

Scheduling rejection, worker Error/exception, external future cancellation and rejected UI delivery end pending state. Bounded feedback retains the reviewed plan/choices and offers explicit Import retry; unchanged frames do not resubmit work. Candidate validation rejection retains the review, full diagnostics in Validation and up to 256 attempt-owned issues with the original count. Correct the relevant state or policy and choose Import again; saving remains separate. A changed committed destination requires Reload and a freshly displayed plan. Other stale authority clears displayed-plan acknowledgement and requires review again before Import.

## Ownership and publication

The owner thread captures a `DocumentSession.EditRequest`, exact `ProjectFileOwner`, displayed-plan identity and diagnostics identity/value/scope. It also captures the selected kind. The worker only applies the already-owned import plan to the request's private candidate, runs its captured validation policy and builds the prepared document edit. It does not access EditorState, Properties or native widgets.

UI delivery checks document lifetime, project object/UUID/revision and values, checkpoint/path/dirty state, selected UUID/ordered siblings/kind, exact private Properties draft/value/raw seed version, displayed plan and current diagnostics. It checks the project/private-action blocker, repeats authority checks after that callback and checks the prepared transaction's source/checkpoint/history/policy. Reentrant cancellation, New/same-UUID Open, direct value changes, newer diagnostics and superseding document work cannot grant an old result permission to publish.

Successful publication consumes the prepared transaction and closes the review before notification. It increments the editor revision and clears accepted validation feedback while preserving the existing private draft object, private fields, raw input, selection and preferences. Import appends/reuses committed definitions only. One nonempty import contributes one Undo/Redo transaction; an exact no-op does not invent a history entry. Notification failure reports a separate consumed-completion failure and cannot repeat the import. There is no implicit save.

Pending work has its own opaque identity and FutureTask, separate from preview planning. Cancellation retires authority, cancels the future and removes queued work when supported by the executor. Non-cooperative running preparation may finish later; its completion is ignored. A normal worker return alone grants no publication authority.

Only candidate application, full compiler validation, freezing and delta construction move to the worker. Owner-thread snapshot capture, exact comparisons, review-row projection, diagnostics, final assignment/notification and file/save publication still have costs. No large-package latency/memory guarantee or interruption of every preparation phase is claimed. Model/engine import rules, compatibility, resource UUIDs, inheritance, headless APIs, schema/registry data and project/archive versions are unchanged.
