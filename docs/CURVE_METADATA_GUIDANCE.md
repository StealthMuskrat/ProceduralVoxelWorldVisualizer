# Configured curve editor guidance and context Help

Status: **uncompiled and untested** under the owner's development-phase testing pause. This is scoped source coverage for 2.3, 4.1.3, 8.2–8.5 and 18.6, extending [curve numeric controls](CURVE_NUMERIC_CONTROLS.md), [numeric metadata guidance](NUMERIC_METADATA_GUIDANCE.md) and [World metadata guidance](WORLD_METADATA_GUIDANCE.md). It is not full GUI, schema, native, Windows 11 or release acceptance.

Previously the curve dialog's numeric slider used a generic value/range hint, the paired input had no matching configured guide, and mode hints came directly from CurveModes. Fixed local controls/actions and endpoint/readout text also lacked configured dialog-specific Help. Curve creation controls already existed in App Config, but changing those defaults applies only to future curves and is a different operation from describing an existing dialog.

CurveControlMetadata contributes 23 presentation-only `curve.editor.<key>` subjects. Ten numeric subjects cover domain/display bounds, snap increments, point X/Y and incoming/outgoing slopes. Three mode subjects cover outside-domain policy, next-segment interpolation and handle mode; three local toggles cover grid and independent snapping. Six actions cover local Undo/Redo, Fit, interior deletion, Apply and Cancel. A plot-readout subject describes exact coordinates and existing gestures. Endpoint X shares the point-X guide and explains its locked domain owner. Fixed dialog labels, ordering, native edit identities, focus routes and CurveModes lists remain authoritative.

Both native parts of every numeric pair use the same active configured tooltip, exact double/range details and canonical Help topic through the existing UiFields guidance hook. Native IDs distinguish popup ownership, including point UUID and dialog scope. Mode selectors preserve the selected mode's canonical CurveModes help after configured guidance; metadata cannot replace those stored IDs or evaluation rules. Non-numeric controls, endpoint/readout text and action buttons attach configured tooltip and read-only context Help. The plot retains its existing right-click action menu; Help is available on its coordinate readout. The standalone public CurveDialog constructor has no EditorState Help host, so it uses built-in tooltips without advertising an unavailable context Help action.

Application Settings labels these subjects as Help names and explains their separation from curve creation defaults. Active metadata changes reach the dialog and immutable Help snapshots through the existing metadata Apply publication. `curve.min`, `curve.max`, endpoint creation values and other existing creation controls retain their original authority. New `curve.editor.*` subjects have empty option whitelists and are excluded from creationDefaults. The explicit app-config schema adds the 23 keys and adjusts its control limit; legacy/partial profiles merge the built-in guides. Format 1 remains unchanged; older binaries may reject newly published unknown subjects. The existing default fixture remains a legacy-compatible partial profile; no default/schema generator has run. Project/model/engine/API/archive formats and dependencies are unchanged.

Guidance does not edit points, toggle snapping/grid, run Undo/Redo/Fit/Delete, apply a curve or save anything. Curve Apply still validates into its original private Properties draft, Properties Apply commits one project transaction, and explicit Save persists that project. Domain endpoint locks, strict neighbor order, unclamped Y, auto/aligned/free slopes, exact text precision, local gesture history, focus, cancellation and stale-parent rejection retain their existing paths. Help popups use existing bounded layout and unformatted tooltip rendering; configured percent/hash/Unicode text does not become a format string or an edit ID.

Ten deferred CurveControlMetadataTest definitions cover the complete subject set, separation from existing creation controls, unknown scopes, literal configured/selected-mode hints, exact numeric values and per-part IDs, legacy/partial merging, private metadata Apply with unchanged curve/preferences, independent mathematical default-curve expectations, forbidden options/creation authority, detached controls/Help snapshots and explicit schema parity. The partial app-config-curve-guidance.json fixture and expanded future schema checker define accepted subjects and rejected unknown/options/creation keys. Schema and fixture changes are source edits only.

The existing deferred CurveNumericProbe gains thirteen production tooltip/context Help routes before its original editing sequence: both parts of domain minimum, display minimum, interior X and Y; outside-domain and interpolation selectors; and Fit/Apply/Cancel action buttons. Configured literal text, exact canonical request delivery, complete copied numeric Help, unchanged private curve/Properties/project/preferences/metadata/history and no new local Undo are defined. Report version 2 and the existing future receipt checker require these routes; existing slider precision, held Escape/collapse, exact text, unclamped output, private staging and one project Undo/Redo definitions remain. Its existing independent engine-only consumer and manual workflow commands remain unchanged. Slopes, toggles, endpoint/readout, standalone and every physical/native interaction still need later runtime coverage.

Only source inspection, Java formatting and git diff --check were performed. No compiler, Gradle, JUnit, native probe, independent consumer, receipt checker, schema validator/generator or GitHub workflow ran. The observed baseline remains 922 tests / 120 suites. Main remains the sole branch; broader metadata/integration/native/platform/hardware and final acceptance/release work remains pending.
