# Input Settings layout and recording controls

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This extends [shortcut recording ownership](SHORTCUT_RECORDING_OWNERSHIP.md), [settings body/footer budgets](APPLICATION_SETTINGS_LAYOUT.md) and [the User Settings category header](APPEARANCE_SETTINGS_LAYOUT.md). It does not certify complete 4.2/4.3/A32, physical monitor/DPI behavior, Windows 11 or GPU font quality.

Input Settings now has a scrolling body and one persistent measured footer: Apply Bindings, Revert Bindings, Reset Binding Defaults, Show First Problem and Cancel Recording. Disabled actions remain present with bounded equal-width hits. Long labels have full tooltips when clipped. Recording cancellation stays available when the command row or explanation has scrolled away. The desktop supplies its existing ordinary Save Preferences handler to a button inside the body and no longer appends a second Input save button below the footer. That button cancels capture before saving active preferences, without applying private bindings.

`ShortcutRowLayout` selects an inline chord/three-action row when all measured widths fit. Otherwise the chord fills its own row and Record/Unbind/Default occupy three, two or one action columns. Buttons use regular measured frame height, and labels/defaults/problems are bounded single-line previews with full hover text. The row clipper receives the resulting uniform stride for the current width/font. Each text/frame advance rounds up to a whole pixel; a zero-size tail item reserves the remainder after native layout. This keeps fractional font metrics from accumulating drift in skipped rows. The native definition separately measures content advance and reserved stride so a too-small budget can be detected. Each action keeps its own stable ID scope across reflow.

The list viewport caps at 65% of the visible scrolling body, even when headings consume its remaining space. A large individual row can scroll vertically inside that viewport; row actions do not require horizontal scrolling. Heading/feedback/save content may require body scrolling. This does not promise that every row or field is simultaneously visible, or that clients too short for the category plus one native action row are usable.

Show First Problem first resolves a displayed/owned binding mismatch, then a validation problem, both in command registry order. This includes an oversized native string rejected by the owned ledger. It filters to the action and requests body/list scrolling and field focus without changing the text or accepting a previous parsed binding. Selecting a correction destination cancels recording. The existing full displayed-map check, stale active-map guard, conflicts, scoped row resets and explicit publication remain in their existing owners.

Footer cancellation runs before key polling. Accepted capture still updates only the owned private field; completion or cancellation retains the existing frame suppression, so a captured or same-frame cancelled command cannot dispatch globally. The existing session/version/active-map/focus/popup/text-input/held-key guards remain in `ShortcutRecording`. Layout changes alone do not replace that owner. Apply remains disabled for the entire consumed capture frame. Feedback from a newly captured key is shown on the following draw.

No new project transaction, raw-buffer reset or file write occurs on reflow. Ordinary saves retain active bindings; failed Apply keeps private input for retry, and accepted Apply merges unrelated preferences through the existing required atomic writer. Project/history/private Properties/raw seed state, shortcut registry and defaults, preference formats/schemas and the headless API are unchanged. Other settings pages and keyboard semantics outside this panel remain separate.

Ten deferred `ShortcutRowLayoutTest` definitions cover independent inline/column thresholds, measured heights, fractional pixel strides, viewport bounds, finite extremes and invalid metrics. Three deferred `ShortcutProblemNavigationTest` definitions cover raw preservation, oversized displayed mismatch priority and deterministic problem order without repair. None has run.

The deferred `InputLayoutProbe` uses the production panel, category header and font atlas with explicit synthetic font magnification. It defines an unfiltered clipping receipt and six wide/narrow/short/scaled layouts, including a 6.25 font product. It requires all footer/category/body rectangles to fit, stable Find field identity/raw text, all action-column modes, horizontal row fit, native content/stride measurements, unchanged cached feedback, ordinary-save exclusion and hidden-problem reveal. Further phases define capture ownership through reflow, Cancel Recording paired with a same-frame Save key, real successful chord capture without command dispatch, occupied-destination failure/narrow retry and unchanged project/history/private Properties. It does not create GLFW windows, a renderer or physical DPI transitions.

`scripts/verify_input_layout.py` independently checks geometry/order, clipped stride receipts, row modes, exact private maps/identity, ordinary-save exclusion and final saved binding/unrelated preferences. Future Linux/Windows commands/artifacts are wired with development trigger exclusions unchanged. The older deferred `ShortcutRecordingProbe` remains a separate definition.

All thirteen new regression definitions, six layout cases, additional native recording phases, replay, compilation and GitHub execution remain deferred. The validated baseline stays at 922 tests / 120 suites. Real DPI/font rendering, every scroll/focus/keyboard/IME/paste path, other settings internals and full program acceptance remain pending.
