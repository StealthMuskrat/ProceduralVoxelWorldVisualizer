## Preparation, publication and abort

Writer finish previously appended an index/footer without rolling it back after a preparation failure. Retrying or appending after that failure could leave old index bytes before a later index and publish an unreadable archive. A failed destination move also left a closed writer without a supported finish retry, and an IOException during close could skip temporary-file deletion. Output-open failure occurred outside constructor cleanup after the temporary file had already been created.

The writer now distinguishes open, prepared, finished, failed and closed states. Payload write and index/footer/sync IO failures truncate and seek back to the last owned file boundary. Only a successful rollback restores open admission; rollback failure leaves the writer unable to append or publish. File/index mutations conservatively become non-publishable before changing bytes, so unchecked failure cannot leave an uncertain writer eligible for finish. Serialization/argument rejection before file mutation retains the prior reusable behavior.

A completed, synced and successfully closed candidate becomes prepared. Publication failure retains those exact bytes for finish retry, without rebuilding or duplicating its index. Appending to a prepared writer is rejected. Successful finish remains idempotent, including after close. Explicit close aborts unpublished work, attempts both handle close and temporary-file deletion, preserves the primary IOException with suppressed cleanup errors, and allows cleanup retry. Constructor cleanup now also covers failure to open the already-created temporary file and preserves initialization errors when cleanup reports an IOException.

The package-private ArchiveOutput boundary delegates production operations directly to RandomAccessFile, including existing big-endian primitive/modified-UTF encoding, sync and rollback. It permits deterministic actual-file fault injection without public test hooks or mutable global injection. Public factory/method signatures, archive versions 1/2, payload compression, sorted index, semantic dictionary, exact EMPTY coverage and Reader behavior are unchanged. The later unvalidated [atomic publication follow-up](ARCHIVE_ATOMIC_PUBLICATION.md) supersedes this batch's earlier atomic-move preference/non-atomic fallback policy: publication now requires atomic replacement, retaining the same prepared retry/abort lifecycle. No stronger crash/power-loss or provider guarantees are established. Writers remain single-caller objects.
