# Appearance and UI scale layout

Status: **uncompiled and untested**, implemented on `codex/development-phase` under the owner testing pause. This extends [private UI scale editing](UI_SCALING.md), [measured settings budgets](APPLICATION_SETTINGS_LAYOUT.md) and [font scope inheritance](UI_DPI_AND_FONT_DENSITY.md). It does not certify complete 4.3/A32, physical monitor/DPI transitions, GPU font quality or Windows 11 acceptance.

The User Settings category chooser now uses available width with a hidden stable widget label. Its preview identifies the current category and a tooltip identifies its purpose. Appearance uses one production `AppearanceSettingsPanel` composition: Theme, private scale editing, Open Themes and ordinary Save Preferences live inside the scrolling scale body. Apply UI Scales, Revert UI Scales and Show Invalid Scale remain in one measured equal-width row outside that body. The desktop no longer appends a second Appearance Save Preferences button below the footer. Other User Settings categories retain their existing ordinary-save behavior through the same save handler.

The searchable target list uses two to six measured text rows rather than a fixed 150 units. A minimum list height may extend the body content below its visible rectangle; the body scrolls to it. Global and selected-window slider/exact-text pairs use the existing measured settings pair policy, stacking at full width when two readable fields cannot fit. Filter/checkbox labels and explanatory text wrap, and clipped target/action labels retain full tooltips. Raw widget IDs remain unchanged across inline/stacked reflow within their stable body scope. Existing scale text/flags and cached complete validation stay with `UiScaleEditSession`; resizing never parses, normalizes, saves or discards them.

Show Invalid Scale first resolves a displayed/owned text or entry-presence mismatch in global/catalog order, then a validation problem in global/catalog order. This covers oversized native text that could not enter the owned ledger as well as an enabled invalid multiplier hidden by filtering. The button selects/filters a window destination and requests one native focus/scroll to its raw field; a global destination scrolls to the global input. It does not replace text, clear another field, enable an override or publish a preference. A mismatched dormant field can be revealed but requires an explicit multiplier toggle before editing. A stale active base without a raw problem continues to require Revert. The button is disabled when there is no correction destination.

Theme selection still changes active theme preferences and invokes the existing style callback immediately. Open Themes keeps its existing navigation callback. Ordinary Save Preferences still saves active preferences and excludes pending scale text; Apply UI Scales retains its exact displayed-map/current-base checks and required atomic write before publication. Failure leaves private input and active scales available for retry. Latest unrelated/extension preferences still merge on accepted Apply. Project/history/private Properties/raw seed ownership, scale ranges/catalog/registry version, persisted formats, schemas and headless API are unchanged.

`UiScaleProblemNavigation` is pure destination selection without parsing or native state. Five deferred definitions cover unchanged formatted text, global display mismatch priority, mismatched dormant text, deterministic entry-presence differences and feedback ordering without mutating either snapshot. Three additional `SettingsPageLayoutTest` definitions cover measured target-list budgets, finite extremes and invalid metrics. None has run.

The deferred `UiScaleLayoutProbe` uses the production Appearance composition, category header, scale editor and dense font atlas without GLFW or a renderer. Six wide, narrow, short and magnified cases include a 6.25 font product. Magnification is explicitly a synthetic fixture input independent of active/private scale values, so reflow does not manufacture a stale preference base. The workflow defines actual keyboard/mouse edits, all three footer/category/body rectangles, inline/stacked native-frame plans, stable input IDs, exact hidden Help/Logs/global strings, cached feedback, ordinary-save exclusion, a retained theme-navigation callback, Show Invalid Scale, failed-write reflow/retry and unchanged project/history/private Properties. The theme callback is a host fixture action, not an actual Theme window layout scenario. Individual offscreen fields need scrolling and are not all asserted simultaneously visible.

`scripts/verify_ui_scale_layout.py` independently checks geometry/order, target-row limits, raw maps/flags/IDs, pair plans, exact ordinary and accepted saved values and unrelated preference preservation. Future Linux/Windows commands/artifacts are wired without changing development trigger exclusions or starting a run. The existing `UiScaleProbe` remains a separate deferred ownership/composition definition.

All eight new regression definitions, six native cases, replay, compilation and GitHub execution remain deferred. The last validated baseline stays at 922 tests / 120 suites. Settings other than Appearance, deep tooltip/style/title scaling, actual physical mixed-DPI behavior, all scroll/keyboard/IME paths and full program acceptance remain pending. A client too short to contain the category and one native action row cannot guarantee physical reachability.

The separate unvalidated [Input Settings follow-up](INPUT_SETTINGS_LAYOUT.md) covers shortcut row/footer reflow and recording cancellation. It does not add physical DPI or full GUI evidence.
