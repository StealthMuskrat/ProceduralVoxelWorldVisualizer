## One shared worker path for source, Find and reference links

Desktop now selects background GuardedNavigation and ResourceFindPanel construction, and its background PropertyPanel uses the same path for reference navigation. When leaving a modified resource requires Apply / Discard / Cancel, Apply captures the exact private Properties input and a DocumentSession prepared edit. The bounded editor executor copies the captured committed project, replaces the captured resource, validates the complete candidate using the captured policy, freezes accepted values and constructs its structural Undo delta. Worker code never reads live EditorState or native controls. Current committed values, selection and the original private draft remain active until queued owner-thread publication.

SearchNavigation retains its Result enum and legacy synchronous public constructor. NEEDS_DECISION continues to mean that the intent is retained; the background path additionally exposes internal preparing/progress/work-version state. Public direct GuardedNavigation, ResourceFindPanel and PropertyPanel constructors remain synchronous. The headless model/API, project format 2, schemas, registries and generated numerical semantics do not change. The existing prepared-edit API supplies the worker protocol.

## Check the current source before publication

An asynchronous intent captures the opening project lifetime/object/revision/values, selected UUID and sibling selection, exact private draft object/values, raw seed ledger and saved path/dirty baseline. Apply captures prepared-document authority as well: exact source values/object, document lifetime, validation-policy identity, saved checkpoint/receipt and Undo/Redo heads/bytes. Even an identical successful Save supersedes already prepared work. Unsupported in-place committed changes are checked before publication. Private changes retire the old intent while retaining the newer values. Another request cannot replace a pending target or its freshness supplier.

Both accepted and rejected preparations pass currentEdit before publication. Captured shared diagnostic identity, values and scope prevent an older navigation Apply from overwriting a newer validation result. Current Find-hit/private-editor eligibility or source-link freshness is repeated at completion, followed by exact ownership checks after that callback. Admission and running-state fences prevent recursive or duplicate decisions from scheduling another task. Cancel does not consult destination freshness and remains available even after an unrelated failure.

A successful Apply commits exactly once and refreshes its source Properties draft through the existing EditorState completion path. It consumes the old intent before running the post-Apply freshness callback. The completed project/private context is captured again around that callback. A changed trace fingerprint, unavailable destination, new private edit, new document or reentrant successor prevents navigation over that state while retaining the completed edit. A successor keeps its own draft, target and decision; the older result cannot reveal, close or annotate it. Postpublication refresh/freshness/reveal failures report a completed edit rather than replaying or rolling it back. A real change remains one Undo/Redo step; existing prepared no-op history semantics are retained.

Source links retain their trace/profiler freshness rules. Find and references continue resolving their current UUID targets. Successful terminal completion performs the owning caller's reveal exactly once; Find also retires its old committed hit. Navigation never saves the project or preferences.

## Responsive decision controls and explicit recovery

The shared dialog retains three logical actions. While preparing, Apply displays Preparing Apply..., Apply and Discard are disabled, and Cancel/Escape remains active. Work transitions change footer gesture ownership so a held predecessor release cannot activate a new retry phase. IDs remain stable during unchanged work. Actions still deliver after popup unwind, with existing per-frame/successor ownership intact. Legacy browser selection/edit dialogs retain synchronous behavior through the original overloads.

Cancel, clear, close and lifecycle disposal retire the opaque work identity, cancel the task and remove queued work where the executor supports it. A late/non-cooperative worker cannot publish, navigate or affect a reopened successor. Desktop owns the lifetime of both source and Find navigators; PropertyPanel closes its reference navigator. Closing the Find search window retains the already visible independent navigation decision, as before; Cancel/Escape in that modal or lifecycle closure retires its work.

Invalid provisional seed input cannot schedule an Apply and stays private. Compiler rejection retains the decision and immutable shared diagnostics. Scheduling, worker and UI-handoff failures end Preparing while retaining the intent/draft and bounded NAVIGATION_APPLY_FAILED feedback. Apply explicitly retries; no automatic retry is scheduled. Changed draft text after a rejected attempt requires Cancel and a new navigation request to own the corrected draft. A changed document or newer diagnostic result retires the older navigation and preserves the newer state. Central Find Help describes these same cancellation, retry and post-Apply boundaries.
