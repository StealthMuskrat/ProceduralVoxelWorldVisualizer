# Bounded visualizer control panes

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. The validated baseline remains 922 tests / 120 suites. This follows [visualizer options](VIEWPORT_OPTIONS.md), [preview Resume](PREVIEW_RESUME_DECISIONS.md) and [image gestures](IMAGE_GESTURES.md). It does not advance A01–A36 or production sign-off.

Each visualizer now places its source selector, commands, mode-specific fields, bookmarks, stage/Inspect controls, status explanations and pressure/recovery UI in one stable scrolling child. ViewportControlsPane measures complete unscrolled content, grows up to sixty percent of the available region and reserves the remaining preview space. Short bodies retain more image space. Content/font/window changes remeasure without changing the child identity or resetting its native scroll. The main parent remains the image interaction host. No additional editor/window, saved preference or generator state is introduced.

Viewports separates existing control/update work from image drawing with a paired try/finally child cleanup. Preview admission, pending result/upload processing, source invalidation, pressure and empty/missing-source returns retain their order and authorities. A failed control/update path cannot leave the child unbalanced. Source selectors and command popups keep their existing owner checks within the new child. Mode/field IDs remain stable through ordinary reflow; tab-specific child IDs isolate controls. Existing gesture admission, platform focus, camera and accepted-image sampling stay with their existing owners. Full integrated physical interactions after this parent/layout change remain unvalidated.

ViewportFields wraps numeric labels above measured slider/text pairs. When both fields fit, the exact numeric text field sits to the right of the slider; narrower or larger-font layouts stack them at the available width. The input identities remain unchanged, and sliders have separate stable identities. Boolean labels stay inline when the checkbox and caption fit, otherwise wrap above the checkbox while retaining the same explicit native key. All double-valued view inputs reject non-finite parsed results before invoking their setter, including the fixed-center coordinates; an active rejected edit shows a short correction message. Integer clamps and per-field finite/range constraints remain with the existing Viewports setters. This is immediate local view editing, not Properties Apply or a project transaction. It does not claim a complete provisional-text/source-lifetime authority for every numerical edit.

The development follow-up adds sliders to all ten existing Viewports numeric controls. Threshold and volume display endpoints suggest [-1,1]; opacity uses [0,10], ray steps [16,512], and preview extent [2,the current configured maximum]. Center Y and Y slices use the inclusive project Y bounds; horizontal centers and X/Z slices suggest [-1024,1024]. Suggested ranges do not clamp values entered in text or values retained during idle drawing. Existing view setters remain authoritative, including volume endpoint ordering, opacity/step/extent limits and finite coordinates. No new preference or serialized field is added.

Double sliders show five fractional digits with native NoRoundToFormat and NoInput flags. Exact adjacent/subnormal/large values remain in the existing seventeen-significant-digit text input; native slider temporary text entry is disabled so it cannot parse a rounded slider label. This follows the existing [numeric precision policy](NUMERIC_EDITOR_PRECISION.md), preserving double storage rather than claiming every numeric display now satisfies the specification's five-place presentation requirement. Integer sliders use an exact double intermediate and round only the accepted slider gesture to an integer. This accommodates full signed project Y bounds without the native signed-int slider's half-domain restriction. Changing a view field retains its existing regeneration/display-only policy; no idle formatting edit marks a preview dirty.

ViewportPanelLayout also measures histogram, image and sample-line budgets from the remaining height and inherited font. Histograms no longer consume a fixed 110 pixels, and their hidden native label avoids extending beyond the plot width. The sample footer has one clipped, non-scrolling line with a bounded inherited-font tooltip. It retains the last hovered text so the pointer can move to that line to read details; accepting another preview resets the retained text. Raw coordinates/samples and the accepted-image program are unchanged. Tiny exhausted areas degrade to positive logical regions rather than claiming impossible physical fit; the renderer retains its own internal framebuffer minimum.

PreviewResumePanel reveals a newly presented pause button in its current scrolling parent without taking keyboard focus. Repeated draws or ordinary context updates within the same pause do not repeatedly reset the user's scroll. The existing pause/source/limit review and consumed recovery callbacks remain authoritative. Users can scroll the control body independently of the sibling preview surface.
