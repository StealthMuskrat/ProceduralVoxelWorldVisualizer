# Bookmark dialog ownership and recovery

Status: implemented on `codex/development-phase`, uncompiled and untested. GitHub testing remains paused by owner instruction. Earlier bookmark evidence remains scoped to its recorded source.

`DocumentSession.sessionToken()` exposes an opaque in-memory document lifetime identity. Successful Open and New replace it, including Open of the same file with the same project/world UUIDs. Ordinary edits, no-op edits, Undo/Redo and Save retain it; failed parsing, validation or I/O do not advance it. Replacement prepares its serialized saved baseline before publishing the new document/token. The token is neither a procedural seed nor ProjectData and is not persisted in project files, packages or archives. Model/storage/core remain independent of desktop and native dependencies.

`BookmarkEditSession` owns one Add, Rename or Teleport operation for an exact editor/document token, logical project/world UUIDs and tab. Rename also retains the target bookmark's complete opening values and rejects changed/deleted targets. Unrelated edits, selection/private-draft changes, Save and history steps remain mergeable when the owning bookmark is unchanged; this deliberately retains the model BookmarkTransactions.Draft merge policy. A replacement document never receives an older dialog. Stale ownership disables Apply while preserving private name/coordinate text and Cancel.

The actual displayed name and complete axis map must match the owned strings before parsing or publication. 2D has exactly X/Z; 3D/World requires X/Y/Z; Rename has no editable coordinate map. Oversized native input rejected by the owned buffer cannot trigger an earlier parsed value. Coordinate inputs keep the existing signed ASCII 32-bit, all-axis validation and 128-character bound. New bookmark names retain up to 4,096 UTF-16 characters. Rename budgets at least the full opening name length so a longer legal loaded name can be preserved or shortened without truncation; it cannot grow beyond that opening budget. Native capacity reserves four bytes per character plus a terminator, with checked capacity arithmetic. Loader/name semantics and serialization formats are unchanged. Very large loaded names and physical byte-capacity/IME behavior remain unverified.

Bookmark transactions use attempt-owned feedback: up to 256 retained candidate diagnostics with their total count. The modal renders at most eight bounded entries in a fixed-height child and a short retry/Logs message for runtime failures. Repeated rejection lists remain current; a later validator exception does not reuse their details. Failed validation retains the same Add UUID, name/coordinates and separate Properties draft for retry. Accepted Apply, including an equal-value Rename, and Cancel consume the dialog. External Cancel closes its popup on the next draw; viewport shutdown releases its private session.

Teleport validates before its callback, rejects reentrant Apply/edit calls, closes only after success and retains raw input after callback rejection. Callback errors record an actionable `BOOKMARK_NAVIGATION_FAILED` Application entry. Arbitrary callback side effects before an exception remain the callback's responsibility; no rollback is promised. Picker navigation also catches callback errors, keeps the previous selected bookmark and open choices, and selects/closes only after success. Bookmark selection/filter state resets on a document-token change, including same-UUID reopen. Toolbar update/delete and the model's coordinate-only bookmark semantics are otherwise unchanged.

## Deferred verification

Three `DocumentSessionTokenTest` definitions cover edit/history/no-op/save retention, same-UUID Open/New replacement, failed parse/validation/I/O preservation and absence from serialized ProjectData. Ten `BookmarkEditSessionTest` definitions cover private Add plus one Undo/Redo, every tab's exact/invalid coordinates, displayed field completeness/hard bounds, same-UUID replacement for all operation kinds, unrelated-edit merging, stale Rename/world ownership, bounded same-list/throw/retry feedback and stable UUID, navigation failure/reentrancy, Cancel/no-op consumption, and name mismatch/blank/bounds with longer loaded-name repair. One additional CoordinateTextTest definition covers exact displayed axes. These fourteen definitions have not run.

`BookmarkInputProbe` retains its original saved 2D fixture and two successful navigation calls. It additionally defines oversized displayed input rejection, null-message navigation recovery/logging, two shared 300-diagnostic rejections followed by a thrown validator and successful one-Undo retry, private Properties ID/raw-seed preservation, direct same-UUID reopen rejection, stale Rename retention, actual picker failure/retry and external popup cancellation. The direct reopen fixture bypasses normal Desktop file guards to exercise the lifetime boundary; it does not certify menu/file-transition gestures. `verify_bookmark_inputs.py` requires the added report fields while retaining its independent saved-coordinate/schema expectations. Existing future platform probe/checker steps and artifact paths already cover this extended definition. No workflow, build, test, probe or verifier was executed for this batch.

The opaque token is an additive DocumentSession API; generator interfaces, schemas/registries, coordinate semantics and deterministic numerical behavior are unchanged. Artifact hashes are not claimed unchanged. Full physical window/input/DPI interactions, huge bookmark/name datasets, arbitrary callback timing, all error-layout cases and Windows 11/full GUI/release acceptance remain pending.
