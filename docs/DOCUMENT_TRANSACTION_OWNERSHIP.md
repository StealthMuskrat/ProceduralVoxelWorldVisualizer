## Reject an outer candidate after its owner changes

DocumentSession.edit previously copied the opening model, called the edit callback/current validator, and then computed a delta against whichever model was active afterward. A callback or custom validator that performed New/Open, another edit, Save or history movement could therefore leave a stale outer candidate eligible to overwrite a newer document or clear its Redo history. Undo/Redo similarly peeked a history delta before validation but could pop a different stack head if validation performed a nested operation.

Edit and nonempty history movement now capture a private TransactionOwner: opening active object, document lifetime, saved path/checkpoint, validator identity, both history heads, byte accounting and complete opening JSON values. Edit builds its candidate from that captured snapshot and checks managed ownership after its callback, before invoking the captured validator. Edit/history check all managed ownership and raw source values again after validation, before publishing or moving history stacks. Changed ownership or values throws IllegalStateException. An edit delta is computed against its own captured opening values rather than a newer active document.

ProjectDelta.applySnapshot reconstructs history from a deep copy of those captured values, preserving the guard's comparison baseline. Persistent Undo/Redo entries remain structural deltas with the same 100-entry/32-MiB capacity policy; temporary comparison snapshots are not stored as project history. Public edit/undo/redo signatures, ordinary validation/diagnostic behavior, no-op active identity, empty-history short-circuiting, successful delta accounting and explicit-save dirty rules remain unchanged.

A stale outer operation does not roll back an already completed nested operation or try to repair unsupported direct mutations. The newer active object/lifetime, values, path/checkpoint, history stacks and accounting are retained. Explicitly retry against the current document if another operation is wanted. Even an Undo/Redo round trip to equal values replaces the active object and invalidates the old owner. A nested no-op that changes no managed state remains permitted. Callback/validator exceptions retain their normal propagation; this adds no automatic retry, skip, reset or recovery file.

This is an owner-thread optimistic publication check, not a lock or new thread-safety guarantee. DocumentSession remains owner-thread confined except its existing owned Open/Save worker preparations. Custom validators should operate on their candidate and support the documented worker preparation policy. Arbitrary external callback side effects are not made transactional or undone by this guard. Save/Open preparation/publication policies and filesystem operations remain unchanged. No schema, registry, saved project/archive, numeric generation or headless dependency changes are introduced. The extra source-value comparison scales with model size; no latency/memory benchmark ran.
