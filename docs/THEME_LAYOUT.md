# Themes workspace layout

Status: **uncompiled and untested**, implemented on `codex/development-phase` under the owner testing pause. This extends [private theme preview ownership](THEME_WORKSPACE_OWNERSHIP.md), [measured settings chrome](APPLICATION_SETTINGS_LAYOUT.md) and [nested font scopes](UI_DPI_AND_FONT_DENSITY.md). It does not certify complete scaling/contrast accessibility, physical monitor/DPI transitions, GPU font quality or Windows 11.

Themes now has a scrolling workspace body and five persistent measured actions: Save Theme, Revert Theme, Reset to Default, Resume Preview and Palette / Contrast. Save stays disabled for a paused/stale preview or rejected RGBA input; Resume stays present and disabled until the current preview can be resumed. The existing readable inspector colors are still pushed before Begin, cover the entire body/footer and are popped before preview resume/refresh. Authored low-contrast or transparent colors therefore do not replace the recovery controls' palette.

Wide workspaces show palette and contrast panes together. Narrow workspaces show one full-width pane, preserving the selected view until explicitly switched. Palette / Contrast switches the narrow pane and scrolls it into view; in wide mode it reveals both panes without replacing their selection state. Pane height caps at 70% of the visible body; a minimum budget within that cap keeps the pane usable after large headings. The palette list caps at 65% of its visible pane. These bounds keep nested viewports from growing with their own scrollable contents. Content and individual tall rows can still require vertical scrolling.

Each palette row has a compact color swatch/picker, a bounded label, four R/G/B/A sliders and Use starting color. Four, two or one channel columns use measured input/axis widths; extremely narrow cells can put axis labels above their inputs. Direct sliders clamp to [0,1] and avoid rounding stored values to their three-decimal display format. Their native temporary text entry remains available. The same hidden per-row/channel IDs survive pane/column reflow. Header/channel/reset rows reserve whole-pixel advances, with a tail item keeping the clipped stride consistent at fractional font sizes. Color picker popup fitting and gestures held during reflow remain separate native acceptance work.

`ThemeColorIssues` records rejected component candidates for a finite known palette/status row set. Nonfinite or out-of-range candidates reaching the ledger block Save until the affected channels receive explicit valid edits, or an explicit row/profile reset clears them. Merely redrawing an earlier valid value, changing a different channel, filtering or changing panes cannot clear an error. Other channels and the swatch are disabled while that row requires correction, avoiding additional edits behind the rejection. Complete invalid RGBA candidates do not replace the private palette. Headings identify the affected color/channels; Use starting color, starting-appearance selection, Revert, Reset and close retain explicit reset ownership. Native sliders may clamp ordinary typed range overshoots before the candidate reaches this ledger. It does not add an independent raw-string editor for native color widgets; invalid native text rendering, paste/IME and all correction gestures remain unverified.

Feedback and clipped palette projections still cache by their existing owners. Contrast rows wrap; the authored-color sample gets a measured bounded child rather than a fixed 130-unit height. Palette edits update the complete immutable feedback before Save; low contrast remains feedback and does not itself block persistence. ThemePreview still yields to external native style ownership, keeps private colors when paused, resumes explicitly, and restores only owned active colors on close. Save still requires the current active base and exact reviewed palette, writes atomically before publishing and merges unrelated preferences. Layout does not dirty a project, apply private Properties, change schemas/catalogs/formats or add engine/native dependencies to the headless API.

Twelve deferred `ThemeLayoutTest` definitions cover independent pane/channel thresholds, viewport caps, 4/2/1 grids, stacked axis labels, fractional strides, finite extremes and invalid metrics. Six deferred `ThemeColorIssuesTest` definitions cover valid values, sticky invalid/fallback handling, affected-axis correction, scoped resets/immutable snapshots, unflagged invalid data and bounded known-row/mask inputs. None has run.

The deferred `ThemeLayoutProbe` uses the real Themes window, color-channel mouse edit, filter, production scale helper and dense font atlas without GLFW or a renderer. Six wide/narrow/short and user-scale fixture cases include a 6.25 global/window product. It defines native pane/footer/channel rectangles, all three channel column counts, stable RGBA IDs, clipped content/stride measurements, palette/contrast switching, unchanged private colors/cached audit/readable guard, ordinary-save exclusion, external-style pause/Resume, occupied-destination failure/narrow retry, saved-style close and unchanged project/history/private Properties. Its invalid-channel ledger coverage is in pure definitions; the native workflow does not inject NaN into a rendered slider or certify every native popup/focus/drag path.

`scripts/verify_theme_layout.py` independently checks registry counts, geometry/order, row strides, channel identity, selective RGBA changes and ordinary/final saved colors and unrelated preferences. Future Linux/Windows commands/artifact paths are wired with development trigger exclusions preserved. No tests, probes, verifiers, generators, builds or GitHub workflows ran for this batch. The validated baseline stays at 922 tests / 120 suites. Other settings internals, full GUI/physical display acceptance and release validation remain pending.

The unvalidated [Theme/Input decision follow-up](INTERACTIVE_PREFERENCE_DECISIONS.md) scopes Theme footer actions to owned raw palette snapshots, private resets and preview pause/resume. Escape suppresses footer decisions; Revert/Reset precede Save and collapse/close releases presentation ownership. Field/child geometry and existing preview style restoration remain; new definitions are deferred.
