# Input binding navigation

Input controls retain a bounded, draft-local choice for each processing-item UUID. Following a diagnostic or source link selects the exact named input once. A later manual choice wins, and returning to another item restores its own choice. Replacing the Properties draft, even with the same resource and item UUIDs, starts fresh. Missing/renamed selections fall back in authored order; selection never edits bindings or creates history.

Go To Control expands the input row and focuses its actual editor. Structural diagnostic pointers identify the binding leaf: type, source kind, constant value/component, shared/earlier/resource reference, ambient value, projection or slice. Only exact decoded input names in recognized item collections can supply a leaf; array indices never select a historical item. Plain input links focus the current source's editor. Scalar/Boolean constants focus Value; vector/coordinate values focus their first component unless a structural pointer selects another component.

Focus is submitted once and acknowledged by ImGui before the navigation request completes. It does not repeatedly activate the field or steal the user's later selection. Ordinary transform bindings, explicit coordinate components and sampled processing-field selectors share this routing. Bindings hidden behind other specialized controls and the complete physical input/DPI matrix still require GUI acceptance.

Same-owner navigation retains the current rejected draft. Edits remain private until ordinary Apply validates and commits the whole resource once; navigation is outside document revision/Undo/dirty state. Existing cross-resource Apply/Discard/Cancel and project-scoped source freshness guards remain authoritative.

`NoiseInputSelectionTest` covers independent choices, later user changes, draft replacement, unavailable names, reorder, removal and bounded retention. Diagnostic tests cover exact escaped names, recognized leaves, coordinate components and unrelated-path rejection. The native InputBindingProbe uses the full production Properties panel with ImGui mouse/key/text events: it repairs a rejected constant by keyboard after following its diagnostic, changes selectors after navigation, revisits two independent items, acknowledges type/source/Boolean/shared/earlier/ambient/resource/projection/slice focus, edits a transform scalar and the second explicit coordinate component without clicking their inputs, then Apply/Undo/Redo. Independent Python recomputes 26.25 from the saved typed bindings and transformed coordinates. Native controlled input is separate from physical OS/hardware certification.
