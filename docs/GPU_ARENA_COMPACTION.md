# Bounded GPU arena compaction

A scene now recovers fragmented vertex space automatically when an upload has enough total free bytes but no sufficiently large contiguous range. Profiler > Compact GPU Arenas explicitly requests the same operation; an active upload publishes before an explicit request starts. Requests on already packed/empty arenas are no-ops. A genuinely full arena still rejects new allocations through the existing pressure policy.

Compaction preserves source-offset allocation order and packs live ranges toward zero. It uses the existing VBO: **no second vertex arena or additional GPU copy buffer is allocated**. At most 64 KiB of reusable CPU staging reads each source range before its destination write. This desktop OpenGL buffer readback/subdata path works with the existing OpenGL 3.0 fallback. Readback may synchronize/stall the driver; bounded byte counts are not a certified frame-time bound or a claim that compaction is faster on every device.

Every viewport frame has one destination-write budget: uploaded bytes plus relocated bytes cannot exceed the configured upload limit. A relocation also reads those same bytes into staging, so the logical write counter does not claim to count all bus traffic. A single copy is at most 65,536 bytes, rounded down to complete 16-byte points or 48-byte triangles. A caller with too little budget makes no progress; the editor's minimum configured budget is sufficient. An incomplete final triangle tail retains OpenGL's original ignored-tail semantics.

## Continuous drawing and ownership

A downward copy may overlap its own original range. The source chunk is first read into staging, so the write cannot corrupt its unread remainder. The renderer then acknowledges that range and draws the moved primitive prefix from the destination plus the unmoved suffix from the original address. Both indirect and per-draw fallback submission use these same ranges. Primitive order, material IDs, AO, normals and chunk origins are unchanged. Partially moved meshes can temporarily need two draw commands. No mesh becomes hidden simply because it is being relocated.

During a layout transaction, allocations and free-list releases freeze. Camera-driven removals stop drawing immediately and queue retirement until the new layout commits; some obsolete bytes may consequently still be copied. New uploads wait without being reported as a full-arena rejection. After every copy completes, the allocator installs the packed layout atomically on the render thread, retires removed chunks and exposes the coalesced free tail. Retiring a middle allocation can create a new hole after commit; a later admission retry can request another bounded pass. Resident versions remain the same, so geometry/LOD/neighbor publication does not need to be regenerated.

Changing epochs or resizing/closing the renderer discards the entire old allocation/relocation state. A partial in-place move is never rolled back into obsolete addresses. Explicit requests made during uploads are cleared on epoch replacement. GL read/write errors do not acknowledge a copy and follow the existing streaming failure path: the scene is disabled and an actionable rendering error is published, preserving the last valid framebuffer. Device-loss recovery and driver-level partial writes are not certified.

## Inspection and compatibility

Profiler exposes scene CPU resident/reserved bytes, actual VBO capacity, used/free bytes, largest free range, frame upload/relocation writes, queued/active maintenance, remaining bytes and completed compactions. Streaming status displays pending relocation work. The opt-in upload elapsed series includes maintenance and a separate byte gauge identifies relocation writes. The scene-GPU allocation gauge now reports VBO capacity; prior `gpuBytes` accessors retain their used-allocation meaning. Auxiliary origin/command/palette/framebuffer buffers are outside the vertex-arena capacity field.

`SceneGpuRenderer.Statistics` and editor `StreamingStatistics` gain components while retaining their old constructors; record-pattern/reflection callers must account for the new shapes. `ArenaAllocator.Layout` is immutable, owned by its allocator and valid until commit/reset. Allocator clients must not use old slice addresses after a committed move. The headless engine API, project/user JSON schemas and voxel/archive semantics are unchanged. The new policy registry documents the bounds and ownership rules.

Validation uses an independent byte-array oracle across random fragmented layouts and every intermediate copy, including overlap, mixed primitive sizes, retry/acknowledgement ownership, sub-primitive budgets, bounded workspace, zero-size meshes, foreign/stale layouts, epoch reset and invalid-release preservation. The native renderer probe creates a fragmented VBO where a 48-byte mesh cannot fit despite 64 free bytes. It compares framebuffer pixels after every bounded move in both draw paths, retires an allocation mid-move, retries admission, queues an explicit request behind an upload, and replaces an epoch during a partial relocation. These checks establish functional behavior, not representative hardware throughput or complete Tree 17 acceptance.
