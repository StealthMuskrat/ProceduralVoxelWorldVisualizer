# Shortcut recording ownership and draft recovery

Status: implemented on `codex/development-phase`, uncompiled and untested. GitHub testing remains paused by owner instruction. Existing keyboard evidence belongs to its recorded baseline.

Input Settings now records through one `ShortcutRecording` owner. Starting Record captures the exact private ShortcutEditSession, its version, the active binding values and the chosen command. Another Record request cannot replace or rearm it. Recording still waits for initiating held keys/modifiers to release before accepting one fresh named-key chord. Any private edit, reset/revert/version change, replacement owner or active binding value change cancels the opening instead of writing a later key into a different draft. A stale binding draft cannot start recording until it is reloaded. Unrelated preferences remain independent.

The production panel cancels recording when its root/child window is unfocused, ImGui reports application focus loss, a popup owns input, or a chord/filter text widget is active. Row Unbind/Default, Revert/Reset, explicit cancellation and hiding/collapsing/switching the host also cancel it. Focus restoration does not resume recording. Cancellation retains private binding text; only explicit reset/revert changes that text. Record buttons remain disabled while another recording is active.

The host calls InputSettingsPanel.beginFrame exactly once before UI processing, including frames in which Settings is hidden. Desktop.process now does this. A frame that starts, completes or cancels recording remains suppressed for application shortcut dispatch even if capture has already ended. Suppression expires at the next host frame when no recording is active. This prevents a captured Ctrl+S, for example, from also running the active Save command, while avoiding sticky suppression after a hidden panel cancels capture. Text input remains with ImGui; this controller does not intercept character/IME input.

ShortcutEditSession retains immutable value/problem snapshots until an actual edit. Reset All and Revert explicitly advance its version even when their resulting values are equal, invalidating an older recording. Active-map comparisons cache the last checked values. Filter projections and private validation results are reused across unchanged frames; the three-line rows use a fixed clipper height and horizontal scrolling. The counters distinguish row queries/private grammar validations; no hardware latency or total-allocation guarantee is claimed.

Raw chord fields retain up to 256 provisional UTF-16 characters. The existing accepted grammar/storage limit remains 80 units. The native buffers reserve four bytes per provisional character plus a terminator. Character-bound rejection keeps the last owned text, while the actual widget can retain a larger displayed ASCII string within its byte capacity; exact complete displayed-map checks block Apply until it matches a valid private map. Hidden invalid fields remain in the draft and block publication. Show First Problem filters back to the relevant command without replacing its text. Footer validation is refreshed after edits/recording in the same draw, so Apply does not use an earlier frame's problem list.

Apply verifies every displayed binding, the active base and the complete candidate before the existing staged preference writer publishes it. Failed writes retain exact raw text, active bindings and retry ownership. Success canonicalizes only after persistence, starts a clean private baseline and merges the latest unrelated preferences. Error display is bounded and uses a non-null description. Revert failures retain the draft and show feedback. Projects, private resource IDs/raw seeds, history and procedural evaluation remain separate. The shortcut registry/grammar, User Config format/schema and headless engine API are unchanged.
