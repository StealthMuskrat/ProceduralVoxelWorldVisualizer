## Keep selection and private input active during preparation

Desktop ResourcePanel now uses the bounded editor executor for Apply in its Leave Properties for Resource Selection decision. This covers ordinary tree rows, Shift ranges, Ctrl sibling changes, final deselection and Voxel Manager selection. Apply captures the active private resource and a DocumentSession prepared edit. Its worker copies the owned committed project, replaces only the captured active resource, validates the complete candidate using the captured policy, freezes accepted values and builds the structural Undo delta. Worker code never reads live EditorState or ImGui controls. Committed values, the exact Properties draft and the old selection stay active until queued owner-thread publication.

A package-level EditorState.requestSelectionApply shares the existing owned-resource capture helper. Unlike the explicit single-resource Properties footer, selection can leave an already existing sibling selection; only its active private resource is applied. This preserves the legacy selection semantics. Public direct ResourcePanel and original ResourceSelectionSession constructors remain synchronous. No public headless API, project format 2, schema, registry or generated numerical semantics change; the batch reuses the existing prepared-edit protocol.

## Own the entire requested sibling plan

The pending plan owns an immutable ordered UUID list, active UUID and sibling scope. Duplicate/missing UUIDs, mixed scopes and an absent active member remain rejected; an empty plan requires a null active member. Another click cannot retarget a pending decision. Exact opening project lifetime/object/revision/values, selected UUID and ordered siblings, private draft object/values, raw seed ledger and saved path/dirty baseline guard the background operation. The private-editor blocker is checked at admission and again before publication, with ownership repeated after that callback. Reentrant admission cannot schedule another Apply.

Prepared-document checks additionally own validation-policy identity, saved checkpoint/receipt and Undo/Redo heads/bytes. An identical second successful Save still supersedes already prepared work. Both successful and rejected results must pass currentEdit. Shared diagnostic list identity, values and scope prevent an older selection Apply from overwriting newer validation. A detected source/private/selection change retires the older intent and preserves the newer state.

Successful publication commits once, refreshes the source draft, then resolves the whole destination plan again. Applying a parent can remove or move a requested child; the explicit edit stays committed, but the obsolete selection is not installed. A valid plan installs only after that check. Selection itself stays outside document Undo/Redo. Accepted no-op edits keep the active model, Redo and history bytes while still completing the requested selection. Neither Apply nor navigation saves the project or preferences.

A short installation fence covers publication, source refresh, selection installation and terminal UI completion. It rejects reentrant selection/action requests and prevents callbacks from clearing half-installed state. A refresh failure after model publication reports the completed edit without replaying or rolling it back. Terminal completion is delivered once; disposal suppresses later delivery.

## Cancel or explicitly recover

The shared decision footer keeps Apply, Discard and Cancel. During preparation, Apply displays Preparing Apply..., Apply and Discard are disabled, and Cancel/Escape remains active. Work transitions change footer gesture ownership without changing IDs every frame. The modal retains its scrolling explanation and persistent actions, and decisions still deliver after popup unwind.

Preparing is separate from the existing short publication/installation busy flag. This lets Cancel, pane reset and lifetime synchronization retire pending work instead of treating it as an uncancellable publication. Cancel, clear/reset, document replacement and ResourcePanel lifecycle closure invalidate work identity, cancel the FutureTask and remove queued work where supported. Non-cooperative/late completion cannot apply or select into another intent or a disposed pane. Desktop now closes the resource pane's selection work together with its existing export cleanup.

Invalid provisional seed text cannot schedule Apply and remains private. Compiler rejection retains the intent and immutable shared diagnostics. Scheduling, worker, handoff or admission failures end Preparing, retain the draft/selection and report bounded RESOURCE_SELECTION_APPLY_FAILED feedback. Apply explicitly retries; there is no automatic resubmission. After rejection, Discard remains explicit, while correcting the captured draft requires Cancel and a new selection request. Central resource Help describes cancellation, retry, sibling/empty plans and history separation.
