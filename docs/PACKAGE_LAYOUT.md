Export uses Choices, Included and Path/Issues pages in one scrolling body. Two persistent measured action rows contain Export, Cancel, Reload and Remove Missing, then Choices, Included and Path/Issues. Import uses a scrolling path/error body and one persistent Import/Cancel row. Labels have stable hidden IDs; disabled actions keep their positions. Path labels and inputs use available width. Error messages are bounded for native display while full owned feedback remains available to the existing event reporter. Path/Issues can request focus and scrolling to the actual raw path input after a failed attempt. A window too small to contain its action rows still requires resizing.

Included identifies Selected versus Required resource rows from the immutable prepared closure. The source catalog, selected UUIDs, dependency closure, folder context and immutable payload still use the existing services; no new procedural copy or implicit UUID substitution is introduced.

Only a visible Included list acknowledges its exact current preview. Choices and Path/Issues do not acknowledge a new selection. A reviewed unchanged preview stays reviewed while switching pages, editing the path, filtering or recovering from a failed write. This confirms display of the filtered/clipped preview component, not that every dependency row was individually read. The standalone `ResourceExportPanel.draw` entry point also offers Choices/Included/Issues and persistent Reload/Remove Missing for existing callers; the production package dialog supplies its own outer chrome and calls the same page renderer.

A committed source change retains the old preview/catalog without silently rebuilding. Reload explicitly retains selected UUIDs, prepares a successor, opens Included and requires a later display frame before Export is enabled. Missing selections remain selected until Remove Missing explicitly removes unavailable UUIDs; the successor preview must then be displayed. A foreign project cannot be adopted through Reload. The original full source-value check still runs immediately before file publication to reject unsupported in-place changes. Import/Export requests cannot replace a pending package action or Import review. The dialog also retains its exact ExportEditSession identity; external panel reset cannot silently freeze another source or make a replacement session eligible for that pending file action. Cancellation releases only its original session.

Cancel/Escape owns the decision frame before submission, including a mouse release on Export or Import in the same frame. Export still passes exactly the reviewed payload and latest active-project path to the existing validated staging/force/atomic-replacement writer. Failure retains raw path, selected UUIDs and the reviewed token for retry; success consumes the session and clears its private selection. Import reads the existing strict version-1 package format, then opens the separate COPY/REUSE/SKIP review without replacing or committing the current project. The package dialog never applies/discards a private Properties draft or changes project history, saved path or user preferences. No schema, registry, engine/model API, numerical, licensing or package encoding contract changes.
