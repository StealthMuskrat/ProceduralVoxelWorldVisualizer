# Curve publication ownership

Status: implemented on `codex/development-phase`, uncompiled and untested. GitHub testing remains paused by owner instruction. Existing curve evidence belongs to its recorded baseline.

Curve Apply now separates accepted staging into Properties from subsequent UI refresh. The opening `CurveDraftEdit` belongs to one exact EditorState, project object/revision/logical UUID, Properties draft, active noise UUID/kind, ordered sibling selection and exact curve item object/UUID. The opening curve parameter node is retained with an independent value copy. Replacing that node, even with equal JSON, requires reopening rather than retargeting the old editor. Removing the item, replacing the draft/project or changing its selection invalidates the opening.

The frame-time guard compares identities, revision and selection without serializing the full project or curve. A stale opening shows an explanation and disables Apply while retaining the private curve, local history and Cancel. Before actual staging, complete opening project values and curve source values are checked again, catching unsupported in-place mutation that did not increment the revision. The candidate is serialized and compiled as an owned ScalarCurve before the single parameter replacement. An existing curve keeps its UUID; a missing optional curve gets the new editor's UUID on its first accepted staging. Invalid candidates leave the source token open for correction. Accepted staging, including an equal-value Apply, and Cancel consume it.

Unrelated pending Properties fields and provisional seed text remain editable and survive curve staging, including changes made after the curve opened. They are not copied over from the opening snapshot or implicitly applied. Curve Apply stages only its parameter; Properties Apply remains the project validation/history transaction. Invalid raw seed text continues to block that parent transaction. Another Edit Curve request retains the already open editor rather than replacing its private buffer.

`CurveApplySession` validates and copies the private curve before passing it to the staging callback. A rejected staging call keeps the editor open with a bounded, non-null error; the next explicit Apply can retry. After staging returns successfully, publication is consumed before running UI refresh. A refresh exception closes the accepted editor and reports `CURVE_EDIT_REFRESH_FAILED` as an application error, while leaving the curve staged in Properties. Later draws or Apply requests cannot repeat staging or the failed refresh. Properties invalidates its noise index in a finally block even if clearing input widgets fails.

The public two-argument CurveDialog constructor remains available. Its single callback is the staging boundary and must return only after acceptance, or throw before publishing; the dialog cannot infer external side effects from an arbitrary callback that publishes and then throws. The production Properties path uses the owned staging token and a separate refresh callback. Engine interpolation, generation semantics, project format and headless API are unchanged.
