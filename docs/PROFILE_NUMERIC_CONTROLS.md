# Application profile numeric controls

Status: **uncompiled and untested** on main. The owner's testing pause remains active, the workflow remains manual-only, and the observed baseline remains 922 tests / 120 suites. This follows [noise](NOISE_NUMERIC_CONTROLS.md), [World](WORLD_NUMERIC_CONTROLS.md) and [Curve](CURVE_NUMERIC_CONTROLS.md) numeric authoring work and supports specification 2.3/4.1.2/4.3.3/18 and A32 without advancing acceptance evidence.

Application Settings creation-default sliders now use NoRoundToFormat and NoInput. The former five-significant-digit slider format could round a native double before its value reached the exact raw-input ledger; it now renders five fractional places without using that format as storage precision. Integer sliders render integral readouts and retain their existing explicit integer conversion. Exact raw fields remain authoritative for scalar/vector precision and signed long/integer parsing. Slider temporary text entry is disabled so it cannot replace retained raw text with a formatted readout.

Every raw numeric slider still requires a present override, current complete accepted raw components, no pending input error, exact displayed/ledger agreement and a finite value. A malformed scalar or any invalid vector component disables slider publication without discarding its text or last complete private value. Native disabled scope ends before invoking the existing ledger edit/change callback. Successful slider edits replace only that component's raw string with Double.toString or exact integer text; profile validation, Apply persistence, failed-write retry and concrete future-item creation retain their existing owners.

Presentation order now has the same measured slider/InputInt pair as other authored integer properties, using its existing [-10000,10000] validation interval. Exact text still permits a temporarily invalid order which blocks profile Apply until corrected. Numeric IDs include the selected control/component and SettingsActionScope version. Ordinary reflow/navigation retains the current private owner; replacing the private profile or live source gives the numeric widgets new IDs, preventing an old native input from silently continuing on a replacement draft. Existing raw-input retention and Show Invalid Value behavior remain; other presentation text controls retain their existing paths.

Application profile edits remain private until Apply saves and activates app-config. Existing project resources, document dirty/revision/history, private Properties edits/raw seeds and User Config do not change. Only later explicit creation uses the stored concrete defaults. No project/model/schema/engine API, field evaluation, immutable registry range or licensing contract changes.
