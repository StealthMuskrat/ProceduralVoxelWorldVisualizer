## Stage the exact reviewed package in the background

Desktop's existing background resource-package factory now covers Export as well as Import. After the current Included preview has been visibly acknowledged, Export captures an owned copy of precisely that preview, the current active-project path and exact document/private authority. The bounded editor executor copies and compiler-validates the resources, serializes the version-1 envelope, writes a temporary sibling, flushes it and closes its channel. Staging never replaces the destination or consumes the export review.

The path modal keeps drawing and shows preparation guidance. The submitted path, Export, page switches, Reload and Remove Missing are disabled while preparing; Cancel and Escape remain available. Disabled input does not repeatedly request native keyboard focus. Duplicate submissions cannot enqueue a second stage for the same request. Cancel/Escape retires the file opening and its export selection. Failed preparation or final replacement retains the path and the still-owned reviewed preview for explicit restaging/retry; a changed source requires the existing Reload and new Included acknowledgement.

ResourcePackageFiles.Prepared owns the unpublished target/temporary paths. Its publish method checks the latest live active-project path immediately before one atomic replacement; unsupported atomic moves have no ordinary-move fallback. Successful publication transfers temporary ownership, and close afterward performs no filesystem operation. Unpublished close is idempotent; a failed direct close retains ownership for explicit retry. Failed publication can retry the same staging while a direct caller retains it. The asynchronous dialog instead closes the failed staging and explicitly restages on retry.

The original synchronous writer now composes these same prepare/publish/close boundaries. It retains its live-path checks before directory creation, after real-parent resolution and before replacement, and preserves the original I/O/runtime/fatal error across distinct or identical cleanup failures. Input resources remain owned copies and existing project/package formats and constructor signatures remain.

## Guard final publication and cancellation cleanup

ResourceExportWriter owns the task, exact source/preview and a single-slot OwnedPreviewMailbox. The mailbox holds closeable staging rather than leaving a temporary file captured only in a queued callback. Cancellation, failure or shutdown invalidates that slot and closes any ready sibling. A non-cooperative worker that finishes after retirement closes its own rejected result. Cleanup failure is reported separately through the thread-safe event service and cannot overwrite a newer request or the primary preparation/publication feedback; an undeletable unpublished sibling can remain.

A successful worker awaits explicit UI delivery. Before publication the UI checks request identity, the original export session and exact preview, resource selection/path/frame-opening authority, current document identity/lifetime/revision, saved path/dirty baseline, committed values, selected resource/siblings and exact private Properties/raw-seed ownership. Current source-dialog/project-action blockers are checked again. Reentrant gates cannot retire or take a successor request's staging. The export session repeats exact reviewed-source validation and protects its final publication against reentrant cancellation/reset, then consumes only that session after successful replacement.

The final active-project check also protects a Save As path established after staging. Export never installs a project checkpoint, applies private Properties input, changes project/history/preferences or regenerates a field. Only explicit fixture edits in deferred scenarios alter source state. Successful file replacement remains a real publication, without later temporary deletion that could report a false export failure. Desktop's existing package-dialog lifecycle closure now retires both background Import and Export.

Centralized File > Export context Help explains Included review, background staging, Cancel/Escape, retained-path retry, explicit Reload, active-project protection and separate project/private state. Help does not initiate file work.
