# Background Theme Save and Binding Apply

Development implementation on main; **uncompiled and untested** under the owner's testing pause. No compiler, Gradle, JUnit, native probe, consumer, Python/schema checker or GitHub workflow ran. The observed baseline remains **922 tests / 120 suites**. Trees 2.2/4.4/18.5/18.7/19.6 and A22/A32/A33 retain their recorded partial/pending acceptance status.

## Shared staging and final input decision

Desktop Theme Save and Input Apply now use the existing PreferenceApplySession and bounded editor executor. The owner captures a detached complete UserConfig source and immutable typed palette or binding-map payload. Worker preparation constructs a private configuration, installs only the requested domain, validates the whole candidate, canonicalizes shortcuts, encodes and forces an unpublished sibling. A delivered result waits for the panel's current input decision before required atomic replacement. No additional confirmation is introduced.

Publication rechecks the exact private session/version, displayed values and complete live preferences. Theme activation installs only theme/colors/statusColors; binding activation installs only input.shortcuts. Nested appearance/input owners, global/window scales, unknown extension scale keys and unrelated preferences remain in place. Requests consume even equal-value publication before panel refresh, so duplicate deliveries or a refresh failure cannot replay a write. Competing preference forms cannot overwrite each other: a changed full active source retires older work; review and explicitly retry against current values. An owned-domain change requires Revert first.

Cancel Apply, Escape and Revert run before ready-result acceptance. Edits and explicit resets invalidate older authority. Queue, handoff, validation, write and atomic-replace failures retain private correction and the prior active/file values for explicit retry. Unpublished sibling/mailbox cleanup and late completion use the existing shared protocol. No unchanged-frame retry is added. Ordinary Save Preferences continues to save only active values; project/history/dirty state, private Properties, raw seed input, generation, schemas and headless APIs are unchanged. Direct constructors and synchronous apply APIs retain their behavior.

## Theme preview and exact RGBA ownership

Themes keeps its independent readable inspector palette. New save capture and final acceptance occur only after that pushed palette is popped and the latest private preview has refreshed. The request owns the exact native style token and preview/session objects; a different appearance taking control retires the pending save and retains the paused private palette until explicit Resume/Revert. Save never installs colors inside the recovery palette's stack.

Retained channel rows contribute exact immutable raw-string snapshots with row identity and generation. Numeric-equivalent edits, invalid text and change-then-restoration retire old save authority. Merely inspecting a newly visible canonical row is permitted; a newly edited or reset row is not. Invalid channel quartets still block Save and retain all sibling text. Filtering, clipping and switching Palette/Contrast do not discard pending input.

Collapse cancels pending save while preserving the private preview. Window close cancels save and releases the preview only if it still owns native style. Reopening starts from active preferences and cannot adopt a predecessor delivery. After successful Save, the session reloads the accepted active palette, so closing retains that palette rather than restoring the opening colors. Final Desktop disposal retires the background actor separately from reversible window close.

## Binding recording and host suspension

Input owns exact complete displayed raw chord strings and the private binding version. Preparation canonicalizes its detached map; accepted publication reloads canonical strings only after consuming the request. A separate recording epoch changes on successful Record start and recording retirement. Even start/cancel between frames, or capture followed by cleared suppression, cannot revive an older Apply.

The panel processes row edits, Reset/Revert/Cancel/Escape and capture polling before accepting prepared bindings. Starting Record on the same release frame as a ready result retires that result; the captured chord remains private. Existing one-frame dispatch suppression is retained for accepted and cancelled recordings. Hiding Settings or changing its category cancels capture and pending Apply while preserving the private binding draft. Final shutdown closes the actor before the shared editor executor.
