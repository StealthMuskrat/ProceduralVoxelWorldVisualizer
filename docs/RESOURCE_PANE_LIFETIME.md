## Independent retirement on document replacement

ResourcePanel previously cleared its clipboard and inline rename only through its explicit reset callback. That callback normally accompanies New/Open, but a direct DocumentSession replacement, same-UUID reopen or missed replacement refresh could leave the old clipboard or inline rename available in the new document. ResourceClipboard's project UUID check alone cannot distinguish two lifetimes of the same file. The same old rename could also keep a later file action blocked.

The pane now observes DocumentSession.sessionToken directly before drawing, shortcuts, resource edits/decisions, forms, focus/transition queries, manager opening and export interaction. A changed token retires clipboard, rename text ownership/focus, drag and range selection immediately. When no resource publication is in progress, the existing complete reset also retires pending forms/selection/edit completions, manager/filter/tree projections and export review state. If publication is currently executing, critical transient input is retired and new actions remain unavailable until a later safe synchronization completes the reset. No in-progress publication is cleared reentrantly.

A successful reset adopts the new token only after retirement completes. Repeated checks are idempotent. Ordinary committed edits, Save, Undo and Redo keep the document token, so the same pane opening and clipboard snapshot remain usable even though the canonical ProjectData object changes. Existing Copy captures values/order and remaps internal UUIDs; Cut moves current live identities/order and is consumed only after accepted publication. The underlying model clipboard and its public signatures remain unchanged.

Resources and Voxel Manager controls now include a pane-opening identity inside their unchanged native window identities. A same-UUID reopen cannot reuse the previous inline input's native ID or held control identity. Docking/window names and persisted preferences remain unchanged. Normal explicit reset also creates a fresh control opening. Clipboard shortcuts, stale draft decisions and stale rename blockers therefore do not depend on a future draw or successful external refresh callback to become safe.

Pane retirement does not modify the current project, saved checkpoint, history, separately owned Properties/raw input, User Config or system text clipboard. In direct model-only replacement cases, the old private Properties object remains under its existing owner until that workflow handles it; the resource pane does not silently apply or repair it. No project/schema/API version or generated-field behavior changes. Central Help now describes the clipboard/session distinction.
