## Construction arithmetic

Interior Smooth/Auto Bezier slopes use the existing same-sign harmonic mean, 2ab/(a+b). Multiplying two tiny secants could underflow to zero and introduce an artificial flat knot; a subnormal product could lose significant relative precision. Large products, a doubled large operand or a summed denominator could overflow even when the mean was finite. For example, a three-point straight line with slopes 2^600 could be rejected, while a line with slopes 2^-600 could bend because its interior derivative became zero.

ScalarCurve now preserves the original multiplication/division order when the sign product is normal and numerator/denominator intermediates are finite. Finite zero/opposite-sign secants keep a zero derivative at flat/turning knots. Other finite same-sign cases use a scaled magnitude calculation: if m and M are the smaller/larger magnitudes, m * (2 / (1 + m/M)), with the original sign restored. Its magnitude is bounded by M to absorb final rounding at the representable limit. This avoids the tiny product and doubled large operand without imposing an output clamp. Nonrepresentable secants retain their existing cubic rejection path.

Cubic coefficient construction also preserves every original finite coefficient. If a = m0 + m1 - 2*delta is nonfinite despite finite inputs, it retries a as (m0-delta) + (m1-delta). If b = 3*delta - 2*m0 - m1 fails and a is finite, it retries b as (delta-m0)-a. These identities avoid overflowing intermediates that later cancel, including large exactly linear cubics and explicit Free handles. Coefficients still reject if the final representation remains nonfinite. Constant storage, Horner evaluation, knot lookup, outside-domain mapping and caller finite-result checks remain unchanged; this does not make every mathematically finite curve representable by this coefficient form.

Ordinary finite arithmetic paths retain their existing operation order. Extreme tiny curves that previously compiled with flat/imprecise derivatives can produce corrected values; some extreme curves that previously rejected now compile. This is an intentional numeric bug fix, not a promise that all previously accepted extreme outputs retain their bits. Existing saved project fields and archive results are unchanged; regenerated values use the current compiler.

CurveModes exposes the additive read-only arithmeticPolicy descriptor guarded-harmonic-and-coefficients-v1 and its description in the format-1 curve registry. The checked-in descriptor and central curve Help use the same policy. Mode IDs/order, defaults, project format 2, schemas and public method signatures are unchanged. No creation/profile value, native edit transaction, renderer or dependency changes. Existing compiled arrays remain immutable and independent of the editable Curve.
