# Owned export workspace

Status: implemented on `codex/development-phase`, uncompiled and untested. GitHub testing remains paused by owner instruction. Earlier export evidence does not validate this extension.

The editor Export dialog now owns its opening committed source. `ExportEditSession` captures the exact project object/revision and UUID, a full value snapshot and one private source copy/catalog. Selection changes prepare dependency closures from that copy. Unapplied Properties fields and raw seed inputs remain separate; exporting never applies or discards them. Opening Export initially prunes unavailable browser selections as before, then freezes the source immediately.

`ResourceExportSession.Preview` adds an immutable prepared token with owned selected UUIDs, included metadata and a private payload. Its resources accessor returns a copy. A preview stays unchanged after later preparations or clearing the lower-level model. Existing prepare/resources/included/selected entry points remain available; ResourcePanel.exportSelection is still a read-only programmatic snapshot helper. Desktop file publication now uses the owned editor session instead of preparing a new payload on the Export click.

The source stays fixed until explicit Reload Preview. Any committed source identity/revision change retains the old catalog/closure for inspection, disables choice changes/export and offers reload for the same project UUID. Reload retains every selected UUID, creates a new source/catalog/preview and clears display acknowledgement. A different project UUID requires Cancel and reopening Export. Missing selected UUIDs remain selected after reload with no exportable preview; Remove Unavailable Selections explicitly removes them. They are never silently replaced by a different resource.

A current preview must have its included-resource child submitted visibly before Export is enabled. This means the preview component was displayed, not that a person read every clipped row. Choice changes invalidate the acknowledgement; filtering and scrolling preserve it and reuse the same closure. A successor preview cannot use the previous token's acknowledgement. Before file I/O, the session also compares the complete current source against its opening value snapshot, catching unsupported in-place changes that did not advance the editor revision. Such a rejection requires reload and leaves the target untouched.

The package writer receives an owned copy of exactly that displayed preview and the latest active-project path for the existing path-protection checks. File validation, staging, flushing and atomic replacement still use [ResourcePackageFiles](RESOURCE_PACKAGE_FILES.md). A failed write keeps the session, choices and displayed token available for correction/retry. Success consumes the session; Cancel/Escape and project/resource-panel reset release it without writing. Second package actions remain blocked by the existing package modal owner. No project dirty state, document history, private draft, preview computation or preferences change because of export preview/reload/write.

The source copy/full JSON value snapshot are prepared only on opening/reload. Catalog query results and closures are cached while drawing/filtering. Draw-time ownership checks use object/revision/UUID values; complete source serialization occurs only at the actual write guard. These operations can still be substantial for a very large project/selection; this batch makes no representative latency or memory-budget claim. Visible IDs/path labels are bounded for native submission, and resource rows remain clipped.
