# Private history for resource forms

Status: **uncompiled and untested** under the owner's testing pause. W01-C10 addresses Create Resource, Add Noise Generator and Delete Resource under 3.5.3, with the existing 3.2.4/3.2.8 actions. The last observed baseline remains 922 tests / 120 suites; no acceptance gate advances.

Each form now has a persistent Undo Fields/Redo Fields row. Create restores exact raw ID text and its optional algorithm choice together in edit order. Continuous native ID typing is one local action, finished on deactivation, focus loss or switching to a discrete choice. Returning to the original text adds no history step and preserves Redo. The absent algorithm choice continues to mean the current creation default; restoration does not freeze a default value or alter metadata. Placement restores the exact selected noise UUID or no selection, and always displays its selected ID even when a filter hides the row. Delete restores its replacement UUID or unresolved choice without touching dependents. Filters and scrolling remain navigation state.

ResourceFormOwner binds history to the original committed project object/revision and opening. It uses the existing TextEditHistory raw-field deltas: at most 100 completed steps and a soft 65,536 UTF-16-character budget, retaining the newest oversized step and one pending gesture. There are no full-project snapshots per action, trimming/normalization, new ID limits or computation changes. No-op edits preserve versions/Redo. Effective new edits abandon Redo. Stale/foreign/equal-value-round-trip tickets cannot restore, while Cancel/reset/resource-panel closure consumes the history and a new opening starts empty.

Primary/history controls own the current input version. Restoration also advances a separate interaction scope, resetting native text state and pending choice-picker ownership without changing the opening's resource/document identity. A held submit cannot survive an Undo/Redo round trip, even when all displayed values return to their previous values. Existing configured Undo/Redo chords belong to the focused modal only outside active native input/widgets; native text Undo retains its field. Cancel/Escape precedes history, and history precedes simultaneous submission.

History never creates, places or deletes a resource, changes references or publishes private Properties input. Existing validators and ResourceEditSession still own the explicit action and Apply/Discard/Cancel handoff. Rejected submission retains its form/history; correction or restoration clears the form's attempt feedback. Accepted or pending action handoff closes the form and consumes its history; cancelling the later action does not reopen the closed form. A successful action retains its existing one-transaction behavior and explicit Save boundary. Resource UUIDs, placement inheritance, User Config, authored formats and headless API remain unchanged.

They compare complete parent/private/preferences values, history/dirty/revision, raw seed input and engine identity. Existing shared history bounds and form-owner/transaction suites remain applicable. Help expectations now describe local versus native text history.
