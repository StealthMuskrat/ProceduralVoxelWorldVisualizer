# Hierarchical export choices and included context

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This extends [package layout](PACKAGE_LAYOUT.md), [owned export](EXPORT_WORKSPACE.md) and [resource hierarchy](RESOURCE_HIERARCHY.md). The validated baseline remains 922 tests / 120 suites.

Export Choices now presents the existing resource hierarchy instead of a flat catalog. Folders collapse/expand, World layers own their operation rows, and child/root order comes from the frozen `ResourceTreeIndex` built on the authored project order. Presentation groups use the existing noise2D, noise3D, world, voxel, group and set roots. No synthetic resources, new resource classification, saved expansion preferences or engine execution order are introduced. Layer captions retain the source's global run ordinal even when presentation order differs.

`ExportTree` builds one iterative full preorder per exact catalog. It uses the existing cached UUID/kind/ID match projection, then performs forward descendant propagation and reverse ancestor closure without recursive calls or repeated parent walks. Ordinary unfiltered folders default closed and layers default open, matching the browser convention. Search automatically reveals matching rows with ancestors; a matching container reveals its descendants. Selected Only shows exactly matching explicit selections with ancestor context and does not substitute for a missing UUID. These temporary projections do not overwrite stored disclosure state. Their forced-open disclosure controls are disabled until the filters are cleared; checkboxes remain available. Clearing search restores that state. Exact catalog/filter/selection/expansion inputs reuse the immutable projected row list; unrelated selection changes do not rebuild the ordinary unfiltered projection.

Checkboxes continue to represent explicit UUID selection. Checking a folder or layer asks the existing `ResourceExportSession`/`ResourceGraph.selection` to include its complete subtree/dependencies. Unchecking it removes that explicit UUID and retains other explicitly selected resources. There is no automatic checkbox propagation, alternate export planner or procedural remapping. Rows already in the current prepared closure but not explicitly selected carry an `[included]` marker. That marker covers subtree members, dependencies and context; it does not pretend to distinguish every provenance path. Unchecking a required resource alone cannot remove it while another explicit selection still needs it.

Included displays the exact prepared payload as a collapsible read-only hierarchy. Its source metadata/order is checked against the frozen catalog; it does not add unexported siblings or invent new required-resource rows. Carrier layers, source folder ancestry and pruned child/root orders remain those produced by the existing export model. Selected/Required captions distinguish explicit UUIDs from resources supplied by the closure. Choice and Included disclosure states are independent. Expansion/collapse never changes a selection, prepares another payload, invalidates an unchanged reviewed preview, dirties the project or enters Undo history. A visible Included component still acknowledges only its exact current preview; visiting every collapsed/clipped row is not a separate acceptance requirement.

Rows keep native checkbox IDs based on UUID, independent of indentation/caption/reflow. Disclosure controls use separate stable IDs. Indentation uses measured frame units capped at one quarter of available width so deep ancestry leaves room for action controls; the original depth remains in the projection. Checkbox pointer telemetry targets the checkbox square rather than a potentially clipped long label. Both choices and read-only Included rows use whole-pixel frame-plus-gap clipping, including disclosure height and an explicit tail item. The previous deferred package receipt checker is updated for Included's new frame-height rows. No payload semantics, schema, registry, public engine/model API, generation or licensing change.

Eight `ExportTreeTest` definitions cover authored order/depth and source execution ordinals, descendant/container/kind/UUID search, restored collapse, exact selected-only context, included subset ownership, cached expansion/catalog replacement, immutable results/rejected metadata and a 12,000-folder iterative chain. Two additional `ResourceReviewLayoutTest` definitions cover analytical indentation/disclosure budgets, finite extremes and invalid metrics. These ten definitions have not run.

`ExportHierarchyProbe` defines twelve production Choices/Included modal/scale cases across six wide/narrow/short/global/window combinations, including the 6.25 font product. Case setup stages one operation UUID through the private selection; native wheel input reveals its checkbox and checks stable IDs/depth/clipping. A separate ordinary-size workflow uses actual noise/operation/folder checkboxes, selected-only/search, World and Noise disclosures, restored collapse, subtree inclusion/removal, exact Included context, view-only expansion and explicit package submission. It checks the same source document/revision/history/dirty state, private Properties ID/raw seed, engine owner and cached preview. The fixture includes 502 noise resources and deliberately different World presentation/execution order. Its native context has no GLFW/OpenGL or physical monitor input.

`scripts/verify_export_hierarchy.py` defines independent footer/list geometry, stable operation IDs, exact carrier defaults and one selected operation, omitted sibling/unrelated sources, original UUID references, folder ancestry and pruned authored orders. `ExportHierarchyConsumer` compiles against the headless engine JAR alone and checks the same structure, constant `.625`, inherited SET behavior with no baked operation overrides, and occupied signed chunks at roots 2/4/8. It explicitly supplies destination world bounds for numerical replay; portable resources do not import project-wide settings.
