# Curve pointer ownership

Status: implemented on `codex/development-phase`, uncompiled and untested. GitHub testing remains paused by owner instruction. Earlier curve evidence does not validate these changes.

The Curve Editor routes point/group movement, editable tangent movement and middle-button pan through one `CurvePointerGesture`. A press captures plot origin/size, view bounds, pointer position and an owned point selection or tangent UUID/side/handle length. Later input cannot retarget the gesture. A sticky three-pixel threshold distinguishes movement from a click, so selecting a point does not snap its existing unsnapped value. Alt continues to bypass the independently enabled X/Y snaps.

Movement uses total displacement from the opening plot and curve. Middle pan also uses absolute displacement from its opening bounds, avoiding accumulation across event partitions. The release position is processed before ending the gesture, including when the last movement and release arrive together or outside the plot. A rejected crossing/nonfinite curve candidate preserves the last valid preview; release commits that preview to local history. One valid gesture contributes one local history entry. A click contributes none. Tangent Auto mode cannot start an editable gesture.

Plot origin/size changes cancel the active gesture rather than interpreting held movement in new geometry. Escape, collapsed/hidden content, window focus loss, ImGui application focus loss, another popup, invalid pointer position or a missing release also cancel. Cancellation restores the exact owned curve/view baseline without new history or clearing existing Redo. New curve objects, explicit gesture lifecycle changes or external view navigation supersede the pointer; rollback changes only state still owned by that pointer. Remaining held-button frames cannot restart without a new press. Undo/Redo, Fit, selection commands and other discrete commands finish the last accepted preview before taking their own action.

CurveDialog now respects ImGui Begin's visible-content result and returns before controls, preview computation or pointer updates when collapsed. Closing the window cancels its active interaction and completes the dialog; a closed dialog does not draw again. The application-focus flag uses the pinned imgui-java 1.89.0 IO binding. Explicit curve Apply still stages into Properties, and Properties Apply remains the sole project transaction. Curve serialization, interpolation, engine evaluation and public API are unchanged.

## Deferred verification

Eleven `CurvePointerGestureTest` definitions cover independent pixel/world deltas and final release coordinates, jitter without snapping, baseline/Redo rollback, resized/moved plot cancellation, immutable selection and external edits, failed discrete-edit ownership, external navigation, event-partition-independent pan, exact pan cancellation, tangent slope/Auto ownership, and rejected/missing release coordinates. `CurveEditSession` also supplies non-null error text for null-message runtime failures.

The production `CurveGestureProbe` definition now interrupts held group moves by collapsing the window and by actual ImGui focus events, verifies rollback/no held resumption, then retains its prior private Apply and one-document Undo/Redo flow. The saved curve remains `(0,0), (0.25,0.35), (0.75,0.85), (1,1)` with endpoint Clamp. `verify_curve_pointer.py` independently checks the report, knots and output UUID; future Linux/Windows steps call it beside the existing engine-only piecewise arithmetic consumer. No definitions or checks have been executed during this batch.

Native release-only motion, resize/undocking, arbitrary popup/focus ordering, tangent interruption, physical OS input/DPI and Windows 11 hardware acceptance remain pending. Conservative resize cancellation can discard the current private drag preview; the completed curve edit and earlier local history remain available. This is the chosen ownership policy, not a claim of uninterrupted dragging through layout changes.
