# Theme and Input decisions

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This follows [preference decisions](PREFERENCE_DECISIONS.md), [theme layout](THEME_LAYOUT.md) and [Input layout](INPUT_SETTINGS_LAYOUT.md). The validated baseline remains 922 tests / 120 suites.

Theme and Input collect their complete persistent footer before making a decision. Theme prioritizes Revert, Reset, Save, Resume and view navigation. Escape suppresses that frame’s footer decisions while retaining the palette. Input prioritizes Escape/Cancel Recording, Revert, Reset, Apply and problem navigation. Escape cancels a recording and suppresses other footer decisions; cancellation retains keyboard dispatch suppression for its frame. The existing recording poll stays after footer cancellation. These changes do not alter inline palette/shortcut edits or ordinary Save Preferences callbacks.

Both forms use transient PreferenceActionScope identities outside their stable scrolling bodies. Private edits, field navigation, filtering and magnification keep footer IDs stable. Successful save, explicit Revert and full Reset replace the private presentation context even if resulting values compare equal; failed saves retain exact private values and retry IDs. Input also snapshots its recording target, so recording entry/exit distinguishes footer contexts. The host’s existing cancelCapture calls now release the presentation context when Input is hidden, another category is shown or Settings collapses. Its private bindings remain retained.

Theme compares only its active starting appearance, color/status arrays and preview pause state, including the external style owner while paused. ThemeActionValues deep-copies arrays into immutable raw lists, including malformed external components, without validating or normalizing them at the presentation boundary. In-place changes therefore invalidate old footer activation while ThemeEditSession still decides whether saving is allowed. Global/per-window scales and bindings do not invalidate Theme ownership. Preview ownership loss advances the footer context; another external style replacement while paused also advances it, so a held Resume cannot overwrite that newer owner. Explicit successful Resume advances it again. Active private preview refreshes retain footer IDs. Collapsing/closing Themes releases its footer context. Existing ThemePreview still preserves newer external styles and installs preview/revert/resume values only after inspector style colors are popped.

Binding snapshots copy the exact active shortcut map without changing canonicalization or validation. Existing ShortcutEditSession and ShortcutRecording retain complete displayed-field, conflict, active-source, opening version and keyboard suppression checks. User Config publication still merges only accepted theme or binding values into the latest unrelated active settings, atomically writes, then publishes. Neither form changes project/private Properties drafts, project history, the engine, schemas, registries, startup resources or licensing. Theme close remains an explicit preview release; it does not save.
