# Resource draft decision layout

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This follows [selection ownership](RESOURCE_SELECTION_GUARDS.md), [browser transactions](RESOURCE_BROWSER_TRANSACTIONS.md), [source navigation](DRAFT_POPUP_LAYOUT.md) and [modal bounds](DIALOG_LAYOUT.md). The validated baseline remains 922 tests / 120 suites.

ResourcePanel selection and browser-action guards now share NavigationGuardDialog with Source links and Find. Selection and browser guards retain their Resources host, modal titles and preferred 620 by 300 bounds; Source and Find retain their existing hosts and preferred sizes. A measured scrolling body contains explanations, up to four bounded destination labels and any rejection feedback. One persistent row holds APPLY, DISCARD and CANCEL. New presentations reset body scrolling; rejected Apply requests reveal its bounded explanation. Complete draft, labels and underlying diagnostics remain owned by their existing sessions. A native window too small for its action row still requires resizing.

The shared presentation collects the frame decision before calling its owner. Escape overrides an Apply or Discard click released in that frame. Each opened presentation advances a private transient version scoped around native footer IDs, preventing a held predecessor from activating a newly opened request. The scrolling child keeps a stable identity, avoiding an extra native child window for each request. Inactive or externally cancelled sessions close their old modal and clear feedback instead of leaving a ghost decision. These presentation IDs are not serialized or used as transaction authority.

Selection still retains its exact project/revision, selected UUID, ordered sibling selection, draft object/value and raw-seed revision. Apply uses the existing parent transaction; rejected Apply retains private input. Discard navigates without publishing the draft; Cancel preserves it. Browser actions still combine an explicitly applied draft with their requested mutation in one document transaction and one Undo entry. Stale owners and blocked private editors prevent Apply/Discard. Source links retain their original freshness supplier and target; Find retains hit/context ownership. No model-session, persistence, schema, headless API or generation semantics change.

ResourceEditCompletion consumes the post-commit UI callback before invocation. Reentry or repeated completion cannot invoke it again. Cancellation releases it without invocation. A RuntimeException during refresh is reported once as RESOURCE_EDIT_REFRESH_FAILED in Application diagnostics, after the edit has committed; it does not roll back or replay that transaction. ResourcePanel clears the completed request before notifying the callback, so a callback that requests another action does not lose that new owner. Immediate edits use the same consumed notification path. Errors outside RuntimeException retain their existing propagation policy.

Four deferred ResourceEditCompletionTest definitions describe single consumption, cancellation, reentry, one failure report and unchanged document/preferences/history. Each case rejects invalid private seed text and cancels while preserving committed and private state. Further native phases describe release-plus-Escape for Apply/Discard, held predecessor replacement, stale source/selection/edit owners and a valid combined draft/rename whose refresh fails once, followed by one Undo/Redo. Requests and private draft edits are explicit fixtures; production native footer controls are exercised. Existing ResourceSelectionProbe and ResourceEditProbe retain actual browser row/menu/shortcut coverage. The context has no GLFW/OpenGL or physical OS input.
