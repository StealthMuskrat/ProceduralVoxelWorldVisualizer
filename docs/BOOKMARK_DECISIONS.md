# Bookmark toolbar and picker decisions

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This follows [bookmark modal decisions](BOOKMARK_LAYOUT.md), [bookmark ownership](BOOKMARK_DIALOG_OWNERSHIP.md) and [selector decisions](SELECTOR_DECISIONS.md). The validated baseline remains 922 tests / 120 suites.

BookmarkPanel now collects its complete toolbar before accepting at most one action in displayed order. A chosen popup row takes priority over toolbar commands. Escape suppresses toolbar opening/mutation and picker navigation. Native trigger/action IDs add a per-panel UUID and per-tab context version; a skipped source frame retires that tab's toolbar presentation. Separate tab scopes support all three toolbars in one frame without churning each other's IDs. Existing wrapping, hit-width caps and control labels remain.

BookmarkActionContext owns the document lifetime/project object/revision, tab, selected UUID and exact immutable index row, plus pending dialog identity/state. Changed selection, canonical publication, document, dialog or recreated panel cannot borrow an old held action. Before mutation, the live selected bookmark must still have the displayed name and coordinates. Camera coordinates and unrelated private Properties input are deliberately outside ownership. Update reads the latest accepted view coordinate after the toolbar decision; it rechecks ownership after that external getter returns and before the document transaction. Add's picked/current getters and public Add/Teleport coordinate capture use the same recheck, so a callback that replaces the document or pending owner cannot seed or edit the successor through an old action.

The bookmark popup uses SelectorSession for exact document/tab/selection/dialog opening ownership and raw-query/index row reviews. It retires changed or omitted sources and scopes row IDs to each opening/review. Query fields, popup IDs and scrolling child identities remain stable. Whole-pixel clipped row strides and explicit single-line hit heights retain full names/coordinates/UUIDs in tooltips. Picker rows are disabled while a bookmark dialog is pending. Filtering never silently substitutes another selected UUID.

Accepted navigation consumes one row and closes/unwinds the popup, child, clipper and native ID scopes before calling Navigation.teleport. Selection changes only after a successful callback that still owns the same source/tab/selection/dialog and live bookmark values. Runtime navigation failures keep the previous selection, record bounded BOOKMARK_NAVIGATION_FAILED diagnostics and reopen an unchanged review on its next consecutive source draw with query/error feedback and fresh row IDs. There is no automatic callback replay. An explicitly admitted successor dialog wins over the predecessor's failure; no old selection update or retry overwrites it. Document changes during callbacks reset selection/filter ownership. Partial navigation side effects remain the callback's responsibility.

Successful Update and Delete retain their existing explicit, undoable BookmarkTransactions operations. Delete clears selection only if it still names the deleted target. Rename/Add/Teleport retain the existing private modal and its transaction/validation/focus authority. Modal field/footer scopes, same-owner retry and consumed callback behavior are unchanged. These toolbar contexts are presentation checks, not new serialization or transaction services.
