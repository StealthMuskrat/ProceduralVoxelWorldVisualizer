# Project file publication and completion

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. The validated baseline remains 922 tests / 120 suites. This extends [project draft transitions](PROJECT_DRAFT_TRANSITIONS.md), [shared decision delivery](NAVIGATION_DECISION_DELIVERY.md) and [history completion](PROJECT_HISTORY_COMPLETION.md). No A01–A36 acceptance gate advances.

Project file buttons previously delivered draft/save decisions, file I/O and replacement/exit callbacks while their modal popup was active. A replacement callback exception after successful Open was caught as PROJECT_OPEN_FAILED even though the document had already been replaced. New completion also cleared old ownership after its callback, which could overwrite a new action started by that callback. Blocker callbacks were checked without revalidating whether they had replaced the request or changed private input.

ProjectFileDialog now collects the complete footer and Escape, captures the exact path string, and ends child/ID/popup scopes before invoking the workflow. Finally blocks balance entered scopes. Exact phase/admitted-request/opening/frame ownership is consumed before dispatch, and repeated drawing cannot deliver twice in one frame. Escape overrides a released primary action. Obsolete modal closure uses a separate balanced scope; a replacement phase or request opens in the next frame. Retained path errors continue to preserve text and request focus on the current input.

ProjectFileWorkflow tracks retirement separately from admitted request identity. Request and transition gates capture their opening context and recheck ownership after the blocker callback. A callback that cancels the old action and opens a successor cannot have that successor cleared by the earlier result or failure. Private input changed during a gate invalidates the old action. Apply Draft still commits one ordinary edit; its post-Apply gate can retire the transition while clearly retaining that committed edit. Cancel for pending modal phases bypasses blockers.

Synchronous Apply, Open, Save and New publication have a busy interval. Nested workflow commands/cancellation cannot interrupt that interval. Desktop history and import/export blockers use complete file busy state, including the named-save interval whose presentation phase is IDLE. Standalone Save/Save As retains its established permission to save committed data while private editors/input remain open; it does not evaluate transition blockers or apply private input. A failed required save still aborts its queued transition, and a corrected path retry remains a standalone save with the same admitted request identity.

Successful New/Open retires all old workflow ownership before delivering the replacement callback. Successful Open publishes its normal information event before callback delivery. Replacement refresh failures report PROJECT_REPLACEMENT_REFRESH_FAILED with the completed action identified; they cannot turn an already published Open into a failed load or replay the old replacement. Exit callback failures report PROJECT_EXIT_CALLBACK_FAILED without assuming the OS window closed. A callback may explicitly start another file action. Older completion reporting leaves that successor's phase, owner and inline error intact while still publishing the old failure to Logs.

Guard/callback diagnostics are bounded to 1,024 characters. Ordinary operation errors retain up to the existing 8,192-character event-detail budget, with the dialog's existing bounded text presentation. No serializer, atomic file-replacement algorithm, schema, preference format, autosave, backup or recovery workflow changes. Unexpected Apply completion failure retires the old transition and reports its boundary; this is not a rollback promise for a partially failed refresh or arbitrary custom validator side effects.
