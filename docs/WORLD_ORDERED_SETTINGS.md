# World ordered settings — unvalidated development

This main-branch source batch addresses specification 3.5.3, 4.1/4.2, 10.2.2–10.2.8 and 10.7: private ordered settings, stable editing ownership, sparse atomic inheritance and authored evaluation order. It is not acceptance evidence. No compilation, tests, native probe, engine replay or workflow ran. The owner testing pause remains active, and the last observed validated baseline is still 922 tests / 120 suites.

## Ordered row actions

World Properties now stages transform, numeric parameter-driver and type-interval structural edits until after the complete row drawing loop. Transform duplication previously inserted into the list during that loop. WorldListEdits captures one frame-local intent with the exact list and complete row identities, consumes it before delivery, and rejects a replaced/reordered list, invalid index, exhausted copy limit or repeated delivery without mutation. Ordinary edits of the still-owned row remain eligible, so duplication copies its current authored values. Copies own their concrete settings; they introduce no resource UUID or extra inheritance layer.

All three lists offer Up/Down and Remove. Transforms retain Duplicate, and numeric drivers gain the same independent-copy action. Type intervals do not offer Duplicate because copying their range would create overlap. Disabled boundary/cap controls stay visible, action buttons wrap/clamp in narrow content, and each list shows its existing limit: 64 transforms, 32 numeric drivers or 256 intervals. Add is unavailable in the frame delivering another structural request, preventing a removed row's release from also activating a reflowed Add button.

A shared World control version refreshes value/action native IDs after successful structural edits, transform-kind or driver-destination changes, and selection/draft replacement. It also advances selector ownership and clears obsolete text widget caches. Tree expansion IDs remain separate from this version. Indexed paths now cover all row values, including driver destination/combination, transform enable/kind/axis order, and interval inclusion/type pickers. Historical diagnostic collection indices still fall back to the owning setting; they are not current row identities.

Choosing the existing transform kind no longer resets its components. An actual kind change retains the existing explicit component-reset policy. Driver destinations retain application metadata labels. Existing layer/placement ownership is unchanged: inherited lists are read-only until Override; a list override replaces only that atomic property; Reset removes its key. Structural actions remain private until one Properties Apply, and project Save is explicit.

Transform numeric drivers keep their authored zero-based row targets. Moving/copying/removing transforms can change which transform is at that row or make the target invalid. Both transform/driver panels and central Help explain this; no automatic target remapping changes the model's established semantics. Validation still rejects an invalid target while retaining the private draft and committed document. Regrouped gates and ordered lists share native value retirement, but list edits leave gate seed paths intact: unrelated incomplete seed text remains attached to its existing path and continues to block Apply.
