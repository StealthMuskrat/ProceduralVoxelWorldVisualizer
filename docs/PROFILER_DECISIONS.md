# Profiler and shared Debug decisions

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This follows [Profiler layout](PROFILER_LAYOUT.md), [export review ownership](PROFILER_EXPORT_OWNERSHIP.md) and [general settings](GENERAL_SETTINGS_LAYOUT.md). The validated baseline remains 922 tests / 120 suites.

Profiler now collects its complete eight-action footer before executing at most one decision. Escape suppresses every footer action without stopping collection or discarding a review. Precedence is Discard Review, Stop, Clear, invalid-limit navigation, Start, Prepare, JSON and CSV, subject to each action’s existing eligibility and current ownership. Fields/children keep their established identities, sections and layout; the persistent two rows of four retain their order and measured budgets.

Three separate presentation scopes preserve the existing independent authorities. Capture actions use the exact Profiler, current Capture reference and recording eligibility. Prepare uses the exact displayed immutable Snapshot object, so a held predecessor cannot prepare a different refreshed/replacement snapshot. Discard/JSON/CSV use the exact ProfileExportSession and its available/consumed state. New captures, Stop, Clear, sample growth and display refresh therefore do not change an independent review’s action IDs; replacing or consuming the review does. A frozen review may still export through a capture replacement while its own held button remains valid. Failed writes retain review, path and retry IDs; success consumes before another format can publish.

ProfileActionContext is a constant-size UI value. It reads current capture identity and recording eligibility, including the existing deadline check; it does not copy/summarize samples. Raw limit edits, measurement filtering, section navigation, preferences and reflow do not become capture ownership. Existing ProfileCaptureInputs displayed-map validation, immutable options, bounded collection, quarter-second snapshot refresh and ProfileExportSession/ExportPaths/atomic ProfileIO publication remain authoritative. Export execution captures its review explicitly and attaches success/error feedback only if that review still owns the panel. The scopes grant no capture or file-publication authority.

Debug & Profiling uses the same context for its Start/Stop toggle and Open Profiler actions. Complete footer collection and Escape suppression precede the shared callbacks. A changed current capture or recording eligibility invalidates armed predecessor controls, including Stop becoming Start after collection stops. It still calls ProfilePanel.start for exact private limit validation and opens Profiler on an explicit Start attempt, including a rejected limit that needs correction. Explicit Open alone never starts collection.

Desktop releases Debug presentation when its Settings page is hidden/collapsed/closed and releases Profiler presentation when its tool is hidden. ProfilePanel also releases all footer scopes on a hidden/collapsed native window. Captures continue and private inputs/reviews survive; reopening gets new native action IDs. Stable body/field IDs and existing section scrolling remain. These are UI-thread presentation checks, not a locking protocol for arbitrary concurrent external controller calls.
