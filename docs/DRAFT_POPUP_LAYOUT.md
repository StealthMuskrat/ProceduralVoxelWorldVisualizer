# Local choice and source-navigation popup layout

This development batch is **uncompiled and untested** under the owner testing pause. It extends the existing [selector geometry](SELECTOR_LAYOUT.md), [monitor work-area policy](POPUP_MONITOR_WORK_AREAS.md) and [DPI font scopes](UI_DPI_AND_FONT_DENSITY.md). It does not certify requirements 4.1.4 or 4.3, physical detached windows, Windows 11, mixed monitor DPI or GPU font upload.

`DraftChoicePicker` now uses the same anchored, monitor/client-bounded `PopupLayout` as resource and bookmark selectors. Its preferred size is 480 by 340 logical units; actual bounds fit the resolved work area. The query and clipped list use available width/height. Trigger widths no longer impose a 100-unit minimum, labels wrap, and clipped choices expose their label, detail and exact key in a tooltip. Existing widget IDs, per-widget query caching, the 128-context bound, authored choice order, nullable choice callbacks and key identity remain unchanged. Escape closes without calling the change callback, and closed widgets clear transient row-hit observations. Layout/filtering never stages a parent draft.

Both referenced-noise and trace/log/profiler source-link draft guards now use `NavigationGuardDialog`. Their existing popup titles and SearchNavigation decisions remain stable. `DialogLayout` provides a resizable preferred 600 by 360 host with the existing logical Properties owner, monitor intersection and main-client fallback policies. The explanation and persistent failed-Apply feedback scroll separately above one measured action row. Apply, Discard and Cancel each receive an equal bounded hit width; clipped labels retain full tooltips. Escape invokes Cancel once. Native button height still follows the effective font; clients too small to contain one font-height action row cannot offer a physical reachability guarantee.

The dialog only presents decisions: existing SearchNavigation retains exact source/draft/selection/raw-seed ownership, validation, transactions and navigation. Failed Apply preserves the pending owner and private input. Feedback survives redraws and is reset by the next explicit opening. Accepted or cancelled decisions close the popup. Callback exception recovery is unchanged and is outside this layout batch.

A pending `GuardedNavigation` now rejects a second request before evaluating or assigning its freshness supplier. Previously, the lower-level navigation session rejected retargeting after the outer guard had already replaced that supplier. An unrelated fresh request could therefore weaken the original freshness condition, or an unrelated stale request could prevent an otherwise valid decision. The opening request now owns both its destination and freshness predicate until completion; a later request after Cancel obtains a new lifetime. Completing a queued decision also clears its opening prompt, so Cancel before the first draw cannot open an unowned modal later.

Closed `DialogLayout.begin` calls now return before touching native NextWindow state. This preserves an unrelated caller's queued position/size and avoids resolving monitor inventory for a closed modal. Opening, resizing and monitor recovery retain the existing geometry policy.

Five deferred `GuardedNavigationOwnershipTest` definitions cover original freshness after a second request, supplier non-evaluation/destination preservation, raw-seed Cancel, rejected Apply followed by changed freshness, and a new request after Cancel. The deferred `DraftPopupLayoutProbe` uses the real picker, Properties referenced-noise guard and source-link guard in twelve narrow/scaled cases: three global factors on a 360 by 240 client and a 6.25 user font product on a 720 by 480 client. It defines real key search/selection, retained queries, empty search, failed Apply feedback, all three action rectangles, Escape, exact private/project/history preservation and unrelated NextWindow preservation and Cancel before the first draw. It builds the production dense font atlas without a renderer. `scripts/verify_draft_popup_layout.py` independently checks reported geometry, action order and receipt identities.

Future Linux/Windows workflow commands and artifact paths are wired without changing triggers or starting any run. These definitions are not validation evidence. All five tests, twelve native cases and the replay script remain unexecuted; the validated baseline stays at 922 tests / 120 suites. Inline combo/context-menu bounds, tooltip scaling at deep nesting, broader internal window reflow, native physical monitor transitions and full GUI acceptance remain pending.

The unvalidated [Find/Trace workspace follow-up](FIND_AND_TRACE_LAYOUT.md) adds Find as another explicit logical host of the shared bounded navigation decision, retaining failed-Apply feedback and original hit/context ownership. Its new native definitions remain deferred.

The unvalidated [resource decision layout follow-up](RESOURCE_DECISION_LAYOUT.md) extends the shared presentation to ResourcePanel selection/browser guards using SettingsPageChrome. Shared Source/Find decisions now give Escape priority over a simultaneous click, scope footer IDs to each opening and close cancelled model owners. Stable scrolling child identities and existing navigation/freshness owners remain. New native definitions remain deferred.
