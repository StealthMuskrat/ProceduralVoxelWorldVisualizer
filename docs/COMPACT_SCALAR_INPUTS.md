# Compact scalar fields with exact native editing

Status: **uncompiled and untested** under the owner development-phase pause. This implements the remaining settled idle-field presentation path in specification 4.1.2 while preserving full-precision editing. It extends [scalar readouts](SCALAR_READOUTS.md), [numeric metadata guidance](NUMERIC_METADATA_GUIDANCE.md) and the existing private numeric controls. Source coverage is not full Tree 4, native, physical DPI, Windows 11 or release acceptance.

Previously paired sliders/read-only labels used ScalarDisplay's five-place summaries, while adjacent native double inputs always drew their full seventeen-digit format. Changing that native format on focus would risk initializing the activation buffer from rounded text. ScalarInputs therefore leaves the real editor, its ID, label, format and value/buffer unchanged. Double editors always receive %.17g; caller-owned ImString objects always receive their full raw text. The rounded readout is never parsed, assigned to a buffer or sent to a setter.

For an inactive eligible scalar field, the adapter makes only the native text color transparent during submission, then paints a compact readout inside the same frame's padded, clipped interior with the original inherited text color. The native frame, selection, navigation and hit target remain. Native active-ID ownership selects the normal exact editor presentation; no replacement focus item, extra click, button or popup is introduced. The existing visible-label convention is preserved. Drawing adds only draw-list text, so last-item bounds, programmatic focus, contextual Help, metadata callbacks, Curve gesture ownership and explicit Apply boundaries remain attached to the original input.

Presentation is selected using the native active ID at submission. On an activation/deactivation frame the previous presentation may remain for one frame; the native activation buffer already contains the full precision during that frame. A raw edit arriving on activation paints its actual spelling immediately. This avoids using a rounded string to seed editing and avoids clearing/reloading the native editor's cursor, selection, undo or incomplete input state. The source implementation does not claim zero-frame presentation handoff or measured glyph/pixel output.

UiFields connects all ordinary double property/literal/vector/World/Curve rows, and ViewportFields connects local scalar inputs. Fixed viewport Center X/Y/Z explicitly use the coordinate readout policy, preserving whole signed coordinate digits plus up to five fractional places. Integer native fields and integer-tagged double rows retain their original exact text presentation. Signed-long/coordinate raw integer ledgers remain unchanged.

Application profile NUMBER/vector fields compact only when the complete displayed buffer set agrees with its valid accepted raw ledger; rejected/out-of-range or stale text remains fully visible. Theme channels compact a valid accepted color but leave all raw channels visible while that color requires correction. UI scale compacts only successfully parsed values. These owners retain their existing raw spelling, grammar, range validation, whole-value vector/color correction, explicit persistence and private-versus-active separation. Profile TEXT/LONG/INTEGER controls retain their existing presentation. Float preferences retain their existing stored float type; engine values remain double.

ScalarInputPresentation keeps a bounded LRU cache of at most 512 readouts per owner, keyed by native ID, full raw double bits and scalar/coordinate policy. Stable redraws reuse formatted strings; signed zero, changed values or changed policy invalidate the readout. Caches retain no native/font/window objects and clear with existing owner lifetimes. Font, geometry, disabled opacity and clip intersections are read from the current field each frame. Tiny and large values use the existing bounded scientific policy; invalid double feedback remains explicit.

Ten deferred ScalarInputPresentationTest definitions cover independent compact/exact format expectations, stable-format reuse and signed-zero invalidation, bounded owner traversal/reset, coordinate whole digits/cache policy, active/integer/invalid ownership decisions, literal hidden-ID labels, padded frame-versus-label geometry, exhausted narrow fields, fractional/composed font metrics and rejected geometry. No definitions were executed.

The extended deferred ScalarDisplayProbe retains its six Properties/view layout cases and exact setter/slider/idle replay, adds adjacent-double focus through the real Properties focus wrapper and viewport mouse input, and appends an insignificant zero at the end of the native buffer. If activation had used compact 1 instead of 1.0000000000000002, that edit would become 10 and fail. Native receipts record the unchanged full-precision format, source, ID, field geometry, clipped compact ink and active state. A raw fixture retains +.12345678901234567 spelling, appends a zero to that actual buffer, keeps rejected '-' and the full integer 9007199254740993 visible, checks inherited disabled alpha and verifies style restoration. The probe observes submitted text/geometry and actual native editing, not rendered glyph readback, physical clipboard, DPI or every production dialog scenario.

A new future verify_scalar_inputs.py independently checks all six layout receipts, source double bits, coordinate policy, exact/compact focus handoff, raw/integer spelling and disabled alpha. The existing Linux/Windows ScalarDisplayProbe commands now include this replay in the same manual-only workflow. Its trigger is unchanged and no workflow was dispatched. No model/schema/engine/API, project/configuration format or numerical evaluation changes are introduced.

Only source inspection, Java formatting and git diff --check are performed. No compiler, Gradle, JUnit, native probe, receipt script, generator, independent engine replay or GitHub workflow ran. The observed baseline remains 922 tests / 120 suites. Existing native parse conventions and owner validation remain; this does not add a general raw ledger to native double fields. Full integration/platform/hardware and final release validation remain pending.
