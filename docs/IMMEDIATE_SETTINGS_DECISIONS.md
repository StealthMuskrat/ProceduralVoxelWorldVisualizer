Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This follows [general settings](GENERAL_SETTINGS_LAYOUT.md), [preference forms](PREFERENCE_FORMS_LAYOUT.md) and [workspace lifecycle](WORKSPACE_LIFECYCLE.md). The basic constructor retains a two-action row. If no ordinary-save callback is supplied, Save is visible but disabled. Existing production Desktop supplies its save handler; older no-handler docking/placement fixtures remain usable. The older preference-layout checker now expects the added workspace footer key.

Workspace, Editor and Visualization collect their complete footer before invoking at most one callback in displayed order. Escape suppresses that frame’s callbacks. Editor retains its one Save action and Visualization retains Save/Edit Preview Limits/Retry Shadows. Retry remains disabled while directional shadows are off. Native action IDs include a transient per-panel UUID and presentation version, distinguishing different Workspace instances that share a native root/body and separating Editor/Visualization Save buttons. Scopes surround footer widgets only, preserving field and child IDs.

These forms edit active User Config values immediately. Their presentation scopes do not freeze preference values or create another private Apply form. Checkbox/slider/visibility edits and ordinary saves keep their current presentation IDs. Workspace callback availability and Visualization shadow-retry eligibility also distinguish contexts, so a held predecessor cannot become an enabled successor action. Save still writes the latest complete active User Config through its existing handler. Neither a successful save nor a handled failure consumes the form; retry IDs stay stable.

Desktop releases inactive immediate categories after the category chooser and releases all three when Settings is hidden, closed, collapsed or showing another page. Fields and active values remain; a returning category gets new action IDs. Existing docking reset, main-window centering, visibility, regeneration and renderer services remain the callback authorities. Inline immediate edits and their existing visibility-change callback are outside footer arbitration. Appearance and the ordinary-save composition of private Performance/Trust/Input forms retain their existing paths and are outside this batch.
