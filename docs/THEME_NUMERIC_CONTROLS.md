# Theme and scale numeric controls

Status: **uncompiled and untested** under the owner development-phase pause. This implements the appearance/preference portion of specification 4.1.2 and extends [Themes layout](THEME_LAYOUT.md) and [theme preview ownership](THEME_WORKSPACE_OWNERSHIP.md). Universal scalar readout/exact-edit presentation and complete GUI/platform acceptance remain outstanding.

Every palette/status RGBA channel now has a bounded [0,1] slider and a separate decimal text field. The existing slider ID stays stable; each text ID is distinct and both survive filtering and measured 4/2/1 column reflow. When one channel cell cannot fit both controls, text stacks beneath its slider; axis labels can stack separately. Whole-pixel clipped strides reserve both input rows. Five-place slider presentation uses NoInput/NoRoundToFormat; full text is the editable representation and never comes from the rounded readout. Native color picking remains available.

`ThemeChannelDraft` owns four raw strings and the last accepted immutable color. Strict ASCII decimal/scientific text is bounded to 128 characters per channel; malformed, nonfinite and out-of-range input remains visible instead of being clamped or replaced with a valid fallback. The draft is allocated only for known submitted palette/status rows. Candidate arrays are detached; a NaN rejection marker is consumed only by the existing channel-error ledger and cannot become a ThemePalette value.

An invalid channel blocks its entire color's sliders/swatch and Save Theme. All four text fields remain editable: valid sibling edits stay with the rejected raw color and are published to the private preview together only when all channels become valid. Filtering, clipping, pane switching and idle frames retain the raw quartet. Accepted text retains its spelling, including extra significant digits and signed zero. Explicit starting-color, starting-appearance, Revert, Reset and close clear their owned drafts. An unexpected changed source color replaces the corresponding raw quartet rather than attaching old raw text to another color.

The existing theme transaction remains authoritative: preview edits do not update active preferences, ordinary Save Preferences excludes the private palette, Save Theme atomically publishes only a valid reviewed palette, and close restores the owned active style. Active-base checks, external-style pause/Resume, safe inspector colors, failed-write retry and unrelated preference merging are retained. No model/schema/engine/API dependency changes are introduced.

UI-scale sliders now also disable native temporary text and display-format rounding. Their existing separate raw fields, strict 0.5–2.5 validation, global/window inheritance, private Apply, stale-base rejection and persistence remain unchanged. The scale slider readout uses five fractional places while raw text keeps every entered digit; the stored preference type remains float.

Eight deferred `ThemeChannelDraftTest` definitions cover independent raw float bit patterns (including subnormal/endpoints/negative zero), exact spelling, multi-channel invalid correction, strict grammar/domain limits, detached candidates, external/reset ownership, rejected edits/acceptance and private theme publication. Two additional `ThemeLayoutTest` definitions cover independent pair-stacking thresholds; existing layout definitions now budget paired fields. No definitions were executed.

The existing deferred production ThemeLayoutProbe now types an exact high-precision channel, retains incomplete text and a valid sibling across filtering, refuses disabled-slider repair, corrects the whole color, restores its original authored palette, and records all eight distinct channel IDs plus slider/text rectangles through its six layout cases. UiScaleLayoutProbe additionally defines exact private scale input and an actual off-center drag that must retain precision beyond the former two-place format. Existing future receipt scripts require the new flags and independently replay float bits/pair geometry/scale precision. No new workflow is added or dispatched.

Only Java formatting, source inspection and `git diff --check` are performed for this batch. No compiler, Gradle, JUnit, native probe, receipt checker, schema generator or GitHub workflow has run. The observed baseline remains 922 tests / 120 suites; this is development source, not final conformance or a Windows 11 release.
