# Resident volume overlap reuse

Camera-relative windows now reuse compatible texels from their accepted GPU texture. Eligibility requires an explicit immutable source key, integer unit-grid placement, overlapping bounds and identical encoding offset/scale bits. Canonical minima/maxima may change without changing the encoding map. Unknown or changed sources, changed encoding, disjoint windows and backends without copy support upload from the CPU. Fixed analysis and the synchronous setVolume API keep the full-host path.

The candidate still owns separate admitted storage; the accepted texture is never overwritten. A central overlap box and up to six disjoint complement slabs cover the candidate exactly once. Compatible overlap copies from the accepted texture, and newly exposed slabs gather encoded CPU rows through the existing 64 KiB staging buffer. Host writes and GPU copies share Upload KiB as a destination-write budget, including partial rows. Only the complete candidate publishes its extent, encoding, source region and viewport origin.

A half-width move of a 64³ window can copy 524,288 bytes and upload 524,288 host bytes rather than uploading all 1,048,576 bytes. A completely contained window can require zero host bytes. This reduces host transfer; it does not remove the complete candidate allocation or destination writes, promise a latency improvement, or provide a sparse atlas. Encoding changes conservatively fall back to host transfer even for geometrically shared cells.

The OpenGL 3.0 path uses equal-size GL_NEAREST layer framebuffer blits between matching R32F images. Scissor clipping is disabled for the copy and restored; read/draw framebuffer bindings and caller state are preserved. Both temporary framebuffer attachments are detached after each copy so retiring a texture cannot leave a hidden storage reference. This follows the floating-buffer and equal-size blit rules in the [OpenGL 3.0 specification](https://registry.khronos.org/OpenGL/specs/gl/glspec30.pdf). Native validation includes values below zero and above one, hostile scissor/color/read-clamp/PBO state, exact texel readback and complete framebuffer equality against fresh host uploads.

Resident and Statistics records gain region/copy components. Their historical constructors remain; record-pattern/reflection clients must account for the extended shapes. The old stage(data,budget) and GlViewport.stageVolume(data,budget) overloads do not infer identity or enable reuse. Backend.supportsCopies defaults false, preserving existing backend implementations. New explicit-region overloads authorize reuse only when the caller can identify immutable sampling semantics. Uploaded/last byte counters remain total destination writes; hostBytes/lastHostBytes and copiedBytes/lastCopiedBytes split the transfer paths. Profiler series report host and resident-copy bytes separately.

Cancellation, replacement rejection and copy/write failure release only incomplete candidates and preserve accepted texture/metadata. Failed advances retain successful destination/copy byte accounting. A legacy full-host retry remains available after copy failure. CPU canonical samples, project/history, headless engine APIs and archive formats remain unchanged. Sparse residency, coarser scalar LOD, representative hardware throughput/latency, arbitrary device faults and full GUI/Windows 11 hardware acceptance remain separate.
