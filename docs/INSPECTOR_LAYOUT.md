# Inspector pages and persistent actions

Status: **uncompiled and untested** on `codex/development-phase`. The owner testing pause remains in force. This follows [raw Inspector coordinates](INSPECTOR_RAW_COORDINATES.md), [Inspector focus ownership](FREE_FLY_AND_INSPECTOR.md) and [shared trace workspaces](FIND_AND_TRACE_LAYOUT.md). The validated baseline remains 922 tests / 120 suites.

The Voxel Inspector now has Coordinates and Trace pages inside one scrolling body. Its two measured, persistent action rows contain Trace XYZ, Cancel Pick/Trace, Bookmark, Use Traced, Refresh and the other-page button. Disabled decisions keep their position. XYZ field IDs remain independent of column count and window scale; complete signed 32-bit text stays private view state. Longer help/status paragraphs scroll without moving the action rows. This retains the existing floating window identity, placement and User Config scale target.

Coordinates shows XYZ before feedback and explains the explicit operations. Trace uses the same immutable `TracePanel` as before; its own copy/source/value/page actions remain inside a contained workspace. Inspector notices are part of the trace's scrolling body rather than a growing prefix above that workspace. The contained height uses the actual parent budget without the standalone trace's five-frame minimum. Logs retains its previous standalone trace policy. A window physically too small for its action rows still requires resizing; this does not claim arbitrary zero-size layouts or physical DPI certification.

An explicit trace or World-pick request opens Trace when it starts. Page navigation does not cancel work, alter XYZ, trace again, move the camera or change a selected observation. Completion does not force the user back to Trace after they have selected Coordinates. Misses return to Coordinates with their recovery hint. Invalid Trace or Bookmark opens Coordinates and requests focus/scroll to the first problematic axis. Display mismatch takes priority over syntax in the accepted raw input; axes use canonical X/Y/Z order. That navigation never adopts a mismatched native string, repairs text, applies Properties or falls back to an earlier parsed cell. Focus requests survive clipped frames until the input becomes active/focused.

Use Traced restores every coordinate from the retained snapshot, cancels pending Inspector work and starts no new work. Refresh remains available only for a changed revision of the current project; it intentionally traces the displayed snapshot coordinate while retaining entered XYZ. Another project's trace stays reviewable with source restrictions and no Refresh. Cancel is handled before starting or replacing work in the same presentation decision. Bookmark continues to open the existing separate explicit Bookmark transaction in production; the presentation probe records the request without simulating that transaction.

Trace ownership is observed even while Coordinates is selected, the Inspector is closed or its native window is collapsed. A replacement snapshot clears the previous trace query/observation/native publication identity before a pending source navigation can Apply or Discard. Hiding an unchanged snapshot clears only visible-row/control telemetry and preserves its selection/filter. No engine/model/schema/API or generation semantics change. Existing project/revision/raw-input publication predicates, cancellation, background queue reclamation and draft guards remain in Viewports and the shared services.

Five additional `InspectorCoordinatesTest` definitions cover first-problem order, native display disagreement, independent map ordering, malformed buffer sets/null disagreement and all-axis strict decimal parsing. Two `TraceLayoutTest` definitions cover contained heights, proportional/fractional/extreme budgets and nonfinite geometry. These seven definitions have not run.

`InspectorLayoutProbe` defines twelve native production presentation cases: Coordinates/Trace across six wide/narrow/short/global/window-scale combinations, including the 6.25 font product. It defines real text/button input for invalid Trace/Bookmark recovery without a second field click, exact signed bounds, page-preserved requests, cancellation, explicit restoration, separated bookmark intent, complete trace copy, changed/foreign snapshot handling, hidden-publication source-guard invalidation and miss recovery. It uses the existing analytical field fixture (22 at `(2,0,3)`, final voxel 1), a private rejected Properties seed and independent project/revision/history/runtime ownership checks. It has a native ImGui context without GLFW/OpenGL; its simulated pending task has no worker future. The existing full Viewports WorldLodPickingProbe, InspectorFreshnessProbe and FreeFlyInspectorProbe now explicitly select Coordinates before native field editing and remain deferred for actual background, camera and platform coverage.

`scripts/verify_inspector_layout.py` defines independent receipt geometry, footer ordering, stable XYZ identity, contained trace actions and analytical committed-fixture replay. Future Linux/Windows commands and artifacts are wired into the existing workflow; triggers are unchanged. No build, compiler, JUnit, native probe, schema/generator, Python verifier or GitHub workflow was run. All gesture/IME/paste paths, real worker races, physical clipboard/DPI/detached displays, internal native font behavior and complete A29/Windows 11 acceptance remain pending.
