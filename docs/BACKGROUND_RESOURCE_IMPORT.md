## Prepare the package and initial conflict preview outside the UI action

Desktop's File > Import now uses ResourcePackageDialog.background. Submitting a path captures an owned committed destination snapshot and exact document/private-input authority, then schedules the package read, strict envelope/project parsing, enabled-noise compiler validation, COPY identity allocation and first ResourceImport.Session preview on the existing bounded editor executor. The worker receives the source path and private destination values; it does not access the live EditorState or draw native controls. No destination project or package file is written during preparation.

The path modal continues drawing the current application and shows preparation guidance. The submitted path and Import action are disabled while reading; Cancel and Escape remain available. Duplicate submission and retargeting cannot enqueue another read for the same opening. The existing precedence of Cancel/Escape over a simultaneous native submit remains. Errors retain the entered path and return to an explicit corrected retry. The read, validation and initial conflict planning are one preparation; review installation does not rerun them on the UI thread.

An editor-owned FutureTask and opaque request identity separate worker completion from UI publication. A successful worker waits for its queued UI delivery. Cancel, a changed owner or shutdown retires the identity and cancels/removes queued work where supported; a running non-cooperative read/compiler can finish later but its callback cannot open review. Terminal scheduling, worker and UI-handoff failures become bounded actionable import errors rather than permanently running state. No package output/temporary file is owned by the read request.

## Install only the current private review

Before installing review, ResourceImportLoader checks document lifetime, active project object/revision, committed JSON values, saved path/dirty baseline, selected UUID/sibling selection, exact Properties draft object/values and raw-seed ledger version. Current source-dialog/project-action blockers are checked again. The import panel repeats its admission gate and then checks the loader's exact request authority, so a gate that cancels or replaces the request cannot admit an older preparation afterward.

ImportEditSession.Prepared owns its incoming values and precomputed model privately and can be consumed once. Installation verifies the prepared destination against the current committed project. The existing review session takes that model and cached plan without regenerating COPY UUIDs. No preparation object exposes mutable incoming/candidate access. Direct synchronous panel constructors and the existing immediate package composition remain available to isolated legacy workflows; Desktop selects the background factory.

Preparation does not acknowledge the preview or apply any changes. Only the existing visible Resources list acknowledges its current plan; changing a COPY/compatible REUSE/SKIP choice still invalidates that review, and explicit Import still publishes one complete validated document transaction. The existing Reload, blocked/rejected Apply, stable targets, diagnostic feedback, Undo/Redo, source definitions, selection and private Properties/raw seed preservation remain. Save alone does not alter a ready import model's revision. Closing a completed review still follows its existing private cancellation behavior.

Desktop owns and closes the package dialog during lifecycle teardown before editor resources are released. Closing retires background preparation and prevents reopening. Context Help for File > Import now routes to centralized guidance describing background preparation, Cancel/Escape, stale ownership, retained-path retry and explicit review/one-transaction publication; it does not run an import.
