Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This follows [Inspector pages](INSPECTOR_LAYOUT.md), [raw coordinates](INSPECTOR_RAW_COORDINATES.md) and [shared Trace decisions](UTILITY_DECISIONS.md). The validated baseline remains 922 tests / 120 suites.

InspectorPanel.Status now carries the actual admitted InspectorRequests.Request; pending and World-pick state derive from it rather than unrelated booleans. The six persistent footer actions collect before arbitration as before, with their existing Cancel/Use Traced/Refresh/Bookmark/Trace/page priority. Escape suppresses that frame's entire footer. Native action IDs add a per-panel UUID and context version outside the stable field/body scopes. Disabled actions keep their positions and can no longer inherit a held gesture when a replacement context enables them.

InspectorActionContext freezes document lifetime, project UUID/revision, exact retained TraceSnapshot and Request references, accepted coordinate version/raw XYZ, displayed native XYZ and selected page. Map snapshots are immutable and comparisons ignore insertion order. An equal-looking snapshot, an equal-valued request object or an edit/reset round trip back to the same text still retires its predecessor. Capturing does not parse XYZ, adopt native buffer differences, repair invalid text or return a fallback cell. Explicit invalid Trace/Bookmark continues through the existing coordinate authority and problem focus/recovery path.

The panel reads a current Status supplier again after collecting its footer and compares the complete context before returning an action. This rejects a request, display or document change during drawing as well as changes between press/release frames. Feedback/hint/error strings are deliberately outside action ownership: progress text alone does not invalidate Cancel for the same pending request. Viewports supplies its live Inspector status; the older InspectorLayoutProbe uses the same supplier contract. Model dispatch remains on the UI thread immediately after panel drawing in production.

Viewports releases the Inspector presentation when the window is hidden, closed or collapsed. Returning requires a new footer gesture while raw fields, page, retained trace and focus state remain. Suspension itself does not cancel work. Existing close-X cancellation and the existing request-validity/reconciliation services retain their authority over actual background jobs and view changes. An explicit page switch remains independent of pending work; Use Traced restores without starting work, Refresh traces the displayed historical coordinate while retaining entered XYZ, and Bookmark opens its separate transaction. Foreign-project snapshots still offer no Refresh.

InspectorTask now accepts attach/finish only from the exact Request object admitted by begin. Request records from independent gates or reconstructed equal-valued records cannot finish a successor or replace its attached future. Replacing/canceling still requests interruption, rejects late attachments and retains the shared InspectorRequests serial/revision/view publication gate. No request record fields, scheduling policy, engine API or immutable trace semantics change.
