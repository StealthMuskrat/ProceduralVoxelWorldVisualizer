# Application creation-default input ownership

Status: implemented on `codex/development-phase`, uncompiled and untested. GitHub testing remains paused by owner instruction. Existing application-profile evidence belongs to its recorded baseline.

Application Settings now retains raw creation-default fields independently for each immutable control ID and vector component. Selecting another control, changing Presentation/Creation Defaults sections or filtering rows does not discard those buffers. The session owns both the provisional strings and the last complete accepted private value. Hidden invalid inputs block Apply even when the underlying private JSON still contains an earlier valid value. Show Invalid Value navigates to the first offending control and resets its detail scroll without clearing text.

Signed long/integer fields accept signed decimal integer text, with exact 64-bit parsing before registry range validation. Scalar/vector fields accept finite decimal text, including decimal exponents, and retain Double.toString precision rather than formatting values to five fixed fractional digits. Hexadecimal forms, whitespace, nonfinite values, incomplete exponents, overflow and registry range/type violations remain private errors. Numeric raw strings are bounded to 128 UTF-16 characters. Text creation defaults retain up to 32,768 provisional UTF-16 characters for correction; their existing registry limit is still 8,192. Existing cross-field/expression/profile validation still runs before persistence.

Vectors parse all components together. No parsed vector replacement occurs while any owned component is invalid. The desktop also submits all displayed components together, so a widget value rejected at the raw-buffer bound cannot cause another edited component to use its old parsed value. Sliders are disabled for invalid or mismatched displayed fields. Numeric scalar/vector rows put the slider beside the exact raw field; slider updates explicitly replace that component's text. Text/long fields retain their dedicated editors. The native buffers reserve four bytes per allowed UTF-16 character plus a terminator; larger displayed ASCII pastes can fit within a byte buffer yet still reject the character bound. Exact displayed/owned checks block publication until corrected. Byte-capacity overflow, IME and physical paste behavior remain unverified.

`MetadataEditSession` owns the ledger and refuses publication while it has invalid/stale inputs. The panel additionally compares every retained native buffer, including hidden controls, before enabling Apply and immediately before writing. Changes to a mounted default outside its ledger are rejected rather than silently retargeted. Reload Value discards that control's provisional text and rereads its current private value. Removing an override/Use Built-In Value discards that control only; repeated enable of an already enabled override keeps its pending text. Revert Profile, Stage Built-In Profile and a successful Apply explicitly replace the whole input ledger. Failed validation, stale active metadata or a failed write retain it for retry. Raw formatting is not written into app-config; successful publication stores concrete values and then starts a clean private baseline.

Application rows now reuse their sorted/filter projection until the private profile or query/section changes; scrolling and unchanged frames keep the same projection. The visible list remains clipped. Profile edits still invalidate validation and relevant row order. No constant-time, search debounce, large-profile latency or frame-budget claim is made. The ledger is bounded by the finite registry/control/component set, and unsupported IDs cannot allocate extra entries.

This work changes editor input and private profile publication only. Existing resources, project history, unapplied Properties IDs/raw seeds and generation output do not read the provisional profile. Only future explicit creation uses saved defaults. Project/app-config versions, immutable creation registry/signatures/ranges, headless API and serialization schemas are unchanged. Other application numeric editors, such as presentation Order, retain their existing behavior.

## Deferred verification

Twelve `CreationValueInputsTest` definitions cover hidden invalid seed retention and file preservation, signed extrema/spelling, adjacent/tiny/subnormal/signed-zero doubles and profile round trips, finite decimal/integer failures and hard bounds, whole-vector publication including oversized displayed components, stale private defaults and explicit reload, UTF-16 text bounds, exact complete displayed maps and immutable returned collections, scoped override/reset behavior, failed-write/success lifetimes, stale active metadata and existing-project/private-draft/evaluation isolation. They have not run.

`ApplicationProfileInputsProbe` defines a production-panel ImGui workflow using synthetic text/mouse input and programmatic initial control/section selection. It requires unchanged cached/clipped rows, a hidden invalid seed blocking file publication, the real Show Invalid Value button preserving its raw input, exact Long.MAX_VALUE, a 1e-9 scalar, atomic vector correction, an occupied-directory write failure with retained text, corrected-path retry, saved future seed and unchanged project/history/private seed/evaluation. Its directory contains a fixture profile and JSON report. `verify_creation_inputs.py` checks the existing schema and independently expects the exact integer, small scalar, complete vector and report assertions. Future Linux/Windows workflow definitions run these alongside the existing profile/headless consumer and retain the creation-profile directory; development-branch trigger exclusions remain unchanged. No workflow, test, build, probe or verifier was executed for this batch.

The native fixture does not cover every row-picker/section gesture, physical input, very narrow/scaled layouts, all slider domains, IME, filesystem durability or Windows 11/full GUI acceptance. Full program/release acceptance remains outstanding.
