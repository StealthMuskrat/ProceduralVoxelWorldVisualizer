# Manual update window layout and decisions

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This follows [manual update checks](MANUAL_UPDATE_CHECKS.md) and [update trust](UPDATE_TRUST_AND_PREFERENCE_FILES.md). The validated baseline remains 922 tests / 120 suites.

Check for Updates now uses a stable scrolling results body and two measured persistent rows: Check Again/Cancel Check/Configure Update Trust, then Open Release Information/Copy Release Link. Every phase retains the same geometry; link actions are disabled without a reviewed result and all actions are disabled after shutdown. Installed version, status, full bounded release URL and link feedback wrap within the body. A new request/result presentation reveals the body top. A link action requests one-shot scrolling to its own feedback; magnification alone preserves presentation identity and scrolling.

The complete footer is collected before a decision. A current-context check follows drawing; Escape runs first, then explicit cancellation, configuration, Check, Open and Copy. Escape cancels a running request, otherwise suppressing the frame’s footer actions without discarding a Ready review. No action starts on Escape while stopped. Collapsing releases native action ownership while leaving collection active; closing cancels/clears the request and result. Reopening/expanding gets a new footer presentation context. Merely opening the results window still does not start a check; Desktop’s existing explicit Help entry point remains responsible for starting a configured manual request.

SettingsActionScope uses the exact request token, phase and result object (or session while no result exists). The new package-private requestToken getter exposes only an opaque presentation identity. Cancellation, new requests, applied trust changes and shutdown already invalidate that token; worker/UI publication and UpdateCheckSession’s exact-result/configuration checks retain all authority. A value-equal result from a later request cannot reuse an armed predecessor button. Footer scopes remain outside the stable body child and are never persisted.

Link-action feedback is also owned by the exact request and result. A browser/clipboard callback may explicitly replace or close the request before returning or throwing. Its old completion/error cannot attach a message to the successor. Failures still report through the existing Application error consumer. An ordinary failed browser action retains its Ready result, native retry IDs and feedback; Copy stays available. Configure routing and the production browser/clipboard implementations remain existing callbacks. Arbitrary callback side effects and all exceptional configuration routes remain outside the guarantee.
