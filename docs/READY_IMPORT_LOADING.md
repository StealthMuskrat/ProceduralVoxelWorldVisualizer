## File Location decides before opening review

Initial package preparation previously opened the private Import review from its queued UI delivery, before File Location could process current Cancel/Escape. ResourceImportLoader now retains the prepared package or captured preparation failure in a one-slot CPU mailbox. Delivery marks readiness only: the path dialog remains pending, phase RUNNING and the request token remain stable, and neither review installation nor preparation-error reporting occurs from that delivery.

ResourcePackageDialog captures the shown opening and original request before drawing. After the native popup scope ends, it dispatches current controls, giving Cancel/Escape precedence, then accepts only that same request and opening. A Submit that prepares inline cannot be accepted as the previously shown work; it waits for a draw that owns the new request. Loading finishes without an extra confirmation. An unavailable native popup does not accept a package on behalf of absent controls.

Acceptance compares the exact displayed path text with the submitted text, including Unicode, spaces and equivalent but differently spelled paths. It repeats document lifetime, project object/revision/full committed values, saved path/dirty baseline, selected UUID/ordered sibling selection, private draft identity/values and raw seed version checks. Current opening/context and blockers are checked again before the Import panel consumes prepared values. Authority is rechecked after presentation callbacks, so a callback that cancels and creates a ready successor cannot authorize that successor through old work. The panel's own admission gate repeats current authority before consuming the prepared model.

Successful acceptance installs the existing privately owned model and cached first preview once, preserving COPY identities. Installation does not acknowledge rows or apply the project. The separate visible Resources review, current COPY/compatible REUSE/SKIP choices, displayed-plan acknowledgement and explicit final Import action remain required. Later preview planning and final Import retain their separate policies. Direct synchronous package-dialog constructors remain synchronous; direct loader owners now explicitly accept delivered preparations.

Ready success, malformed input and captured preparation failure can all be cancelled before opening review or reporting that preparation failure. Accepted failures retain the entered path and explicit corrected retry. Stale project/private/path/opening ownership retires old work without replacing newer values or starting another request. No draw retries automatically. FutureTask observation continues through readiness so an inline delivery followed by a handoff fault cannot silently install an unaccepted review. Infrastructure faults retain their existing refresh/failure behavior.

Cancellation, stale ownership, retry and close clear the mailbox independently of draining UI callbacks. Retired workers cannot repopulate it, and queued callbacks hold identifiers rather than prepared payloads. Close also closes the mailbox and prevents reuse. Cooperative interruption and non-cooperative read/compiler limits remain. No project, package, preference, history, schema, registry, public engine API or generated field/voxel rule changes in this batch. Source capture, exact owner comparisons, native row projection and review installation still cost owner-thread work; no measured latency, heap or large-package bound is claimed.
