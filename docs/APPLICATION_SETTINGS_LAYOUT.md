# Application Settings layout

Status: **uncompiled and untested**, implemented on `codex/development-phase` under the owner testing pause. This extends [creation input ownership](CREATION_INPUT_OWNERSHIP.md), [outer window fitting](CORE_WINDOW_LAYOUT.md) and [nested font scopes](UI_DPI_AND_FONT_DENSITY.md). It is not complete 4.3, A32, Windows 11, physical detached-monitor/DPI or GPU-font certification.

Application Settings now places its entire editable workspace inside one scrolling body and reserves one measured native button row outside it. Apply Application Profile, Revert Profile, Stage Built-In Profile and Show Invalid Value have equal bounded hit widths with full-label tooltips when clipped. Show Invalid Value remains present and disabled when there are no raw creation errors. Failed saves retain the existing private profile and exact buffers; the same footer remains available after reflow for retry. Feedback stays in the scrolling body and can require scrolling to read. Extremely short clients that cannot contain one native font-height action row still cannot guarantee reachability.

The metadata list and detail use measured pane budgets. If two minimum-width panes fit, they sit side by side. Otherwise they stack, with the result list capped at four text rows. Horizontal and vertical spacing are accounted for separately. A four-text-row minimum combined pane budget keeps the detail viewport usable when a large heading exhausts the immediately visible body; the surrounding body scrolls to that content. This can intentionally put panes below the visible body. The footer remains separate. Row previews remain bounded single-line text even while a private presentation value is invalid; hover shows the full label and stable control ID. The list stays clipped and reuses the existing cached projection on unchanged frames and resize.

Presentation labels now sit above available-width fields. Section/filter/choice fields use available width, multiline fields use measured text heights, long descriptions wrap, and creation reset/reload actions fit and wrap. Numeric scalar/vector slider and exact-text pairs share a row only if both measured minimum widths fit; otherwise the same widgets stack at full width. Long and text defaults retain full-width editors. The numeric input IDs and their source/component scope remain stable across both arrangements; moving between columns and stacked panes does not clear or reinterpret raw strings.

Layout still delegates validation, complete-vector parsing, hidden invalid input checks, exact displayed-buffer checks, scoped resets and atomic profile publication to the existing owners. No implicit Apply, new project transaction, buffer reset or file write occurs on resize. Existing project values, private Properties IDs/raw seed text, revision and history remain separate. The existing creation registry, profile/project/user schemas, persisted formats and headless API are unchanged. Other settings pages, presentation Order parsing and the existing callback/write ownership semantics are outside this batch.

`SettingsPageLayout` holds pure finite-metric calculations for body/footer budgets, action widths, pane orientation and slider/text pairing. `SettingsPageChrome` applies the body/action policy to the production panel without storing native wrappers. Ten deferred analytical definitions cover independent numerical budgets, threshold boundaries, narrow/scaled panes, separate gaps, exhausted content, finite extremes and invalid measurements.

The deferred `SettingsLayoutProbe` uses the real Application Settings panel, production dense font atlas and synthetic native input. It defines six wide, narrow, short and scaled cases, including a 6.25 user font product. The fixture requires all four footer rectangles and the body to fit the client, both pane orientations, stable scalar widget IDs, exact invalid exponent text after reflow, blocked invalid Apply, cached row projections, Show Invalid Value after a section change, occupied-destination failure followed by narrow-window retry, and unchanged project/history/private Properties. It measures native ImGui layout without GLFW, a renderer or actual monitor DPI. It does not claim every field remains simultaneously visible or that every high-scale scroll path has been exercised.

`scripts/verify_settings_layout.py` independently checks reported geometry, row order, field identity, raw text and the corrected saved scalar. The earlier deferred `ApplicationProfileInputsProbe` receipt is now version 2: its obsolete fixed fewer-than-twenty row assertion is replaced with measured row height/list bounds and total-row clipping. Its replay consumes the same measured receipt. Historical passed evidence is unchanged.

Future Linux/Windows probe/replay commands and artifact paths are wired with development trigger exclusions preserved. None of these tests, probes, verifiers, generators or builds ran for this batch. The validated baseline remains 922 tests / 120 suites. Other settings internals still need their own responsive-layout work; the separate [Themes follow-up](THEME_LAYOUT.md) covers palette/contrast and RGBA controls; the separate [Input follow-up](INPUT_SETTINGS_LAYOUT.md) covers shortcut rows and recording controls; the separate [Appearance follow-up](APPEARANCE_SETTINGS_LAYOUT.md) covers the user-scale page; physical monitor transitions, IME/paste, extreme-size accessibility and full program acceptance remain pending.
