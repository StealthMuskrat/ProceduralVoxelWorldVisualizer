# Atomic archive publication — unvalidated development

This batch supports specification 14.3.5, 14.4.1–14.4.4 and 19.6.2, with A21/A22 coverage definitions. No compilation, JUnit, independent consumer, checker, packaging command or workflow ran. The owner testing pause and last observed validated baseline of 922 tests / 120 suites remain unchanged.

## Atomic replacement without fallback

VoxelArchive.Writer previously preferred ATOMIC_MOVE but, when unsupported, retried using ordinary replacement. That second move could remove or partially replace an existing valid archive before failing. Both legacy-v1 and packed-v2 writers now require atomic replacement. Unsupported atomic publication reports IOException with destination guidance and the original AtomicMoveNotSupportedException as cause; it never invokes an ordinary replacement fallback. This applies to new destinations, existing archives, empty archives and omitted-payload EMPTY coverage.

Preparation is unchanged: append builds only a private sibling, and finish writes the complete sorted index/footer, syncs and closes it before attempting publication. A publication error retains the exact complete closed candidate in PREPARED state. It rejects further append and permits finish retry without rebuilding, rewriting, resyncing or reclosing the file. Recoverable destination failures may be fixed and retried on that same writer. If the destination permanently lacks the capability, close the writer to abort and create another writer at a supporting destination. Catch failures inside the writer's lifetime when retry is intended; leaving try-with-resources aborts the unpublished candidate.

Successful atomic replacement alone enters FINISHED. Repeated successful finish/close perform no further publication or cleanup, so a pathname subsequently owned by another writer is untouched. Explicit close after rejected publication deletes only the owned sibling and cannot publish later. Existing checked/unchecked initialization, rollback, abort and reader-cleanup recovery remains authoritative. No file operation is added after successful publication.

ArchivePublication is a package-private, per-writer boundary whose production implementation performs exactly one Files.move with REPLACE_EXISTING and ATOMIC_MOVE. Existing public factories/signatures and the earlier ArchiveOutput constructor boundary remain compatible; no mutable global injection or alternate public codec is introduced. Only deterministic deferred module faults inject the publication boundary. Archive versions 1/2, modified-UTF dictionary, compression, sorted index, semantic remapping, wire bytes, coverage, Reader behavior and headless dependency direction remain unchanged. No schema/registry wire-version change is needed.

This intentionally rejects filesystems/providers previously served by the unsafe fallback. It does not promise support on every provider, filesystem crash/power-loss durability, atomic directory syncing or behavior beyond the provider's atomic-move contract. Physical permission, locking, replacement and unsupported-volume matrices remain deferred.

## Deferred definitions

Ten ArchivePublicationTest definitions cover unsupported atomic replacement with existing valid archives and readable prepared bytes; absent destinations; repeated access-denial retry of identical bytes without extra writes/sync/close; recovery after an unsupported-capability failure; unchecked publication exceptions/Errors; abort cleanup and permanent publication rejection; terminal completion after later pathname ownership; empty/sparse EMPTY archives; inspection of a complete closed sorted archive before publication; and rejection of a null boundary before staging. Both formats are covered by the main publication/retry cases. Counted real-file output delegates distinguish preparation from publication; injected failures are definitions, not observed provider evidence.

The existing engine-only ArchiveRecoveryConsumer command additionally invokes ArchivePublicationConsumer. For both formats it writes a valid prior archive, prepares different replacement data while independently reading the old destination, then publishes and compares exact bytes with a fresh reference. No reader handle spans replacement, so the replay does not invent a cross-platform sharing guarantee. Reordered runtime registries must decode independent signed-position cell patterns and omitted EMPTY coverage correctly. Later uncommitted aborts retain the published bytes; completed writers cannot overwrite a pathname assigned later bytes; retained chunks and supplied registries remain unchanged. There must be no leftover owned sibling after normal completion/abort.

Independent expectations cover 64 prior stone cells, 64 replacement pattern cells and eight EMPTY cells per format: 272 exact observations in total. Future output includes replacement/reference/terminal v1/v2 archives and atomic-publication.json. The earlier 198-cell failure/retry replay and reader cleanup/corruption replay remain intact. Existing manual-only Linux/Windows commands already invoke the expanded source, without trigger changes or workflow dispatch. The public replay covers actual normal replacement and abort; unsupported atomic-move faults are module-level definitions, not a simulated physical-volume certification.

All ten contracts and the independent replay remain uncompiled/unexecuted. Full filesystem/provider failure timing and durability, JVM/platform/Windows 11 hardware and final release acceptance remain pending. Main remains authoritative; no development branch was created.
