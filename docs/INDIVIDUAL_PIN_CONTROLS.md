# Individual pinned item controls — unvalidated development

This source batch extends the compact pinned-controls feature in specification 6.11.4 and the persisted presentation identities in 20.3.17, with 4.1.2 numeric editing, 3.3/3.4 copying and explicit project Apply/save boundaries. The owner testing pause remains active. No compilation, JUnit, native replay, independent consumer, checker, schema generator or workflow ran; the validated baseline remains 922 tests / 120 suites. Main is authoritative.

## Original controls, live sources

Pin Item remains available. Each processing/coordinate item also offers a searchable Pin Control picker for its authored parameters and named inputs. The default value slot of Constant items is available even when its implicit zero has not been materialized. Multiple controls from one item may be pinned independently. Adding the same exact item/path again leaves its existing pin intact. New labels identify the item and chosen control; labels and groups remain editable presentation metadata.

A specific pin stores the original item's UUID and a logical control path. It stores no copied computational value. Numeric literals and Boolean parameters edit the original item map through the existing provisional Properties draft. Constant items and constant input bindings use the existing Scalar/Boolean/vector/coordinate editors. Scalar controls retain paired suggested sliders and exact double text; rendering the panel does not quantize values or create missing literals. Structured/textual controls keep a link to their original editor rather than adding a competing editor.

Bound inputs show the current resolved source and Go To Control, without exposing an editable constant. The source description resolves current names/UUIDs without evaluating procedural fields. A parameter pin follows a same-named input while Bind is enabled and returns to its original literal when that binding is removed. The literal and binding remain at their original locations. A pin created for a named input remains tied to that input; removing the input requires unpinning or repairing that pin before Apply.

Go To Control routes a specific pin to the exact current parameter/input, opens a pinned curve's existing private editor, or disables the route with repair guidance if the control is missing. Whole-item/shared-parameter routes retain their existing behavior. Picker selection still belongs to the exact Pin object, so two pins on one item do not share transient picker identities. Historical UUID-only pin-metadata navigation remains ambiguous when several pins target that item and reveals the picker rather than guessing.

## Additive format-2 identity

Pin adds `control`, a string defaulting to empty. Missing/empty means the existing whole-item/shared-parameter behavior. Specific item paths are `parameters/<key>` and `inputs/<name>`; the complete suffix is the map key, including any slash in it. Shared parameters also accept the explicit `value` alias. These strings are control identities rather than copied parameter content or historical array indices. The project version remains 2, and legacy files without this field load with the empty default. Older binaries that reject unknown fields need updating before reading newly saved pins.

PinControls centralizes path enumeration, live resolution, validation and duplicate admission without an editor/native dependency. Validator indexes item targets once per noise and reports an invalid target or path at the exact pin index. A missing or incompatible control blocks project publication instead of silently falling back to another field. Structural item replacement keeps a pin's path only if the replacement actually supports it; otherwise the existing structural-edit transaction reports the problem and leaves the draft unchanged. Unpin first or choose a compatible replacement. Ordinary duplication/import UUID remapping preserves the path while remapping its original target.

The canonical schema and ContractGenerator define the optional string/path shape together. Semantic validation additionally requires an existing target and live control. Null/non-string malformed controls and nonexistent paths reject. JSON/CSV export formats and engine arithmetic are unchanged. Pin metadata remains excluded from preview computation identity; editing the original value through a pin is a real computational draft change. Apply remains one resource transaction, followed by ordinary Undo/Redo and explicit Save. User preferences and committed resources are untouched by navigation or provisional editing.
