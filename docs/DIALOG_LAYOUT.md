# Modal viewport bounds and responsive actions

Status: implemented on `codex/development-phase`, **uncompiled and untested**. Builds, regression/native execution, independent replay and GitHub testing remain paused by owner instruction. No historical pass count or acceptance gate is advanced.

## Hosting and geometry

`UiWindowHosts` records logical Resources, Properties, Visualizers and Find hosting viewport IDs and immutable owner rectangles immediately after their real Begin, including a collapsed Begin. EditorState owns this transient map; it contains no native pointer or preference data. Desktop clears it for context initialization, and a decreasing native frame count also clears old associations. Observations preserve signed representations of unsigned viewport IDs. Missing logical owners use the main viewport.

`DialogLayout` resolves the current viewport from an owner's recorded ID on every call, verifies the temporary native wrapper and falls back to the main viewport when that ID is absent/removed. It reads current ImGui viewport WorkPos/WorkSize. A transient invalid/zero rectangle retains the last valid work area for that viewport; otherwise it falls back to the main viewport or a preferred-size provisional area until valid native dimensions return. Native wrappers are used locally and never retained between frames. Popups are assigned the resolved host viewport before Begin.

The original policy bounds dialogs to the **hosting ImGui viewport's client work area**; the separate [monitor-intersection follow-up](POPUP_MONITOR_WORK_AREAS.md) now adds absolute-coordinate monitor work intersections and visible-main owner recovery. Main-window physical monitor fitting remains in the preceding [main-window placement policy](MAIN_WINDOW_PLACEMENT.md). The original batch does not independently intersect detached windows with OS monitor work areas; the follow-up implements intersections and popup recovery while leaving physical host movement to its own policy. Full specification 4.1.4 physical monitor behavior remains partial.

`DialogBounds` is a pure per-lifetime geometry policy. It reserves up to eight screen-coordinate units at each work edge, reduces margins for very small rectangles, and fits preferred width/height together. Minimum constraints are 160 x 120 or the smaller available dimension. A new lifetime centers its fitted preferred rectangle. Explicit Open resets the previous lifetime's measurements; no raw editor data is reset by geometry.

Every modal Begin gets current minimum/maximum size constraints. Position is submitted only for opening, a changed host/work rectangle or a measured out-of-bounds position. Size is submitted only for opening or a measured size outside the current bounds. A valid user drag/resize is observed and retained rather than being overwritten every frame. Work-area shrink, negative secondary origins, owner moves and removed-owner fallback are handled by the same policy. Measurements are captured after Begin, so dragging outside the work rectangle can require the next frame's correction.

## Covered modal presentations

Sixteen existing modal titles/variants use this helper: the three project-file phases, project history, package path/export, import, bookmark coordinates, membership, expanded expression, noise-edit resolution, Find's draft guard, and five resource browser placement/selection/action/create/delete dialogs. Owners follow the related Resources/Properties/Visualizers/Find window; project-file decisions deliberately use the main viewport. The helper constructors remain independent of a native context.

Former AlwaysAutoResize modal presentations now use bounded, resizable initial geometry. Existing NoSavedSettings and other flags are retained. Dear ImGui's ordinary vertical scrolling handles content taller than the bounded window; Apply/Cancel and controller transitions keep their existing lifetimes. False BeginPopupModal calls consume next-window settings in the pinned API and clear the helper's measurements, so inactive dialogs do not leak constraints into a later window. See the [pinned binding declarations](https://github.com/SpaiR/imgui-java/blob/v1.89.0/imgui-binding/src/main/java/imgui/ImGui.java) and [native popup behavior](https://github.com/ocornut/imgui/blob/v1.89/imgui.cpp).

Shared action helpers measure the next label and move it to another row when horizontal room is insufficient. A button's hit rectangle is capped to available content width; an overwide label has a full-label hover tooltip. This keeps Cancel/Apply targets inside the content width, although an unusually long label can be clipped. Project paths use available width after reserving their label. Noise diagnostics, package errors and export children fill available width instead of imposing fixed 580/720-unit panels. Project-file/history prompts wrap. Existing diagnostics/list clipping and private text buffers remain owned by their original editors.

No controller decision, filesystem writer, project transaction, UUID reference, validation/stale ownership rule or save policy changes. Bounds and hosting observations do not publish private Properties values or change User Config, project dirty state, history, engine identity or profiler state. Resource/bookmark selectors have a separate [anchored layout follow-up](SELECTOR_LAYOUT.md). The Curve Editor has a separate [floating/body/footer layout follow-up](CURVE_LAYOUT.md). Other context popups, arbitrary utility windows and top-level scale settings keep their existing behavior.

## Deferred verification definitions

Fifteen `DialogBoundsTest` definitions provide analytical centered/negative/oversized/tiny/minimum-size vectors; stable user drag/resize; outside recovery; same-area owner changes; work shrink/origin movement; lifetime reset; invalid/nonfinite shapes and finite extreme arithmetic; independent signed host IDs; explicit/context-frame cache clearing; and project/preference/history separation.

`DialogLayoutProbe` defines actual ImGui project-draft and path dialogs at 480 x 320 and 360 x 240 with global scale 2.5, same-kind reopening at 720 x 480/scale 1.25, and a real import preview at 360 x 240 with an intentionally removed host ID. It measures native window bounds, uses native wheel input to reveal Cancel, types a full controlled path without saving, and clicks the production Cancel controls. It retains a private resource ID/raw seed/project/history and checks that Cancel did not create the project file. The independent Python definition recomputes work-area containment and checks the recorded cases/status. Future Linux/Windows workflow and artifact definitions preserve development trigger exclusions. None has run.

The scenario has an isolated ImGui context, no renderer and no OS-detached platform windows. Its report explicitly marks physical detached-window and DPI verification false. It does not exercise every covered modal, every child-scroll interaction, mouse drag/resize timing, maximum compounded scale, OS work-area changes or physical monitor removal. Tiny work rectangles smaller than native title bars/controls cannot promise full native containment. Per-monitor DPI/fonts, independent dialog scales, other selector/context-popup clamping, physical detached-host/monitor recovery and full GUI/Windows 11 acceptance remain pending.
