## Presentation and exact values

ScalarDisplay centralizes presentation without parsing its result back into a value. Normal scalar labels use at most five fractional places and trim trailing fractional zeros. Nonzero magnitudes below 1e-5 and magnitudes at least 1e7 use scientific notation with at most five fractional mantissa places. Tiny nonzero values no longer appear as ordinary zero; large scalar labels remain bounded. Signed zero and explicit NaN/Infinity feedback are retained. Java readouts use Locale.ROOT. Whole signed voxel-coordinate digits remain visible throughout the signed-int range, with up to five fractional places; they are not shortened to an indistinguishable scientific coordinate.

UiFields, ViewportFields and application creation-default scalar sliders use the same fixed/scientific choice. Integer slider formats and signed-long editors remain unchanged. NoRoundToFormat and NoInput remain enabled: slider display text cannot quantize publication or activate rounded native temporary text editing. Adjacent double input retains %.17g, and raw creation-default text keeps its existing complete ledger. Suggestions, validation, exact editing, source ownership, curve gesture history, private Apply, model/schema and engine arithmetic are unchanged.

Viewport scalar sliders also now match the shared property's non-finite presentation boundary. A non-finite incoming value supplies only a finite disabled-widget placeholder labelled Invalid; the original value still reaches the exact input for repair. Drawing never publishes the placeholder. This does not add a general raw numeric input ledger or change the existing finite-only viewport setter rule.

Inherited World numeric labels and curve cursor/locked-endpoint readouts use compact scalar labels with full round-trip value tooltips. Shared scalar sliders expose full values and their range guidance on hover. Preview sampling keeps a one-line compact status and a separate full coordinate/raw/display tooltip, retaining its existing fixed layout height. Full details follow the accepted last observation, are replaced on a new sample, clear with preview reset/publication, and are retained when no new slice sample occurs. The original four-argument ViewportSampleStatus entry point remains available. Sampling, images, meshes, textures, camera/picking and project/preferences values are not changed by formatting.
