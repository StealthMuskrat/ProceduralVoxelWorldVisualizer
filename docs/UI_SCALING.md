# Top-level UI scale targets and private editing

Status: implemented on `codex/development-phase`, **uncompiled and untested** under the owner testing pause. No build, regression, native probe, schema validator, independent replay or GitHub workflow has run for this batch. Historical baseline evidence and acceptance counts are unchanged.

## Shared window targets

`UiScalePreferences.WINDOWS` and generated `registries/ui-scale-targets.json` define nineteen supported top-level targets: Resources, Properties, Visualizers, Find, Logs, Validation, Help, Notifications, Profiler, Themes, the four Settings pages, About, Check for Updates, Voxel Manager, Voxel Inspector and Curve Editor. Logs and Validation are logical keys for the visible Logs & Error Center and Validation Results titles. Existing Resources/Properties/Visualizers keys retain their meaning.

A shared native `UiScale.window` operation applies the selected font multiplier immediately after Begin, including a collapsed Begin, before the window's content is processed. It runs between Begin/End rather than changing another window's scale. Production owned curves use their editor preferences; a standalone curve helper without an EditorState uses multiplier 1. The update-result panel obtains the same preference owner as its request session. The original catalog left children, menus and private popups with pinned native inheritance; the DPI follow-up adds explicit nested scope inheritance. Independent popup/dialog targets are not added by this catalog.

Composition preserves the existing multiplicative policy: global scale times the window multiplier. An absent entry uses multiplier 1; for example, global 1.25 and Logs multiplier 1.5 produce effective text scale 1.875. Both individual controls accept 0.5–2.5, so their product can be outside that individual range. An explicit entry of 1 and an absent entry have the same font result but distinct persistence/ownership intent. The panel calls these values multipliers to make the composition visible.

Font scale is not a new procedural or model value. It does not regenerate previews, replace the engine, dirty a project, create history, apply a Properties draft or start profiling/network activity. The original global IO font scale is set by Desktop each frame; the separate [DPI/font-density follow-up](UI_DPI_AND_FONT_DENSITY.md) now composes transient display density before native NewFrame. Window multipliers remain window-specific. Dear ImGui may use the preceding window scale for portions of Begin such as title-bar layout before the current setter; actual frame/layout/DPI behavior still needs native acceptance.

## Appearance editor

The Appearance category replaces three immediate per-window sliders with `UiScalePanel`: a global slider plus exact decimal input, a searchable target list, an explicit Use a window multiplier toggle and a selected-window slider/input. All nineteen private fields are retained when selection/filter/category changes or Settings is hidden/collapsed. The [Appearance layout follow-up](APPEARANCE_SETTINGS_LAYOUT.md) wraps labels, stacks numeric widgets when measured widths do not fit, places three scale actions in a persistent footer and adds hidden-error reveal. Theme and ordinary-save controls share the scrolling body. Complete high-scale/small-window layout acceptance is not claimed.

`UiScaleEditSession` owns the global raw string, all known-window raw strings and enabled-entry flags. Each field has a 128 UTF-16-unit bound, with sufficient native UTF-8 buffer capacity. Decimal/scientific notation is accepted; blank/intermediate signs, whitespace, NaN/infinity, hexadecimal and suffix syntax do not become a previous valid candidate. Finite double parsing checks the requested 0.5–2.5 range before conversion to the existing float preference. Opening/canonicalizing uses Float.toString ratios, without percent multiplication/division drift.

Feedback caches one immutable complete candidate/problem map for unchanged text/flags. Invalid enabled fields continue to block Apply when another window is selected or the search filter hides their row. Disabling a window multiplier explicitly requests inheritance and removes that entry on successful Apply; its raw private text is retained until save/revert so reenabling can still reveal a correction. Apply checks the complete native displayed text/flags and the current global/all known-window active values, including entry presence. A changed active base requires explicit Revert; private input is retained.

Pending scale text is excluded from periodic saves and Save Preferences. Apply merges only global/known target entries into the latest User Config snapshot, validates and persists through the existing forced-content/required-atomic writer, then publishes active scales. Failed saves retain active/native values, raw input and candidate for retry, with bounded `UI_SCALE_SAVE_FAILED` details in the shared Error Center. Unchanged Apply does no file I/O; reentrant Apply/edit/Revert during save is refused. Successful save canonicalizes the draft, with the next Desktop frame using new scales.

Historical or extension window keys outside the catalog are retained and merged from the latest active map; this editor neither changes nor exposes them. All stored map values, including those retained keys, must still be finite numeric scales in range. The strict reader, Java validation and structural schema now enforce global/map ranges and reject null or string values before binding. Format version remains 1; absent historical scale maps/global fields keep defaults. The contract generator reflects the editor catalog/ranges without adding editor/native dependencies to the engine-only consumer.

## Window lifetimes

Logs, Notifications, Validation, Find, Voxel Manager, Help and About now respect Begin visibility/window-X before drawing their controls. Find still services a pending navigation-decision modal outside its collapsed/closed main content, retaining private-draft decision ownership. Existing Profiler, Themes, Settings, Curve Editor, Inspector, Resources/Properties and update-window lifetime handling remains in place. Scaling is assigned independently of content visibility so reopening does not retain a previous unrelated multiplier.

## Deferred definitions and limits

Thirteen `UiScaleEditSessionTest` definitions cover catalog uniqueness/inheritance, immutable subsets and explicit entry presence, raw/range/nonfinite rejection, cached feedback/bounds, hidden invalid fields and explicit removal, exact complete display evidence, failed-save retry/latest unrelated and extension-key merging, every known active owner, ordinary-save exclusion, float-ratio bit preservation, strict stored types/ranges, reentrant writes and project/engine invariance.

`UiScaleProbe` defines real text/mouse input on the production scale editor: hidden invalid Help input while editing Logs, disabled Apply, periodic-save exclusion, filter/hidden/collapsed retention, stale-base Revert, occupied-directory failure/retry, canonical strings, explicit inheritance and latest unrelated/extension preferences. It retains a private resource ID/raw seed/project/history. It then measures native font sizes for all nineteen catalog keys through isolated helper windows against a default-font baseline. Those helper windows exercise composition, not every actual production panel. Its report explicitly marks full production-window coverage and physical DPI verification false.

`scripts/verify_ui_scales.py` independently checks persisted values, inheritance/removal, known/unknown merging, baseline times global times multiplier metrics, registry membership, schema/shortcut validity and temporary cleanup. New positive/negative fixtures and future Linux/Windows workflow/artifact definitions retain the development trigger exclusions. None has run.

This original batch applies the existing font/window multiplier mechanism; the [DPI follow-up](UI_DPI_AND_FONT_DENSITY.md) adds a fixed denser atlas, runtime density composition and nested scope inheritance. The original batch does not add atlas rebuilding/oversampling, per-monitor font DPI adaptation, independent spacing/style scaling, fixed status/menu-bar reflow, arbitrary popup work-area clamping or detached-window recovery. Full production window gestures, maximum-product scale recovery, physical displays/mixed DPI, Windows 11 hardware and complete A32 acceptance remain pending.

The unvalidated [preference decision follow-up](PREFERENCE_DECISIONS.md) adds per-owner footer scopes and Revert/Escape priority to the retained scale form. Known active scale changes invalidate predecessor activation, while private text and unrelated appearance/extension values retain their existing owners. Failed writes keep raw retry state. New native magnification/ownership definitions remain deferred.
