# Native text history belongs to one opening

Status: **uncompiled and untested** under the owner's testing pause. W01-C09 addresses native input lifetime in 3.5.3, with Expanded Expression and F2 rename entry points. The last observed baseline remains 922 tests / 120 suites; no acceptance gate advances.

The source audit found that Expanded Expression scoped its footer to a per-dialog UUID but kept the same multiline widget ID across openings. F2 scoped its input only to the resource UUID. A new Java buffer or cleared provisional text does not itself establish a new native input identity. If a user edits, undoes back to the original text, closes, and reopens with identical text, the native Redo stack can still describe the discarded opening.

This is a source-derived lifetime risk, not an observed native execution result. The pinned [imgui-java v1.89.0 include tree](https://github.com/SpaiR/imgui-java/tree/v1.89.0/include) points at Dear ImGui commit 1d8e48c161370c37628c4f37f3f87cb19fbcb723. Its [InputText implementation](https://github.com/ocornut/imgui/blob/1d8e48c161370c37628c4f37f3f87cb19fbcb723/imgui_widgets.cpp) retains cursor/selection/Undo state when widget identity, input specifications and text match. Reusing that identity therefore conflicts with the application's discard-on-close boundary.

Expanded Expression now scopes only the multiline widget to its existing opening UUID. F2 gets a fresh transient input scope on each admitted beginRename request. These scopes do not change resource UUIDs or visible IDs. They remain stable during editing, scrolling, feedback selection and reflow within an opening; a successor starts with a different native identity, even for the same resource and text. Window/INI/scroll-child identities and existing explicit staging/commit behavior retain their owners. There is no custom replacement for native text Undo/Redo.

ExpressionLayoutProbe now keeps one actual opening across its six layout/scale cases, rather than asserting equal widget IDs across six different openings. It adds five native lifetime cases: Cancel, Escape, dialog close, external session cancellation and Use Text. Each appends text, uses native Undo/Redo within the opening, returns to the source with Redo available, closes, then verifies that successor Undo/Redo cannot resurrect it. Ten distinct text IDs/opening scopes are recorded. The Use Text case stages an equal-value expression once through a separate local callback; the original workflow's three callback expectations remain unchanged. Its independent reader verifies scope/ID separation and exact source/restored text beside the existing unchanged committed formula and Unicode range checks.

VoxelIdentityProbe adds Escape and unchanged-Enter rename lifetimes. Each exercises native Undo/Redo within one F2 opening and verifies a fresh successor ID/history for the same voxel UUID and visible ID. Its separate rename-native-history report records four distinct text IDs; rename-history-after must equal the full existing inline-redone project. The original six layouts, 2,051 dependents, preference comparisons, three long-ID cases and 24 whole-project readbacks remain.

These are native behavior definitions, not mirror-only unit assertions. Existing session, selection, pane lifetime and explicit publication suites remain applicable. None of them ran. Source inspection and Git whitespace/content/metadata checks are the available verification. No headless API, authored format, registry, engine arithmetic or persistent preference changes are introduced.
