Status: development source on main, **uncompiled and untested** under the owner's testing pause. This extends [archive writer recovery](ARCHIVE_WRITER_RECOVERY.md) for 14.3.5–14.3.9/14.4 and A21/A22. ## Preserve primary failures and finish cleanup attempts

Writer cleanup previously caught only IOException. A RuntimeException or Error while closing after initialization failure could replace the original failure and skip temporary-file removal. Unchecked rollback failure also replaced the original write IOException; explicit abort could skip deletion after unchecked close failure. Reader initialization similarly called close before preserving its parse error, allowing cleanup to hide the reason an archive was rejected. Finally, Reader marked itself closed before handle close but never attempted that handle again if close failed.

Writer constructor cleanup now attempts temporary-file deletion even when handle close fails unchecked. The initialization failure remains primary, with distinct close/deletion faults suppressed in encounter order. Rollback failure of any thrown kind preserves the original write IOException and leaves the writer non-publishable. Explicit close always attempts both handle close and temporary deletion, retains the first fault's IOException/RuntimeException/Error type and suppresses later distinct cleanup failures. An unexpected checked cleanup throwable is wrapped in IOException. A later close retries any handle/deletion cleanup not confirmed successful. Successful publication remains terminal and its subsequent close remains a no-op; cleanup never removes the destination.

Reader initialization preserves its original IOException even when close reports a checked or unchecked failure. Non-IO parse failures retain the existing IOException("Malformed archive", cause) policy; cleanup details attach to that wrapper without changing the original cause's suppressed list. A cleanup throwable identical to the primary or its already visible cause is not added again. Failed construction makes one best-effort handle-close attempt; no Reader is returned for later cleanup retry.

Reader close now separates logical read retirement from confirmed handle cleanup. Reads, including unarchived-position queries through read(), reject immediately after the first close attempt. If handle close throws, another close attempts it again; after successful close, subsequent closes are idempotent. Version/dictionary/coverage inspection remains available and immutable, and completed VoxelChunks remain independent. This is an opportunity to retry cleanup, not a guarantee that an OS or a failing file implementation can recover. The calls retain their existing synchronized reader and single-caller writer ownership.

The production reader still opens a read-only RandomAccessFile. A package-private transferred-handle constructor enables deterministic module-level faults without a public injection API, mutable global hook or alternate production codec. Writer faults reuse the existing ArchiveOutput boundary. Public factory/method signatures, normal parsing/decoding, dictionary/remapping rules, resource limits, archive versions 1/2, compressed bytes, EMPTY coverage, sorted index are unchanged. The later unvalidated [atomic publication follow-up](ARCHIVE_ATOMIC_PUBLICATION.md) supersedes the earlier atomic-move preference/fallback: publication now requires atomic replacement while cleanup/retry ownership remains authoritative. No schema, registry, project/editor/preference format or dependency changes. No stronger filesystem crash/durability or VM recovery guarantee is asserted.
