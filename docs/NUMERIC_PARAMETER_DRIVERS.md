# Numeric placement parameter drivers

Layer defaults and placement overrides now include an ordered `parameterDrivers` list. Each row maps a primary or explicitly referenced scalar field into one of eleven documented destinations: `threshold`, `baseHeight`, `heightScale`, `strength`, `probability`, `scaleX/Y/Z` or `offsetX/Y/Z`. The entire list inherits live by property presence; an explicit empty override disables the inherited list, and Reset to Layer Default removes that override. Editing, reordering and removing rows stays provisional until Apply commits one transaction.

A NumericDriver extends the existing FieldDriver authoring shape with `destination` and `combination`. It retains enabled, optional noiseGeneratorUuid, inputMin/inputMax, outputMin/outputMax and LINEAR/SMOOTHSTEP mapping. A null source uses the already sampled primary value. Explicit resources use their own 2D/3D dimension and the placement's signed axes and ordered sampling transforms. The primary field's column cache does not cache a separate Y-dependent driver. FieldDriver now permits the canonical NumericDriver subtype; probability/strength settings retain their base FieldDriver shape and existing semantics.

## Exact execution contract

After effective Y clipping, rows execute in three fixed phases. Each phase preserves authored order, including repeated destinations; authored interleaving does not move a row across phase boundaries. SAMPLING scale/offset rows require an explicit field and all sample the original resolved placement coordinates, including original signed axes, scales, offsets and ordered transforms. They update component constants without feeding changed coordinates back into other sampling rows. The final controls then resample the primary and all later referenced fields through the same placement transform program. INTERPRETATION rows run after primary sampling, before interpretation/type selection. ACCEPTANCE strength/probability rows run only after interpretation and type interval selection pass, before the existing mapped probability/strength factors, gates, predicates and deterministic probability decision. Threshold rows apply only to DENSITY/SELECTION. Base-height and height-scale rows apply only to HEIGHT_BELOW/HEIGHT_ABOVE/HEIGHT_BOUNDARY. Disabled and irrelevant rows are not sampled and do not appear in executed trace reports. Rows still require valid finite structural settings and resolvable authored references, including disabled rows.

The current value begins with the resolved constant setting. Each row computes its mapped scalar and then applies:

| Combination | Result |
|---|---|
| REPLACE | mapped |
| ADD | current + mapped |
| MULTIPLY | current × mapped |

Repeated destinations are allowed and ordering matters: starting from 1, ADD 2 then MULTIPLY 3 gives 9; reversing those rows gives 5. There is no reassociation or implicit clamp after combination. A nonfinite intermediate fails that executing row even if a later replacement could hide it. The failure identifies the placement, world XYZ and zero-based authored row. Failed/cancelled generation never publishes a partial chunk.

Inputs clamp at the declared endpoints. Input minimum must be strictly below maximum. Interior LINEAR uses normalized t; SMOOTHSTEP uses t²(3−2t). Numeric outputs can be any finite signed endpoints, including descending or equal endpoints. Interpolation avoids overflowing opposite large endpoint spans, returns exact declared output endpoints for clamped inputs, and bounds rounding to the convex output interval. Constant endpoints return that constant. REPLACE/ADD/MULTIPLY then operate in ordinary ordered double arithmetic and require a finite result. Every strength/probability numeric-row intermediate must remain in [0,1]; signed mapped endpoints remain allowed (for example ADD -0.5 to strength 1). Invalid intermediates fail immediately even if a later replacement would hide them. The older probability/strength FieldDriver factors retain their [0,1] mapping and multiplication order, multiplying the constants resolved by the new acceptance rows.

Height interpretation uses the resulting baseHeight + primary × heightScale, then the existing FLOOR/CEIL/ROUND policy. Density/selection uses primary >= the resulting threshold, including exact ties. Sampling rows change final field query coordinates, including primary/type-interval/gate/factor fields, while their own source queries stay at the fixed baseline. Changes to sampling scale/offset precede the existing authored transform list; they do not edit transform rows or resource definitions. Acceptance rows change probability/strength constants. Seeds, Y clipping, type identities, gate thresholds and arbitrary reflective destinations remain outside the whitelist. A placement with any enabled sampling driver bypasses primary column prefetch, preserving Y-dependent and failure/laziness behavior; other placements retain the existing fast path.

## Traces, persistence and resources

`GenerationTrace.Details.parameters()` is an immutable list of ParameterEvaluation records: authored row, destination, combination, optional noiseUuid, sample, mapped, previous/effective values, phase and the actual driver query coordinates. The old eight-argument ParameterEvaluation constructor remains available with INTERPRETATION phase and absent coordinates; record-pattern/reflection clients must migrate for its added components. Inapplicable/unreached rows are omitted, and row numbers retain their authored positions. The inspector displays these reports alongside probability/strength and inherited constant settings. Existing seven- and eleven-argument Details constructors remain available with empty parameter reports; record-pattern/reflection clients must account for the added component.

Project JSON stays format 2. parameterDrivers is optional and defaults to an empty list when reading historical projects. Each row's structural schema, destination/combination vocabularies and the 32-row limit are published in the schema and world-operation registry v4, including explicit phase, unit-range and source requirements. References participate in dependency closure, portable copy/remap, replacement, deletion and undo just like other settings references. Compilation freezes the resolved list; subsequent authoring changes do not mutate existing compiled worlds or snapshots.

`Example.parameterDriversDemo()` and `fixtures/parameter-drivers.json` provide an engine-only height example driven by an explicit 3D X field followed by an ADD row. The independent consumer checks exact y <= x+1 results, JSON roundtrip and trace values. Normal startup still creates no resources.

## Validation scope

Tests cover independent mapping expectations, extreme spans, descending/constant outputs, whitelist/range/ref/row-count rejection, atomic inheritance, ordered repeated destinations, exact threshold ties, height rounding, explicit 2D/3D and transformed Y sampling, cache safety, unused/disabled/out-of-Y laziness, overflow without publication, stage snapshots, frozen compiled settings, worker/root/trace invariance and resource import/replacement/undo. Native smoke adds the actual ordered numeric controls using a saved valid demonstration project. Per-driver column optimization, arbitrary transform-row destinations, representative hardware performance and full interactive Tree 10 acceptance remain outside this extension. The phased extension adds explicit sampling/acceptance destinations, phase-aware traces, schema source requirements and native private editing. Its validation is run after implementation.
