## File Location decides before replacing the destination

ResourceExportWriter previously replaced the package from its queued UI delivery before File Location processed the current Cancel/Escape controls. It now stores successful staging or a captured preparation failure in its existing closeable CPU mailbox. Delivery only marks readiness: phase RUNNING, the request token, original destination bytes and the reviewed export session remain stable. It neither replaces the file nor reports a captured preparation failure.

ResourcePackageDialog captures the shown opening and original export request before drawing. After the native popup scope ends, it handles current controls with Cancel/Escape precedence, then accepts only the same shown request. Newly submitted inline work waits for a later draw that owns the new request. An unavailable popup does not publish staging on behalf of absent controls. The existing explicit Export action finishes without another confirmation after its Included review; successful replacement consumes that session once and closes only its current file opening.

Acceptance requires the exact submitted/displayed raw path text, including Unicode, spaces and equivalent but differently spelled paths. It repeats original session/preview/selection, opening/context, document lifetime/project/revision, saved path/dirty baseline, full committed values, selected UUID/siblings, private draft identity/values and raw seed ownership. Successful publication repeats blockers and ownership after external gates and presentation callbacks. A callback that cancels and stages a ready successor cannot authorize that successor from old work, consume its mailbox or dispose its staging. The export session still repeats exact reviewed-source validation before publication, and ResourcePackageFiles.Prepared still protects the latest active-project path immediately before atomic replacement.

Ready success, captured I/O/fatal/null-result failure and preparation cancellation may be cancelled before replacement or primary failure reporting. Cancel closes ready unpublished staging through the existing owned mailbox and preserves the prior destination. Failure payloads own no temporary file after the preparer cleans up. Accepted failures retain the exact reviewed session and path for explicit restaging; no draw retries automatically. A changed source still requires Reload and another Included display. Changed displayed path/opening retires old staging. A Save As established after readiness cannot be overwritten by the package.

The writer keeps observing its FutureTask through readiness. Inline delivery followed by a handoff fault therefore cannot silently publish an unaccepted result. Scheduler rejection, external Future cancellation and handoff faults retain their existing refresh/failure policy. A caller that explicitly consumes a result before a later external fault retains the existing completed-publication boundary; replacement is not rolled back afterward.

Cancellation, staleness, retry and close invalidate the closeable mailbox independently of draining callbacks. Retired workers close their rejected staging and suppress delivery, including captured failures. Queued callbacks now hold identifiers rather than staging or captured failure payloads. Failed deletion remains separate bounded cleanup feedback; a provider that refuses deletion can retain an unpublished sibling. Already published staging transfers ownership and close performs no filesystem operation. Reentrant final publication retains the existing publishing/close-request fence, with no ordinary-move fallback after unsupported atomic replacement.

Export does not apply private Properties, alter project/history/preferences, save the project or change generated noise/voxel values. Initial export catalog/selection/Reload planning retains its separate completion policy. Synchronous direct package/dialog writing remains synchronous; direct asynchronous writer owners explicitly accept delivered staging.
