# Bounded editor callback delivery

Status: **uncompiled and untested** under the owner's testing pause. W01-C11 addresses the editor handoff gap in 1.2.6/1.4.1, with the frame responsiveness audit in Tree 4. The last observed baseline remains 922 tests / 120 suites; no acceptance gate advances.

EditorState previously retained an unbounded ConcurrentLinkedQueue and drained until empty before drawing. A callback could continually post more callbacks in that same drain, and an exception from one callback escaped before the remaining delivery/status work. This was a source-confirmed queue/fairness/failure boundary gap; no callback-storm or native timing measurement has run.

UiDispatchQueue now admits at most 256 pending callbacks. Each owner-thread drain reserves an initial FIFO batch of at most 32; newly posted callbacks wait for a later drain even when the current batch was shorter. Up to one reserved batch can coexist with the pending queue. Recursive drains cannot bypass the boundary, and EditorState guards the complete drain/validation/status turn against reentry. These are internal engineering bounds, not measured frame-time guarantees or user settings. A single arbitrary callback can still take time; this change does not make blocking callback code safe or undo its side effects.

EditorState.postUi is the strict nonblocking producer API. Full or closed posting throws RejectedExecutionException into the existing worker/future observation path. Accepted callbacks are never evicted to make room. The exposed editor-only uiQueue field now has the Queue<Runnable> type; ordinary offer still returns false on full/closed, and readback/probe polling remains possible. Production adapters use postUi so rejection cannot silently lose their completion signal. No headless engine API changes.

A thrown callback is reported through bounded EDITOR_UI_CALLBACK_FAILED diagnostics without preventing healthy callbacks in its admitted batch. A failing diagnostic sink cannot strand that batch. Existing request identities, candidate validation, controls-before-acceptance and explicit transaction/file boundaries retain publication authority. Queue admission/delivery itself grants none. Shutdown closes posting and discards pending delivery before background teardown; closure during a callback also skips the rest of its reserved batch. Controller-owned staged resources retain their existing cancellation/cleanup rules.
