# Slice navigation and accepted image geometry

Orthogonal slices use their declared plane axes: X shows Y/Z, Y shows X/Z, and Z shows X/Y. Slice sampling uses the requested plane-local centers, fixed coordinate, extent and spacing regardless of the fixed-bounds toggle. In particular, X/Z image motion along world Y uses its requested pan center rather than an unrelated orbit/free-fly camera position.

Left and middle presses own a slice pan. The gesture retains its original navigation and image dimensions, uses total normalized displacement after a three-pixel threshold, and continues beyond the image while that viewport retains focus. Release includes its final displacement. Escape restores the original request and prevents the held gesture from resuming. Focus loss, popups, tabs, mode/source changes and externally changed requests cancel ownership while keeping the latest valid request. Foreign held buttons are never adopted. Image item ownership prevents slice drags from moving the surrounding window.

Wheel zoom keeps the requested procedural point under the pointer fixed, using the current requested extent rather than the 2D tab's fixed 256-sample extent. Spacing saturates at 0.0001..10000; zero/clamped gestures do not dirty the preview. Held buttons suppress wheel navigation. Pan/zoom validate finite results before changing the request. Plane/fixed-coordinate/extent changes supersede an older held gesture.

Every accepted slice carries immutable plane, fixed coordinate, origin, extent, spacing and sampling program alongside its pixels. Hover and bookmark coordinates use that accepted geometry and sampler while edits or manual regeneration leave the previous image visible. They never combine an old image with a newly requested extent, plane or spacing. Hover evaluates the canonical procedural field at the continuous pointer coordinate; it is not a GPU-filtered pixel readback. The displayed-image label identifies its actual plane, coordinate, extent and spacing. Navigation follows requested controls; hover/bookmarks follow the displayed image.

A short left click captures an inspectable 3D bookmark coordinate; a drag or canceled/foreign release cannot replace it. Right-click retains existing context actions. Navigation and coordinate selection do not alter authored project data or Undo history. No engine API, generation semantics, schema or archive changes are introduced. Native image/key/focus fixtures and independent affine expectations provide scoped evidence; physical OS input/focus, DPI, full GUI and Windows 11 hardware acceptance remain separate.
