# Diagnostic workspaces and displayed-result ownership

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This extends [diagnostics/recovery](DIAGNOSTICS_AND_RECOVERY.md) and [measured action rows](PROFILER_LAYOUT.md). It adds no passing evidence; the validated baseline remains 922 tests / 120 suites.

Logs & Error Center, Notifications and Validation Results now use a scrolling body and persistent measured recovery actions. Log search/severity/subsystem labels wrap above available-width controls. Result/detail panes sit alongside one another when two measured minimum widths fit, and stack when they do not. Stacked results use at most four measured text rows; each pane retains its own scrolling viewport, and the outer body can scroll when headings/minimum pane heights exceed the visible space. Fixed 100-pixel list minima and percentage-only list sizing were removed. The body/footer can fit ordinary narrow/short clients without claiming that clients smaller than their action rows can show every action.

Logs keeps Copy Details, Go To Problem/Open Project Settings and Show Selected outside its body. Search can hide the selected event without changing the selected ID or silently substituting another event's detail/actions. That state is explicitly labelled. Show Selected clears the three filters and requests result-list/body scrolling to the same retained ID. An evicted selection has no actions and explains that its details are no longer retained. Notifications shares the selected event ID and provides two persistent rows: Mark All Read, View Selected in Logs, Copy Details, source navigation, Mark Read and Mark Action Resolved/Dismiss Notification. Resolving an action and dismissing a notification remain separate explicit activations. Dismissed entries stay in historical Logs.

Event rows use stable hidden event IDs, bounded single-line text and measured whole-pixel clipped strides, including a tail item for native rounding. Full retained message/source details wrap in the selected pane. Shared retained traces still use the same `TracePanel`, source guard and frozen payload. This batch changes its containing viewport, not the trace's internal fixed-height lists, paging or freshness rules. More complete trace reflow remains pending.

`EditorEvents.View` is one immutable newest-first entry list and matching Counts object. The store reuses it until an actual publication, eviction or read/action/dismiss change. No-op state requests do not allocate replacement entries or invalidate it. Logs and Notifications keep separate `EventProjection` caches keyed by exact View identity and normalized query/severity/subsystem/notification mode. Idle redraw, resize and unchanged filters reuse the immutable projection. Real changes still invalidate it immediately; workers keep the same synchronized bounded grouped store. Historical snapshot/search/count signatures remain available.

New displayed-entry overloads for Mark Read, Resolve and Dismiss accept only the exact retained Entry object shown to the user. A repeated occurrence with the same group ID, an intervening state change, eviction or an equal-valued entry from another store rejects the older acknowledgement. This also holds when the clock timestamp has not changed. The panel retains selection and explains that the event changed before acknowledging it. Reading does not resolve an action. Mark All Read uses the displayed View: unchanged reviewed occurrences become read, while new or changed occurrences remain unread. It does not resolve required actions. Existing ID-based service methods retain their original semantics for callers that deliberately address the latest group state.

Copy Details uses the exact entry whose detail was drawn. The production callback remains `ImGui.setClipboardText`; a package-local fixture callback allows exact payload verification without claiming operating-system clipboard integration. Event source navigation conditionally marks that same displayed entry read before invoking the existing host callback, and still checks current project/draft target availability. The desktop continues routing settings links to the retained Project Settings panel and other source links through its draft guard.

Validation selection now belongs to an exact immutable result publication, EditorState, document lifetime token, project object/UUID, revision and scope. New result-list identity, changed scope/revision/lifetime or detected in-place list-value mutation clears the selection instead of carrying an old row index into a new result. No first issue is automatically substituted. The native row-ID scope changes with the publication, so a held gesture cannot activate a replacement issue at the same index. Resizing keeps an unchanged publication and selection. Supported target resolution uses the selected captured Diagnostic and owning project UUID; source availability still uses existing UUID/control checks. Unsupported metadata remains copyable without an invented control destination.

Validate Committed Project, Copy Details and source navigation remain persistent. Explicit validation reads the committed document, replaces the result publication, clears selection and leaves private Properties/settings text and project/history untouched. Empty results identify their current scope and absence of issues. Candidate validation details are never relabelled as committed-document success through an automatic row selection. No persisted format, schema, engine API or deterministic generation behavior changes.

Seven deferred `EventViewTest` definitions cover immutable cached history/counts, repeated-occurrence rejection, reviewed-only bulk reads, eviction/foreign-entry rejection, no-op/state independence, normalized projection reuse and composed historical/notification filters. Five `ValidationSelectionTest` definitions cover exact target/private state, equal-valued list replacement, in-place reorder, same-UUID New/lifetime/scope/revision changes, foreign editors and unsupported indices. All twelve definitions remain unexecuted.

`DiagnosticsLayoutProbe` defines eighteen production form/size cases across six wide/narrow/short/user-scale combinations, including the 6.25 global/window font product. It defines actual mouse/text filtering, hidden-selection retention/Show Selected, measured clipping and persistent row geometry, stable event/publication IDs, exact Copy callback payloads, source/log callback routing, Mark All Read without resolution, explicit resolve/dismiss/repeat recovery, equal-valued validation replacement clearing selection, and real committed-project validation preserving project/history/private Properties/preferences/engine ownership. Its explicit results-reveal hook scrolls the production body to measure result rows; it does not simulate every wheel/keyboard scroll path. Source callbacks record exact targets, with the existing separate navigation probes responsible for modal/draft-guard gestures.

`scripts/verify_diagnostics_layout.py` independently checks pane ordering, clipping budgets, persistent action rows, stable selected IDs, recomputed retained/unread/action counts, repeated group state and project-scoped source identities. Future Linux/Windows commands and artifacts are recorded with workflow triggers unchanged. No compilation, JUnit, native probe, verifier, generator, build or GitHub workflow ran for this batch. Physical clipboard/DPI/detached displays, arbitrary publication stress, full trace reflow, every input/focus/scroll path and complete GUI/Windows 11 acceptance remain pending.
