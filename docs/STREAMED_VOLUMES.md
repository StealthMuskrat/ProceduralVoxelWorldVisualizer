# Camera-relative scalar volume windows

Normal Volume display follows the orbit focus or free-fly camera through an aligned moving texture window. Preview extent rounds up to complete 32-cell chunks, bounded by the configured preview dimension/cell and CPU/GPU limits. Fixed world bounds retains the existing exact analysis extent and explicit center. Camera navigation does not change canonical field semantics or the accepted compiled source identity.

At full detail each cached chunk owns 32³ finite canonical double samples at global cell centers. The unvalidated [display-detail extension](VOLUME_DISPLAY_DETAIL.md) adds spacing-specific coarse tiles under pressure. Complete chunks share an LRU cache capped by Cache MiB, 64 MiB and the space remaining after working-memory admission. Moving one chunk across a populated 64³ window reuses its shared chunks; revisits can reuse the full window. Source changes in Auto mode and explicit Regenerate start a new source generation. Manual mode keeps its immutable accepted project snapshot while travel continues; Regenerate explicitly adopts current committed definitions. Display minimum/maximum, opacity and threshold operate on accepted texture metadata without rebuilding the source or sampling chunks.

A window assembles cached canonical chunks before choosing one finite affine encoding for its complete texture. Internal chunk faces therefore interpolate through one contiguous scalar grid and one encoding, including extreme/tiny fields. This is a bounded moving texture, rather than a sparse GPU atlas. It still builds a complete replacement texture, using the bounded per-frame texture path and active/candidate GPU admission. Compatible resident overlap now copies on the GPU while exposed slabs upload from the CPU; see [GPU overlap reuse](VOLUME_GPU_REUSE.md). The previous framebuffer and accepted origin remain until complete publication. The finite outer window clips visible volume; no outer sampling halo is added. Coarser display sampling is now implemented on the development branch and awaits validation.

CPU admission reserves 12 bytes per actual display sample, one spacing-specific chunk plus entry allowance, and 64 KiB upload staging. Cached tiles consume only the remaining admitted CPU space. One worker per viewport serializes assembly before allocation, so canceled work cannot overlap another full-window allocation. Chunk sampling, assembly and encoding check owned cancellation at row boundaries; an individual field evaluation remains cooperatively cancellable. Old leases, source generations and closed caches cannot publish obsolete windows or tiles. Cancellation parents run outside cache locks.

Queue saturation, numerical failure and budget rejection retain the last accepted display. Streamed windows now share staged pressure observation: effective extent reduction, optional cache release, deferred new sampling and critical pause with explicit Resume Volume. Configured extent and canonical unit sampling remain unchanged. Admission changes can rearm a rejected request; numerical failure retains explicit Regenerate recovery. See [scalar pressure controls](VOLUME_PRESSURE.md). Leaving streaming analysis clears the chunk/program cache; returning creates a new generation. Source removal and viewport closure reclaim owned work/cache/upload state. CPU cache bytes and conservative working reservations join the existing profiler totals. Queued windows reserve their sampling/encoding peak immediately, while a serialized worker and upload staging share one window ownership estimate. Canonical engine/project/archive formats remain unchanged.

Contract and native coverage includes signed floor/domain edges, exact direct/assembled encoding, reuse and eviction, one compiled source, serial cancellation, failures/closure, cache-lock callback isolation, seam-spanning GPU texels and optics, signed XYZ production camera travel, manual source retention, transfer reuse, canceled uploads, GPU/queue rejection/retry and fixed-analysis return. Full physical input/DPI, representative memory/performance measurements, sparse atlas residency, validation of the new coarse volume detail, representative performance and complete GUI/Windows 11 hardware acceptance remain separate.

CPU cache hits and GPU reuse are separate: cached historical chunks can avoid sampling even when their texels are absent from the current GPU resident. GPU reuse intersects only the accepted texture and requires compatible source/encoding identity. Destination-write budgets still cover the entire candidate, and host/copy counters report the transfer split.
