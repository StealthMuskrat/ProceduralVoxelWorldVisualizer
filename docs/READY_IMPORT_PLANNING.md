## Current review controls before replacing rows

Subsequent COPY/REUSE/SKIP choice and Reload planning previously installed its replacement model or reported a captured worker failure during queued UI delivery. ImportEditSession now retains that model/failure in a one-slot CPU mailbox. Delivery only marks readiness: the original request and planning state remain stable, the last completed rows remain visible, desired choices retain their current values, and Import/display acknowledgement remain disabled. Delivery does not install or acknowledge a replacement preview.

ResourceImportPanel captures the review opening and planning request before drawing. Current row choice edits and footer Cancel/Escape, Reload, Retry and page controls run first. After the native popup scope ends, acceptance requires the same opening, session and originally shown request. Newly started inline work waits for a later draw that owns its request. An unavailable popup does not accept a result on behalf of missing controls. Filters and page navigation retain their existing behavior; a current visible review can accept while showing a different review page, but Resources still must display the replacement plan before Import.

Acceptance repeats complete ProjectFileOwner values, current document/reload authority, shown opening/context and blocker checks. It rechecks request and source ownership after presentation callbacks, so callbacks that cancel or prepare a ready successor cannot authorize or retire that successor through old work. The prepared model must still match the committed destination. Raw committed/private/seed/selection changes retire stale work without replacing newer values; a changed destination still requires explicit Reload. No frame starts an automatic retry.

Successful acceptance installs the already computed model and cached plan once and clears shown-plan acknowledgement. Choice forks retain their original COPY allocation; Reload uses its owned current destination snapshot and may allocate new targets. Old rows cannot acknowledge the replacement. Only later visible Resources rows can permit the separate explicit final Import action, which retains its own background validation, one transaction, Undo/Redo and private Properties boundaries. Initial package loading and final Import acceptance remain separate paths.

Ready success, invalid plans and captured planner exceptions may be cancelled before replacement or failure reporting. Accepted exceptions keep the old rows and desired choices, report bounded failure and offer explicit Retry preview. Scheduling, external Future cancellation and handoff faults retain the existing refresh/failure policy. FutureTask observation continues through readiness, so an inline ready callback followed by a handoff fault cannot silently install an unaccepted preview. Retry must obtain and display a new plan; a failure does not restore the old plan's Apply authority.

Supersession, cancellation, stale ownership and retry advance the CPU mailbox epoch and release retained results independently of draining callbacks. Retired workers cannot refill the slot. Queued callbacks hold identifiers rather than computed model/failure payloads. Closing the review closes the mailbox, and successful final Import releases it as part of session shutdown. Non-cooperative planner cancellation retains its prior limits. Synchronous direct sessions retain immediate choice/Reload planning; asynchronous direct owners explicitly accept delivered work.

The headless choice/merge algorithm, package/project/schema/registry formats, generated field/voxel semantics and public engine API are unchanged. No preview acceptance applies Properties, edits project history or saves files/preferences. Owner snapshot capture, full JSON comparisons, choice-map copying and native row projection still have costs; no measured latency, heap or large-package bound is claimed. Other background completion policies and full platform/release acceptance remain outstanding.
