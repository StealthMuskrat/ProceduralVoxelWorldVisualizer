# Complete streaming-chunk workers and reservation settlement

Development implementation on main; **uncompiled and untested** under the owner's testing pause. No compiler, Gradle, JUnit, native probe, schema/Python checker, independent consumer, packaging, real update request or GitHub workflow ran. The observed baseline remains **922 tests / 120 suites**. Native/Windows 11 and final release acceptance remain pending; no A01–A36 gate advances.

## Queued data and meshes remain private until terminal observation

ChunkScene previously settled jobs only by draining their queued Result. A mesh profiling callback or finalization failure outside result preparation could complete the Future exceptionally without queuing any result, leaving active-job count and reserved CPU bytes stranded. Conversely, a queued data/mesh result could be installed before its Future had completed normally.

Each active entry now retains one private prepared result. Frame draining first stages bounded ready receipts, then observes active Futures without reading unfinished work. A normal terminal Future and its matching prepared result are both required before data/mesh installation, generated/mesh counters, CPU ownership and upload versions can advance. A terminal Future failure overrides an unaccepted prepared result or settles the job without any receipt, releasing its active slot and reservation once. Terminal faults cancel the captured token/Future after detaching ownership. Future status/get faults are contained, original execution causes are preserved, and interrupted terminal reads restore interruption.

The original entry object, job ID and Future must still be current after observation. Cancel/travel/eviction, close and newer jobs cannot have their reservations released by obsolete completion. Finish clears the private result, task handle, token and reservation together. Cancellation revokes the job ID and releases owner state before cancelling its captured Future, preserving a replacement created by cancellation callbacks.

Both receipt staging and terminal settlement respect the supplied per-frame completion limit. A completed normal Future whose receipt lies beyond that frame's drain budget waits for a later frame. Private staged results remain bounded by active job admission and retain their existing reservation until settlement. This adds owner-side entry iteration and terminal polling; no measured latency, heap or scheduler bound is claimed beyond these structural limits.

## Submission, failure feedback and accepted displays

Data and mesh submission now contain non-queue Throwable failures as well as ordinary queue rejection. A Future returned by submit is attached only if its original entry/job is still owned; otherwise that returned Future is cancelled. Failed admission cancels the original token and releases its slot/reservation without adopting a result queued during inline execution. Existing queue-rejection, cancellation and pressure-classified rejection policies remain; ordinary failed entries still wait for the existing Regenerate/new-scene recovery. Healthy neighboring work can continue.

Failure detail is bounded to 2,048 UTF-16 units, preserves surrogate boundaries and has a class-name fallback for blank/unreadable messages. Description does not mutate the original Throwable. Entry/job/closure guards after description prevent reporting against work replaced during that callback. Tick stops if draining or inline submission closes the scene, rather than repopulating or admitting into the closed owner.

Failed replacement work retains previously accepted data, mesh/display ownership and CPU accounting. Greedy, point and surface meshing, halo snapshots, LOD choice/signatures, upload acknowledgement, picking, pressure preferences, source semantics, public Config/Source/Upload APIs and immutable chunk contents are unchanged. Project/private/raw/history/preferences, model/schema/project/package formats and deterministic field/voxel mathematics are unchanged. Renderer recovery introduces no editor/native dependency into engine/model/storage.
