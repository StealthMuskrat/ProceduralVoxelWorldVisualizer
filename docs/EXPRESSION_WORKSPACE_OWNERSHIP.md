# Expanded expression workspace ownership

Status: implemented on `codex/development-phase`, uncompiled and untested. GitHub testing remains paused by owner instruction. Earlier expression evidence does not validate these changes.

An expanded expression belongs to its exact EditorState, opening project object/revision/logical UUID, Properties draft, noise UUID/kind, ordered sibling selection and expression item object/UUID. The opening expression parameter node and its presence are retained. Even a same-value replacement node requires reopening; the old workspace does not retarget. Source/selection changes disable Use Text (formerly Use in Properties) with an explanation while keeping private displayed text and Cancel available. Closed sessions return completion before opening/drawing another popup.

Before staging, the session checks complete opening project values as well as its source ownership. Unsupported in-place project mutation permanently makes that session stale until it is cancelled and reopened. The frame-time guard does not serialize the whole project. Source text is checked against the actual displayed string before publication; a rejected oversized edit cannot cause an earlier accepted string to be used. Text remains provisional: incomplete syntax can still be staged into Properties, and only ordinary Properties Apply validates/commits the complete resource. No project save is implicit.

Other private Properties values remain independent. Pending IDs, changed named bindings, shared parameters and raw seed text are retained rather than copied over from the opening. Feedback inspects the current committed project context and current private noise metadata. A cached owned item candidate is converted only when the item's serialized values change; private text edits update just its expression parameter. The candidate never replaces the real draft item. Named-input type/value changes refresh the candidate, while shared-parameter/context changes still reach the existing parser-feedback cache key. The preparation counter measures item conversions, not parser compilations. Item-tree serialization and feedback-key construction still occur on each inspection; no constant-time or hardware-latency claim is made.

Successful staging consumes the session before running the Properties refresh callback. A callback exception records `EXPRESSION_EDIT_REFRESH_FAILED` as an actionable Application error and closes the accepted editor. Further draws cannot repeat staging or refresh. Properties invalidates its noise index in a finally block even if clearing input widgets fails. A second Expand Expression request preserves the existing dialog and its private buffer. Rejected staging keeps the buffer available for correction.

Errors have non-null fallback descriptions and bounded rendered text. The expanded native buffer reserves four bytes per provisional UTF-16 character plus a terminator: 262,145 bytes for the existing 65,536-character provisional bound. The language/staging limit remains 16,384 UTF-16 characters. The byte capacity can hold an oversized ASCII paste above the session character bound; session edits reject it, the displayed text remains available within the native byte capacity, and displayed/session equality prevents publication until corrected. Native byte-capacity overflow behavior, IME composition and physical paste acceptance remain unverified. No language, engine API or project schema changed.
