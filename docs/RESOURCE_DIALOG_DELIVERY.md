# Resource dialog action delivery

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. The validated baseline remains 922 tests / 120 suites. This extends [resource review lifetime](RESOURCE_REVIEW_LIFETIME.md), [Import](IMPORT_WORKSPACE.md) and [package presentation](PACKAGE_LAYOUT.md) for specification 2.8/3.4/3.5 and A07. No acceptance result advances.

Import and package dialogs collect a complete footer decision and immutable path text, then unwind their native child, ID and popup scopes before dispatch. Validation-window callbacks, import validation/publication, export storage and the final action eligibility gate run in the caller window. Availability checks run before popup entry. Import rows additionally balance their child, ID, disabled and combo scopes with finally blocks.

Every successful opening has its own native widget namespace and decision ticket. Body fields, resource rows and footer controls retain IDs during one opening; reopening creates new IDs so a predecessor press cannot release onto a successor. Each dialog draws and delivers at most once per native frame. Escape supersedes the other collected actions. Cancel bypasses action eligibility gates. A successor opened from a callback is first drawn on a later frame.

An action captures the exact document token, canonical project object, project UUID and editor revision, plus its owned session and preview. Package actions also capture selected UUIDs and path text. Publication/reload/removal checks these again after the external gate. A gate that changes the canonical source, preview, selection or opening cannot lend the earlier gesture to the newer state. Import and package admission likewise capture a retirement generation and committed context around their gate; reentrant cancellation or admission cannot overwrite a successor. Private Properties text is deliberately outside this context because these workflows preserve it separately.

Validation callbacks may cancel and open another Import, or open a destination popup. Old completion does not close or annotate that successor. Runtime callback/guard failures produce bounded application diagnostics; inline feedback belongs only to the still-owned opening. The old session cannot cancel its successor, even after an exception. Package submission remains busy across read/handoff or export I/O, retaining the prior publication exclusion. Failures preserve the entered path and reviewed preview for an explicit retry when current. Complete package validation, atomic replacement, same-document Reload and live active-project path protection remain unchanged. No schema, registry, engine API or preference format changes occur.
