# Exact 2D image row reuse

The async 2D noise image path reuses bounded immutable raw rows before applying the existing color and histogram mapping. Keys contain the selected field/dependency computation identity, every X coordinate's exact double bits and the row's exact Z bits. Coordinates keep the original `pan + (pixel - side/2) * step` evaluation order; no view snapping, reassociation or hidden output clamping is introduced. Grayscale/Heatmap/Contour/Threshold/Histogram display changes can reuse raw values.

Matching vertical pans reuse overlapping rows, and revisiting an exact view can reuse retained rows. Changed X axes/step, dependencies/seeds and explicit Regenerate cannot serve incompatible values. Horizontal and diagonal pans can reuse exact overlapping values across different cached X axes and row sizes. Positive-step axes are sorted, so bounded row candidates use binary search with exact double comparison, including signed zero. Matching coarser/finer grids can also reuse intersections. Fractional translations that change sampled coordinate bits still execute those samples; no alignment is forced. A full world-tile cache remains separate work.

An access-ordered byte budget reserves a conservative row allowance and caps retained rows at 4 MiB per view, further limited by configured cache MiB and the scene CPU budget remaining after current image work. Zero disables row retention. Budget reductions trim even an inactive 2D view, and an older in-flight request cannot raise the current ceiling. Eviction rebuilds map storage after trimming; closing drops rows and prevents in-flight work from repopulating them. Field callbacks run outside cache locks. Request versions/generation leases prevent stale sources from replacing newer cache contents. Complete successful rows may remain reusable after cancellation, but failed/partial rows and images are never published. Returned image observations own their arrays.

Statistics distinguish rows requiring any new samples from individual sampled/reused values; partially reused rows still count as sampled rows. An immutable row is admitted only after every missing value succeeds. Candidate observations hold immutable row references outside the cache lock, and only current-generation use updates LRU order.

NoiseImageRowsTest covers exact/fractional/large/signed-zero coordinates, vertical/revisited reuse, source/axis/step/force invalidation, LRU/byte/zero budgets, horizontal/diagonal overlap, cross-size fragment assembly, exact zoom intersections, next-representable-coordinate rejection, failure/cancellation ownership and concurrent stale-source protection. ImageRowsReference exercises eight production cache views and emits exact raw/color/histogram digests. Independent Python recomputes every digest and work count; an external engine-only consumer checks 524,288 samples from the saved original/changed fields. Desktop smoke separately waits for actual async/GL completion and asserts display-only recoloring, a one-step vertical pan return-view reuse and a one-column horizontal pan. These are work-count and numerical guarantees, not a hardware speedup claim or complete A27 GUI acceptance.
