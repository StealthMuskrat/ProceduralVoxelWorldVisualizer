# Unified Find and protected navigation

View > Find now separates advanced search from simple resource selectors. Filters combine kind, root, folder/layer subtree, enabled flags, text and references. Text can match authored values/UUIDs, IDs/control labels, or breadcrumb context. Find References resets unrelated filters and shows direct usages by default; Include containing resources additionally shows the owning processing/resource containers. Changing search text while a reference filter is active narrows those references rather than silently clearing the filter.

Results include resources, transforms, processing items, shared parameters, authored source controls, item parameters, input/output bindings and curve points. Each row shows its breadcrumb and a stable opaque UUID/control key. Actual JSON locations are retained for inspection, while navigation resolves current UUIDs instead of replaying old array indices. Source/item/input targets open the relevant property sections; numeric parameter/input controls scroll into view where supported. Curve-point targets open the private Curve Editor, select the exact point and center its view. Conditional/hidden controls and the complete gesture matrix remain outside this scoped navigation evidence.

## Search data and identity

`ResourceSearchIndex` captures immutable committed metadata. Root and folder/layer relationships are separate from visible IDs. Parent traversal is iterative; directory scope uses UUID ancestry. Breadcrumb base paths retain a bounded 4,096-character suffix for very deep hierarchies, while directory ancestry remains exact. Authored per-hit value text is limited to 32,768 characters. Truncated text/path suffixes can limit text matching on unusually large/deep definitions; exact UUID reference and directory filters remain separate. Search does not index unapplied drafts or invent missing engine-default values.

Direct usage checks preserve recognized reference-key context, including references inside input bindings and UUID-valued item parameters. UUID-like display strings do not become references. Container references remain available explicitly. Disabled layer flags propagate to operation results, and disabled item flags to their child-control results; this is flag state rather than a claim that the compiler executes every enabled item.

`ResourceSearchSession` caches one immutable index by committed revision/project-object identity and one result set by the complete filter value. Scrolling/drawing reuses both. Closing Find releases its index/results. Folder/layer scope uses the same clipped searchable selector as other resource choices. Result rows use fixed two-line native clipping. Query/index construction still scales with project size; these bounds are not hardware latency certification.

## Leaving a property draft

Same-owner navigation preserves the existing property draft, including invalid/rejected edits. A target removed only in that draft is unavailable rather than recreated from the committed document. Leaving a different resource with unapplied edits opens Apply/Discard/Cancel. Apply uses the existing validated property transaction, then navigates; failure keeps the draft and decision open. Discard is explicit and performs no document transaction. Cancel preserves selection, draft, history and dirty state. Stale targets, project replacements, a newer draft or a newer committed source definition invalidate the pending decision.

Find navigation waits while a private Curve/Membership Editor is open, so another search target cannot replace that temporary editor. Curve-point navigation itself changes selection/view state only; Curve Apply and parent property Apply retain their existing separate behavior. Existing Resources-panel selection and diagnostic navigation retain their established behavior; this is a search-specific draft guard, not a global rewrite of all navigation flows.

## Validation scope

Unit contracts cover explicit root/directory/breadcrumb vectors, direct/container reference sets, UUID-like presentation text, real escaped JSON locations, stable keys, disabled-parent propagation, immutable metadata, locale independence, bounded deep paths, cache inputs and project replacement. Navigation contracts cover same-owner rejected drafts, Apply/Discard/Cancel, failed validation, stale/deleted/foreign targets, draft-only deletion, one Undo and exact curve-point selection.

`UnifiedFindProbe` creates an isolated real ImGui context with 1,000 noise resources. It checks bounded viewport submission and cached native scrolling, exact root/directory/ID filtering, actual mouse activation and Escape cancellation of the draft guard, explicit discard, precise reference-binding locations and selected curve-point identity. Document/history/dirty/numerical invariance is checked against an independent 0.25 + 0.5 expectation. `verify_unified_find.py` independently checks the exported report. Desktop smoke renders the real Find window with committed results. Linux/Windows CI run the reference alongside prior workflow/render/input checks. Complete GUI/DPI/platform acceptance, every conditional control, arbitrary mathematical domains and Windows 11 hardware remain separate.
