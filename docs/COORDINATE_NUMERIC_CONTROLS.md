# Coordinate slider/text controls — unvalidated development

This connected source batch implements the slider/text pairing portion of specification 4.1.2 for Inspector XYZ and Add Bookmark/Teleport coordinate forms, while preserving the existing 4.3 responsive layout, Tree 18 bookmark/navigation ownership and Tree 19 explicit inspection actions. No compilation, JUnit, native replay, independent consumer, checker, schema generator or workflow ran. The owner testing pause and last observed 922-test / 120-suite validated baseline remain. Main is authoritative.

## Exact raw coordinates and suggested sliders

CoordinateInput provides one shared slider/text pair. Text remains the complete provisional signed decimal input in its existing buffer and ledger. The original input labels/IDs and focus targets remain; the slider has its own native identity and disables native temporary text editing. The Inspector retains its responsive XYZ column budget, grouping each complete pair as a cell. Pairs place the text to the right when there is room and stack within narrow cells. Bookmark/Teleport forms use the same component across their tab-specific X/Z or X/Y/Z axes. Rename's read-only saved coordinates retain their existing presentation.

Each valid coordinate gets a suggested neighborhood extending up to 256 blocks in each direction, clipped to the signed 32-bit endpoints using long arithmetic. Native slider storage uses double, which exactly represents every int, avoiding native signed-int slider half-range restrictions and float narrowing. Slider proposals round explicitly to the nearest integer with ties to even; only a different, finite integer inside the displayed neighborhood produces new decimal text. Suggested ranges do not restrict text admission. Text still accepts both integer endpoints and its existing leading sign/zero forms, rejects fractional/exponent/overflow/malformed coordinates, and never falls back to an earlier parsed cell.

Drawing, layout changes and unchanged rounded proposals do not normalize raw text. A slider is disabled with Invalid when the displayed coordinate is malformed or disagrees with its accepted ledger text; its finite placeholder is never published. Disabled hover guidance explains correction. Text remains available for repair. All axes are still validated together at the existing explicit action boundary.

The displayed range stays anchored for a held slider interaction rather than walking with each accepted edit. If accepted/displayed raw text changes outside that interaction, its remaining held proposals are rejected. A release, changed widget identity or hidden frame retires that range ownership; a subsequent activation can establish a new neighborhood. The native control owns mouse/keyboard activation, while the pure CoordinateSlider state owns proposal eligibility and exact range arithmetic.

## Existing publication boundaries

A slider edit writes only that axis's raw buffer and private input ledger through the same callback as text. Inspector input advances its existing coordinate ownership version and invalidates old retry/action observations as ordinary typing does. It does not generate a trace, choose a voxel, add a bookmark or move the camera. Bookmark/Teleport input stays inside its request-owned private form; opening/cancelling a form clears its coordinate widget state. Slider movement does not invoke Teleport or Apply. Existing footer/context checks, complete displayed-text agreement, explicit actions and one-entry bookmark history remain authoritative.

Project/model/schema formats, world arithmetic and engine/headless dependencies are unchanged. No default coordinate is serialized merely by drawing. The central Help catalogue adds Coordinate sliders and exact input, related to Bookmarks, Navigation, Trace and scalar readouts, with shared tooltip guidance and explicit action/precision rules. The broader universal numeric-control/precision/metadata audit remains separate; this batch does not certify every numeric caller.
