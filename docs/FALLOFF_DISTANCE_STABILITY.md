## Distance construction

Falloff multiplies its signed input by 1 - shape(distance / extent). Previously, Euclidean distance squared each coordinate difference directly. Tiny differences could produce a zero or inaccurate subnormal sum of squares, flattening the falloff, while large squares could overflow despite a finite distance and normalized ratio. A norm, Manhattan sum or opposite-sign center difference could also overflow before division by a large extent even when the desired ratio was representable.

ScalarRemapping now keeps the original Euclidean pow/sum/sqrt operation order when its squared sum is normal and finite, and at the exact center. A nonzero subnormal sum or square overflow uses StrictMath.hypot on active dimensions. NaN square sums remain NaN. If the distance itself is nonfinite, coordinate differences are normalized by the positive finite extent before recomputing the selected metric. Each difference still subtracts before division whenever subtraction is representable; only overflowing subtraction distributes division over the two coordinates. This preserves small differences between nearby large values. INPUT-domain distance uses the same subtraction guard independently of sampling coordinates. Two-dimensional coordinate distance still ignores Y.

Euclidean, Manhattan, Chebyshev and Axis share the normalized recovery path. Ordinary finite metric arithmetic remains unchanged. All four shape functions, explicit Clamp/Extend policy, signed final multiplication, typed explicit positions, transformed coordinates and compiled parameter ownership remain in their existing paths. No implicit output clamp or normalization is introduced. Genuinely nonrepresentable extended results still fail at the existing compiled-item boundary. This is not a guarantee that every mathematically finite expression is representable; shape/interpolation arithmetic and final multiplication retain their existing limits.

Previously accepted tiny falloff inputs can produce corrected values, and some previously failing large cases now produce finite results. This intentional numerical bug fix does not promise extreme-case bit compatibility. Existing archive bytes and authored project fields do not change; regeneration uses the current implementation. The registry description documents the guarded policy. Registry version 6, operation IDs, parameter/default/range declarations, project format 2, schemas, UI ownership and public method signatures are unchanged.
