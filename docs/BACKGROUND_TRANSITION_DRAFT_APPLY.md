## One private Apply before the existing file decision

The production New/Open/Exit guard now moves explicit Apply Draft candidate replacement, complete compiler validation, immutable freezing and Undo-delta construction onto the existing bounded editor executor. It captures the active private Properties resource through the same prepared DocumentSession edit API used by ordinary Properties Apply. Ordered sibling selection is retained; only the active Properties resource is applied. Invalid provisional seed input rejects before scheduling and remains visible/private.

Applying Properties is a separate modal phase with Cancel Apply and Escape. A CPU mailbox owns at most one prepared result. Worker completion publishes to that mailbox; UI delivery marks it ready without changing the project, private draft, history or file. After rendering and processing the modal's current input, the owner accepts a ready result from the original Apply action. No additional confirmation is introduced. Cancel/Escape wins over acceptance on its activation frame, including an already delivered result.

Publication checks the exact document lifetime/project/revision, private draft identity and complete values, raw-seed generation, active/ordered sibling selection, path and dirty baseline. It also checks full committed source values, shared diagnostics identity/content/scope and prepared document checkpoint/history/validation-policy authority. The existing transition blocker is checked around ownership before acceptance. Changed or reentrant owners abort the older action; an older result cannot overwrite newer diagnostic feedback or a successor transition. Returning private input to its committed values after requesting a transition does not silently rebase the captured draft decision.

Accepted Apply is consumed before private editor refresh and any later file/exit consequences. It creates one ordinary undoable edit, then reloads the private draft and enters the separate Save/Don't Save/Cancel decision. Cancelling that later decision keeps the explicit Apply committed and undoable. A post-Apply guard/refresh failure aborts the transition while retaining the committed edit; duplicate deliveries cannot apply it again. Required-save failure still aborts New/Open/Exit, and a successful save retry only saves. Standalone Save remains committed-only. Discard Draft keeps its deferred-disposal behavior until actual transition success.

## Recovery and lifetime

Rejected canonical candidates retain the original draft and expose immutable current-policy diagnostics. Scheduling, compiler/worker Error, UI handoff and externally cancelled Future failures return to the original draft decision with bounded attempt-owned details and explicit Apply Draft retry. There is no automatic unchanged-frame retry. A rejected/failed decision can be cancelled or explicitly discarded. Correcting the private input after cancelling requires a newly owned transition request; stale source authority is never silently rebased.

Cancel, lifecycle closure and successor requests retire queued/completed mailbox ownership and best-effort remove/interrupt queued/running work. Late CPU results cannot repopulate a retired slot, and queued delivery closures retain only request identifiers rather than a prepared project. Rejection feedback and success refresh are consumed before callbacks so feedback failure cannot replay a transaction. No project file or preference write occurs during preparation. Existing background Open/Save paths, public synchronous constructors, project/config schemas, headless APIs, generation semantics and manual-only workflow triggers remain unchanged.

Owner capture/copy/full-value comparisons, diagnostics presentation, history publication and private draft refresh still cost UI time. Cancellation does not interrupt every compiler phase, and no large-project latency, memory or hard cancellation deadline is claimed. Complete native/OS/Windows 11 and release acceptance remain pending.
