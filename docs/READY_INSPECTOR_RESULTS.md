## Current Inspector decisions before publication

Coordinate Trace and World Pick previously published trace snapshots, logs, picked coordinates, misses and primary failures directly from queued UI callbacks. Those callbacks could run before the Inspector processed current Cancel or close controls. InspectorTask now owns a private CPU mailbox and one exact Ticket for each pending attempt. Worker publication is retirement-aware; UI delivery carries only the task/ticket identities and marks readiness. It does not replace the prior trace, append a log, update entered XYZ/bookmark targets or report a captured failure. Pending request/target and native control identities remain stable through readiness.

Viewports captures the shown Ticket before Inspector controls. After the Inspector's native window scope ends, current decisions run before that exact Ticket can accept a ready result. Cancel Trace/Pick, coordinate edits, Restore, another Trace/Refresh and window close retire or supersede the predecessor. New work submitted from that footer waits for its own shown frame. Bookmark retains its separate explicit edit flow; a resulting committed source change also invalidates old inspection authority. The original accepted Trace/Pick still finishes without another confirmation.

Escape retains its existing Inspector contract: it suppresses footer decisions and acceptance for that frame while leaving the request pending. It does not silently cancel work or replace entered XYZ. Closing cancels. Explicit jobs continue while the Inspector is collapsed or initially hidden; an initial accepted pick can open the Inspector as before. Camera/view/preview changes still retire view-bound picks, while explicit coordinate jobs remain independent of camera/tab navigation. Document replacement still retires every Inspector task.

Acceptance requires the shown Ticket, complete worker return and UI readiness. A terminal future failure can be accepted without a successful delivery callback, preserving recovery from escaped Errors, failed handoff, future status/get faults and external cancellation. Cancel or current ownership changes can retire those failures before primary feedback. Readiness while the worker is returning grants no publication authority. Queue/capture failure is prepared as an owned ready failure for the same current-control boundary, rather than reporting from submission. The low-level legacy finish helpers retain compatibility; production uses the complete-work/readiness acceptance path.

## Source, preparation and consumption

InspectorSource retains the committed project object, document lifetime, logical UUID, revision and complete captured project values. Final acceptance repeats that source guard and the original coordinate version, exact displayed XYZ strings and existing request/view/GPU-picking checks. Unsupported in-place source mutation cannot publish a trace labelled current at an unchanged revision. Private Properties, provisional seed text, preferences and camera-independent explicit targets remain separate. A stale source/display retains the applicable prior trace and corrections and requires a new explicit request.

The worker still compiles and evaluates an owned ProjectData copy. It now completes world closure before preparing the immutable TraceSnapshot presentation and publishing into the CPU mailbox. A close or presentation-preparation failure produces only a failure payload; no success has already entered the UI queue. Prepared payloads contain immutable trace presentation, optional picked coordinate/proxy status, a miss or a Throwable. They contain no renderer/native object or mutable project accessor. The World Pick View stays on the UI owner. Queued callbacks capture the task/ticket, rather than Viewports, source snapshots, trace payloads or failures.

Ticket identity prevents equal-valued reconstructed requests, foreign task tickets, duplicate callbacks and closed/predecessor deliveries from taking a successor's slot. Acceptance rechecks the original Ticket after terminal-future and validity callbacks. A callback creating a ready successor and returning true, false or throwing cannot consume or report against that successor. Cancellation clears ownership before requesting interruption; cancellation callbacks cannot overwrite a newer request/future. Accepted work detaches its completed Future and consumes the mailbox before later trace/log/native/failure feedback. A consumed result cannot replay.

Coordinate failure retains Retry Trace for its exact attempted target, independently of entered XYZ or an older displayed result. Pick failure retains explicit new Pick/Trace guidance without inventing a coordinate target. Failure and cancellation leave prior trace/log state intact; accepted pick miss retains the established Coordinates hint behavior. Exact-stage picking, streamed proxy explanations, engine arithmetic and historical snapshot/source-link contracts remain. No retry loop or extra transaction/save/history boundary is added.

Mailbox retirement releases ready success/failure independently of draining callbacks; a late worker cannot refill a cancelled or closed slot. Interruption/queue purge remains best effort, and worker-local copies or trace preparation may persist until computation exits. Owner snapshot capture, complete source comparisons, native controls and final presentation/log operations still cost UI time. Moving TraceSnapshot preparation to the worker is source implementation, not measured latency, heap, renderer or platform evidence. No schema, registry, file version, public headless API, User Config or authored mathematical semantics change.
