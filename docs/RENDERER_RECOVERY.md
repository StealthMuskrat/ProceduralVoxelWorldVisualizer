# Viewport renderer startup recovery

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This implements specification 17.1.7/19.6 and supports A27–A29/A31/A33. The last validated baseline remains 922 tests / 120 suites.

Previously each View field eagerly constructed its OpenGL renderer before the Viewports constructor could contain failure. A viewport shader compile/link exception could prevent all three tabs and the editor from starting, while partially allocated shader/program or viewport objects could remain unowned.

Each tab now owns an independent render-thread startup slot. Successful initialization transfers a complete renderer; failed initialization records bounded diagnostics and leaves that tab unavailable. The other tabs and the rest of the editor can initialize. A failed tab presents its error and a working Retry Renderer button. Idle frames, profiling and project reopening do not automatically repeat the failed initialization. Each failed explicit attempt publishes one VIEWPORT_RENDERER_FAILED event. A healthy renderer is retained rather than recreated by another tab's retry.

Unavailable tabs schedule no preview work. Shadow/timing/streaming metrics and arena maintenance tolerate them and report no invented GPU allocations. Document retirement, normal close, camera-input reconciliation and private project editing remain usable. Successful explicit retry adopts current display preferences and enables the tab's normal change-driven generation. It does not apply private Properties input, change the project, create history or replace healthy accepted previews. Fatal JVM errors remain fatal, with cleanup of already initialized tab resources; this does not recover loss of the main GLFW/OpenGL context or the ImGui backend.

GlPrograms now owns shader IDs before source submission/compilation, owns the candidate program before attaching/linking, and transfers it only after successful linking and shader cleanup. Vertex/fragment compilation, attachment, zero allocation and linking failures attempt release of every allocated object. Primary diagnostics survive cleanup errors, with cleanup failures suppressed. Driver log messages are bounded to 8,192 characters before the editor retains a 1,024-character startup explanation. Existing mesh, volume, packed-scene and shadow programs all use this path, with their GLSL text and attribute indices preserved.

GlViewport initialization now closes partial viewport allocations when construction fails, including a successfully created mesh program if volume compilation subsequently fails. Close is idempotent and accepts partially initialized resources. Native resource cleanup can itself fail; these guards promise explicit ownership and attempted cleanup rather than recovery from an arbitrary broken driver.

Four RendererStartupTest and four GlProgramsTest definitions cover explicit retry/no idle retry, independent resources, close during construction, null factories and throwing close, successful transfer/attribute slots, compile/attach/link failures, zero allocations and primary-versus-cleanup error ownership. Two additional StatusBarLayoutTest definitions require strict retained-diagnostic caps including the ellipsis and whole surrogate pairs. Existing display clipping retains its prior content-budget contract; startup and recent resource failure messages use the strict diagnostic helper. None has run.

RendererRecoveryProbe defines a real GLFW/OpenGL 3.0 context, two deliberately invalid GLSL vertex compilations during 3D tab startup, real healthy 2D/World preview generation, explicit Save while the 3D tab is unavailable, two actual Retry Renderer button clicks and a recovered `.25` slice. Five phase records require factory attempts `[1,3,1]`, two errors, no failed-tab work, healthy image identity/submission retention and exact project/history/private/raw-input preservation. The shader failure is injected through the package-private viewport factory; failure after partial GlViewport allocation is source-defined cleanup, not a native fault-injection receipt in this probe.

The independent checker defines exact phases/statuses and complete source/saved/after/preference equality. RendererRecoveryConsumer uses only the headless engine JAR to replay 162 exact `.125`/`.25` scalar values and 144 solid cells over signed chunks at roots 2/4. Future Linux/Windows probe/consumer/checker commands and artifacts are wired without changing workflow triggers. Nothing was built, compiled, run or certified during this batch. Runtime device loss, physical DPI/GPU behavior, all driver failures and complete GUI/Windows 11/release acceptance remain pending.
