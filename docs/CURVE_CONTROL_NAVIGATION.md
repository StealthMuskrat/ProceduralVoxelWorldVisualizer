# Curve diagnostic and search control navigation

Status: **implemented, awaiting validation** on `codex/development-phase`. GitHub testing is paused by owner instruction until the program is fully developed. This implementation, its regression definitions and future native/independent replay have not been compiled or executed.

Curve-point search and diagnostic/source links now share the Properties navigation route into the private Curve Editor. A link resolves the current owning Curve item and point UUID first. A historical JSON pointer may contribute a recognized control leaf, but its resource/item/point array indices never select a current object. Direct logical field keys take precedence over contradictory pointer text. An item-only link into a historical point array does not guess a point. Ordinary item/input navigation still reveals Properties.

The route covers curve domain minimum/maximum, display minimum/maximum and outside-domain policy, plus point X/Y, next-segment interpolation, handle mode and incoming/outgoing slopes. Point links select only their exact point and center its plot location. The requested control receives one keyboard-focus submission and scroll request; the actual widget acknowledges it. Following a new destination creates a fresh request. Navigation does not change a numeric value, interpolation, handle mode, project, preferences or history.

Endpoint X is domain-locked, so its route focuses the corresponding domain bound with an explanation. A tangent link without an adjacent Bezier segment focuses the segment mode. Auto-derived slopes focus Handle mode so the user can explicitly choose an editable mode. These fallbacks reveal the existing controls without changing them. A condition change before acknowledgement or removal of the selected point cancels pending focus. Explicit point/plot selection, local history shortcuts, deletion and Cancel also cancel it. Guarded source links focus the Curve Editor when it is the navigation destination.

An already open private property editor blocks further control/problem links instead of replacing its buffer. Normal project/draft replacement still uses the existing publication guards: a stale curve session cannot stage into a changed source. Curve Apply stages only into its exact Properties draft; Properties Apply remains the project transaction. Cancel discards private curve edits. The engine, curve representation, interpolation and project/User Config/API schemas are unchanged.

## Deferred verification definitions

`CurveNavigationTest` defines four contracts for UUID ownership with deliberately wrong historical indices, direct-key precedence and every supported field, ordinary/input/unrelated routes, foreign resources and missing/removed controls. `CurveControlFocusTest` defines six contracts for single submission/acknowledgement, domain-locked endpoints, Linear/Auto/Free tangent fallbacks without mutation, cancellation/replacement/deletion, invalid keys and conditional-control changes. `SearchNavigationTest` adds an open-editor link guard and exact-draft preservation case.

`CurveFocusProbe` defines a production native workflow: a point-Y diagnostic with historical point index 777 focuses the current midpoint, keyboard entry changes its private Y from 0.5 to 0.75, attempted links preserve that editor, and Cancel restores the parent draft. Later links acknowledge the domain-maximum, segment-mode and display-maximum controls without editing their values. It then repeats the point repair, stages through Curve Apply, commits through Properties Apply and checks one project Undo/Redo. Its saved three-knot Linear/Clamp curve is `(0,0), (0.5,0.75), (1,1)`.

`CurveFocusConsumer` defines a public engine-JAR replay over 147 observations against independent piecewise arithmetic: `1.5*x` on the first segment and `0.5*x+0.5` on the second, with endpoint clamping. `verify_curve_focus.py` checks the native report, schema, exact knots, bindings and unchanged modes. Future Linux/Windows workflow steps and retained artifacts reference these definitions, without altering development-branch trigger exclusions. None has been executed during this batch.

Opening an invalid curve that the existing private session cannot compile still reports an open failure; this batch does not add an invalid-curve repair editor. Physical keyboard/IME/DPI behavior, arbitrary window-scroll layouts, all native tangent-mode gestures and full A13/GUI/hardware acceptance remain pending. Earlier validation evidence remains scoped to its recorded source.
