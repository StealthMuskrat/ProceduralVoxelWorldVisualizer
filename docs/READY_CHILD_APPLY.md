## Current controls before publication

Background Apply Members previously committed its prepared document edit from the delivered UI callback. It now retains the prepared edit or worker failure in a one-slot CPU mailbox. Delivery marks readiness while preserving Applying Members, the request version and the shown Cancel action identity. The Membership dialog handles Cancel/Escape, checkboxes, Select/Clear Matching and other footer controls, then unwinds the popup before accepting only the request shown in that draw. A normal success finishes from the original Apply action; no additional confirmation or Apply click is added.

A choice edit retires preparation even if later edits restore the same ordered UUID values. A no-op checkbox notification leaves ownership intact. Accepted member publication retains full document/private/raw/checkpoint/history/policy/diagnostic checks, one Undo transaction and no-op Redo behavior. It copies only the published member list into the existing private Properties draft. Separate private ID, seed ledger, preferences and project Save keep their existing ownership. Voxel sets continue to affect generation predicates; groups remain organizational resources. Direct synchronous constructors retain their prior behavior.

Curve Apply already waited for its dialog to accept a prepared result. Its handoff now also uses a CPU mailbox, and both successful preparation and worker failure remain pending until that acceptance. Delivery changes neither work version nor request token. The Curve dialog accepts only the work shown before its controls, after the native window scope has unwound. Ownership callbacks that cancel and start a ready successor cannot authorize it from the older acceptance call.

Curve Cancel Apply/Escape preserves the local curve and history; Cancel/window close discards the local editor. Collapsing Curve Editor retires pending preparation while retaining local input/history for explicit retry. An unavailable Membership modal suspends its pending Apply and keeps temporary choices. This does not change the existing policy for explicitly closing either editor or the parent Properties panel.

Queued callbacks capture request identifiers rather than prepared projects/curves. Cancel, suspension, stale input, closure and successors clear the mailbox independently of callback draining. A worker that finishes after retirement cannot refill a retired slot. Worker failures/rejections remain cancellable before feedback is accepted; scheduler/external-Future/handoff failures still use the existing failure recovery. Late and duplicate delivery cannot consume another request. Successful staging/publication is consumed before follow-up refresh and cannot be repeated after a refresh failure.

Curve publication remains private staging of only its parameter. Parent Properties Apply and explicit Save are separate steps. Complete opening source/project checks, source node identity, curve UUID and local values remain authoritative; unrelated private Properties ID/seed input survives. Public headless APIs, formats, schemas, registry identifiers and curve/voxel mathematics are unchanged.

Snapshot capture, complete comparisons, selected-type resolution, diagnostics, prepared value copies, final history installation and refresh retain owner-thread cost. Cancellation is best effort for running compilation. A worker may retain its own captured inputs until it exits. These changes do not claim measured responsiveness/heap, physical input, platform/DPI or complete GUI acceptance, and do not change unrelated background completion paths.
