# Bounded volume texture replacement

Volume previews now stage a replacement GL_R32F texture and upload encoded texels across frames using the configured Upload KiB. A complete candidate atomically replaces the accepted texture and its encoding/extent. Until then the last framebuffer, accepted origin, palette and hover metadata remain available. New requests cancel obsolete candidates; transfer failures before publication and admission rejection retain the accepted texture. Regenerate explicitly retries rejected or failed requests. Post-publication retirement failures now retain the complete replacement with matching metadata in source; see the unvalidated [retirement handoff](VOLUME_RETIREMENT_HANDOFF.md).

Admission includes both accepted and candidate texture bytes at four bytes per texel, checked before sampling and again before texture allocation. The bound covers scalar textures; framebuffer/depth attachments, fixed mesh buffers and driver overhead remain outside this texture reservation. Switching to image/mesh/streamed display or removing the source releases hidden volume textures. Viewport closure disposes both accepted and candidate textures.

The render thread copies only the next contiguous region into a reusable 64 KiB direct buffer. Whole planes/rows are combined where possible; partial rows support byte budgets below a row. No extra full-volume float clone is created during upload. Fixed-volume working-memory admission adds the staging allowance to its 12-byte-per-cell sampling estimate; profiler CPU bytes include the retained staging buffer and pending encoded samples. Shrinking CPU/GPU limits below an in-progress replacement cancels it with explicit retry feedback. GL unpack alignment, strides, skips, byte swapping and pixel-unpack-buffer binding are normalized for each write and restored afterward. Texture allocation still uses driver allocation and may incur latency; the byte cap measures destination writes, not GPU completion or elapsed time.

CPU ownership tests use an independent 3D memory backend and cover exact texels under arbitrary budgets, active/candidate reservation, cancellation/replacement, allocation/write failure, closure, immutable data and invalid ranges. Native probes compare every encoded texel, analytical Beer-Lambert pixels, retained framebuffer bytes during incomplete uploads, nondefault unpack/PBO state, and production viewport metadata through cancellation, GPU rejection and retry. Camera-relative volume windows now reuse this upload lifecycle; see [streamed volumes](STREAMED_VOLUMES.md). Complete GUI/DPI/hardware acceptance remains separate.

Identified streamed windows now reuse eligible resident GPU overlap and gather only exposed CPU regions. Copy and host writes share the destination budget and publish one complete candidate; separate counters and profiler series identify each path. Legacy unidentified/synchronous APIs retain full-host behavior. See [resident GPU reuse and renderer API notes](VOLUME_GPU_REUSE.md).

Unvalidated W06-C04: [texture cleanup ownership](VOLUME_TEXTURE_CLEANUP.md) preserves a pre-publication transfer fault and successful-transfer counters when candidate deletion also throws. clear()/close() detach both captured handles before backend callbacks and attempt both deletions, retaining the first fault and suppressing a distinct second one. close() drops its staging reference in finally. A throwing deletion has ambiguous physical effects and is not blindly retried. Six added CPU-backend fault definitions remain uncompiled/untested; the testing pause and wider native/caller/release gates remain open.

Unvalidated W06-C05: [retirement handoff](VOLUME_RETIREMENT_HANDOFF.md) synchronizes representation and metadata acceptance with the committed version when previous-texture deletion throws. Recoverable retirement faults report a ready display with a cleanup diagnostic; Errors still propagate after metadata acceptance. Retirement no longer passes through candidate-failure cancellation. Five handoff and two additional cleanup definitions remain uncompiled/untested; actual native transitions and independent acceptance/reporting faults remain pending.

Unvalidated W06-C06: [palette upload ownership](PALETTE_UPLOAD_OWNERSHIP.md) makes palette failures retryable without falsely caching the attempted colors/width and isolates the write from caller unpack/PBO/2D-binding state. Four CPU definitions and expanded VolumeUploadProbe/checker definitions remain uncompiled/untested. This does not make the in-place palette write or preview acceptance transactional against independent GPU failures.

Unvalidated W06-C07: [failed-volume UI ownership](VOLUME_FAILURE_SETTLEMENT.md) settles pending/active/working UI state before backend cancellation, delays guarded exception text and checks an exact failure ticket/epoch before later feedback. Cancellation faults report separately; diagnostic-delivery faults preserve primary viewport feedback. Seven CPU helper/uploader definitions and a strengthened native rejection assertion remain uncompiled/untested. Actual native failure/closure/retry and wider post-commit acceptance/profiling recovery remain pending.
