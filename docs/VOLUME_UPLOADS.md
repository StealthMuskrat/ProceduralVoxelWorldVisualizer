# Bounded volume texture replacement

Volume previews now stage a replacement GL_R32F texture and upload encoded texels across frames using the configured Upload KiB. A complete candidate atomically replaces the accepted texture and its encoding/extent. Until then the last framebuffer, accepted origin, palette and hover metadata remain available. New requests cancel obsolete candidates; failures and admission rejection retain the accepted texture. Regenerate explicitly retries rejected or failed requests.

Admission includes both accepted and candidate texture bytes at four bytes per texel, checked before sampling and again before texture allocation. The bound covers scalar textures; framebuffer/depth attachments, fixed mesh buffers and driver overhead remain outside this texture reservation. Switching to image/mesh/streamed display or removing the source releases hidden volume textures. Viewport closure disposes both accepted and candidate textures.

The render thread copies only the next contiguous region into a reusable 64 KiB direct buffer. Whole planes/rows are combined where possible; partial rows support byte budgets below a row. No extra full-volume float clone is created during upload. GL unpack alignment, strides, skips, byte swapping and pixel-unpack-buffer binding are normalized for each write and restored afterward. Texture allocation still uses driver allocation and may incur latency; the byte cap measures destination writes, not GPU completion or elapsed time.

CPU ownership tests use an independent 3D memory backend and cover exact texels under arbitrary budgets, active/candidate reservation, cancellation/replacement, allocation/write failure, closure, immutable data and invalid ranges. Native probes compare every encoded texel, analytical Beer-Lambert pixels, retained framebuffer bytes during incomplete uploads, nondefault unpack/PBO state, and production viewport metadata through cancellation, GPU rejection and retry. This adds upload lifecycle contracts to bounded fixed volume analysis. Streaming volumes and complete GUI/DPI/hardware acceptance remain separate.
