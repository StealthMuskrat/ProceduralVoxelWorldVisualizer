## Current selection and host controls before installing Included

ExportEditSession previously installed initial catalogs, selected-resource dependency closures and Reload results or reported captured planner failures during queued UI delivery. It now retains the result/failure in a one-slot CPU mailbox. Delivery marks readiness only: the original planning request remains stable, an initial catalog/preview stays private, and any previous catalog/Included rows remain visible. Desired selections keep their latest values. Export and new-plan acknowledgement remain disabled until acceptance and a later Included display.

ResourcePackageDialog captures the current export opening/session and planning request before drawing. Checkbox changes, Cancel/Escape, Reload/Retry, Remove Missing and page controls run first. The exact shown request may be accepted only after the native popup scope ends. A newly started inline preparation cannot be accepted as the previously shown work. An unavailable popup does not install a result for absent controls. Acceptance precedes the separate staged-file acceptance path; catalog preparation itself writes no package or temporary file.

ResourceExportPanel also guards the exact session and its externally owned selected UUID set. It repeats those checks after a presentation callback, so a callback that mutates the desired set cannot authorize the earlier closure. Its standalone draw accepts the originally shown request after its own body/footer controls finish. A session first created within that draw waits for a later draw; external standalone hosts still own any enclosing window/lifecycle controls. Package-hosted pages delegate acceptance to the current File Location opening after popup unwind.

Successful installation repeats complete ProjectFileOwner authority, document/source identity/revision, full frozen-source equality, exact desired selection, shown opening/context and blocker checks. Requests and owners are checked again after callbacks, preventing old work from installing or retiring a ready successor. Full frozen-source comparison also rejects a raw committed edit made before a new selection request captures its owner; that request cannot reuse an older source catalog merely because the new capture matches the edited project. Changed source values require explicit Reload. Private/raw seed/selection/saved-path changes retire old work without restoring older values.

Installing the computed catalog/model/closure does not acknowledge Included. Selection-only work reuses the immutable catalog for that frozen source; Reload installs a new catalog and disables old choices until it arrives. Missing selected UUIDs remain explicit unresolved selections: accepting the new catalog may produce a missing count and no preview. Remove Missing remains an explicit action against that catalog and prepares another closure. Empty selection remains non-exportable. Old or foreign preview objects cannot acknowledge a replacement. Only later visible Included rows can permit the separate explicit Export action.

Ready success or captured catalog/planner failure may be cancelled before replacement rows or primary error feedback. Accepted failure retains the last completed rows and desired selection for explicit Retry preview. Staleness and missing selections never start an automatic retry or remove resources silently. FutureTask observation continues through readiness, so inline readiness followed by handoff failure cannot silently install an unaccepted catalog. Scheduler rejection, external Future cancellation and handoff faults retain their existing refresh/failure policy; already consumed publication is not rolled back by a later external fault.

Supersession, cancellation, stale ownership and retry advance the mailbox epoch and release CPU results independently of draining callbacks. Retired workers cannot refill it. Queued callbacks hold identifiers rather than computed catalog/model/failure payloads. Reset/cancel and successful file publication close the session mailbox. Synchronous direct sessions retain immediate planning; direct asynchronous owners explicitly accept delivered work.

Package/project/schema/registry formats, dependency closure math, exact source UUIDs/root order and public headless APIs are unchanged. Planning does not apply Properties, save files/preferences, change history or alter generated field/voxel rules. File staging/replacement retains the separately guarded reviewed-preview boundary. Source snapshots, full comparisons, selection copying and native hierarchy/Included projection still cost owner-thread work. No measured large-project latency, heap, cancellation or platform bound is claimed. Other completion paths and full release acceptance remain outstanding.
