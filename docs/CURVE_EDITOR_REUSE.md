# Curve Editor compiled and sampled work reuse

Development implementation on main; **uncompiled and untested** under the owner's testing pause. No compiler, Gradle, JUnit, native probe, consumer, reference evaluator, Python checker or GitHub workflow ran. The validated baseline remains **922 tests / 120 suites**; this is not full GUI, A13, Windows 11 hardware or final release acceptance evidence.

## Interactive work

The private Curve Editor previously reconstructed `ScalarCurve` and captured 513 plot samples on every visible frame, including unchanged frames. It also discarded the canonical curve already built while validating an accepted edit. `CurveEditSession` now reuses those immutable compiled definitions for drawing, accepted edits, gesture previews, tangent baselines, insertion sampling and Auto-to-explicit handle conversion. Local Undo/Redo and gesture rollback can reuse a retained definition without recompilation.

The session owns an access-ordered cache of at most eight entries and an estimated 2 MiB of retained keys/compiled data. Keys contain every authored Curve and Point value: ordered point identities/coordinates, segment/handle modes, explicit slopes, curve identity/domain/display range and outside-domain policy. Signed zero remains distinct. Keys hold immutable value records, not editable model or point objects. Every lookup captures current values, including calls after unsupported direct mutation through the existing mutable curve getter; object identity alone never authorizes reuse.

The canonical `ScalarCurve` constructor still validates every uncached definition. Invalid attempts never become cache entries, never replace a successful entry and retain the constructor's diagnostics/order even for malformed shapes. A definition larger than the retention estimate may compile and display without entering the cache. The estimate is not an instrumented JVM heap limit. The existing 100-entry local authoring history and the currently displayed compiled curve remain separate ownership/costs.

A second, single-entry cache retains the immutable 513-sample `CurvePreview` for one compiled definition and exact horizontal input span. Selection, unchanged frames, window pixel reflow and vertical-only view navigation do not change those numerical observations. A changed definition or horizontal span captures a new set; rendering still projects those values into the current screen/Y view each frame. Numerical failures remain explicit NaN gaps with the original count/first failure, including when reused. Fit or a corrected definition can produce fresh finite observations. Invalid view requests do not replace the previously successful snapshot.

Cancel, accepted staging and terminal draw cleanup clear both caches. Closing Properties cancels its open Curve Editor as well. No new preference, automatic save, committed edit or history entry is introduced. Apply still validates and stages into the exact owned Properties source; the ordinary parent Apply remains the full project transaction. This batch does not move curve work onto workers: value projection/comparison, cache misses, editing/validation, plot drawing, opening/staging snapshots and final Apply validation remain on the UI thread. No measured frame-time or large-curve throughput bound is claimed.

Four added `CurvePreviewTest` definitions cover exact unchanged observations, changed span/compiled identity/signed zero, invalid-view retention and cached gaps/correction. These sixteen definitions are unexecuted.

A separate default-curve fixture stages endpoint Y=2 through the production editor, then explicitly applies, saves, undoes and redoes the parent transaction.

It defines **441 exact affine/clamped observations**, whole-project Redo equality and an Undo comparison allowing only the edited endpoint. Its original 99 finite extreme-extension observations and six structured failure boundaries retain their scope. Existing manual-only Linux/Windows commands and artifact directories reach the expanded probe/consumer without adding a trigger or dispatch. None of these scenarios or consumers was executed.

Engine/model/compiler APIs, canonical interpolation/arithmetic policy, schema/registry data, file/archive versions and deterministic generated values are unchanged. Broader latency/memory measurements, physical keyboard/docking/DPI/platform behavior, Windows 11 acceptance and final artifact verification remain pending.
