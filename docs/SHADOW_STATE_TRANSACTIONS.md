## Allocation ownership

ShadowMapWork serializes allocation and rendering on the render thread. Invalid configured resolutions and device limits reject before retiring an accepted map. A matching completed size returns without native queries or allocation. A full caller-state snapshot also precedes retirement. Snapshot/preflight failure leaves the previous allocation and foreign state unchanged, apart from any external callback's own effects.

Once admitted, the previous allocation retires before a private candidate is created. Texture/framebuffer/program handles belong to that candidate, while public getters remain zero. ShadowAllocationState composes the existing ten-value TextureUploadState with independent read/draw framebuffer restores. Host allocation uses the captured active unit, unpack PBO zero, alignment four and zero swap/row/image/skip state. All twelve restoration attempts finish before completion checking and transfer of candidate handles/resolution to the accepted owner. Foreign signed bindings retain their exact bit patterns. A saved texture/FBO binding naming the retired owned object restores to zero instead of recreating or binding a reused name; this exception is necessary when the saved resource itself was deliberately retired.

Body RuntimeException/Error retains identity through failed restores and candidate cleanup; otherwise the first restore failure wins. Candidate cleanup attempts every typed handle independently, without text/suppression/replay. A post-restoration completion failure also retires the unpublished candidate. Failed admitted replacement leaves logical getters zero and permits explicit retry while open; it does not preserve old depth pixels or resurrect the retired predecessor. There is at most one logically complete shadow allocation, with no new budget or physical-reclamation guarantee.

Close remains available during work and retires accepted/candidate ownership independently. Returned names are checked before registration; a name returned after closure is retired once as an orphan. A backend that throws after allocation without returning its handle retains responsibility for that unknown allocation. Recursive allocate/render rejects before snapshots or native commands, including same-size calls. Closed work cannot publish a candidate after restoration or completion.

## Depth pass state

ShadowRasterState captures five integer bindings/functions, six flags, viewport, generic attribute 4, clear depth and depth range. Array snapshots are owned and restoration callbacks receive fresh copies. Depth work binds its captured framebuffer for read/draw, selects its resolution viewport, enables depth testing/writes with LESS, uses clear depth one/range [0,1], disables cull/scissor/polygon offset/rasterizer discard and clears depth before drawing. Current checks follow each normalization command and the draw callback.

All fifteen restore tails are independent: VAO, attribute 4, program, depth mask/function/clear/range, five capability flags, split framebuffers and viewport. The body or first restore primary retains identity, and no later fault can skip the tail. A draw count returns only after restoration, completion and current-owner checks. Direct failed rendering retains allocated storage for explicit retry; depth contents may already have changed. GlViewport's optional shadow failure path retires the failed map under existing C22 policy. This is logical acceptance and caller-state restoration, not physical depth-buffer rollback or full parent viewport/frame acceptance.

Native allocation and raster completion check glGetError after restoration, so queued body/restore errors cannot produce normal acceptance. The first queued error is consumed; there is no error-drain loop or rollback of GL's error flags. Shader sources, DEPTH_COMPONENT24 storage, nearest/clamp depth sampling, 3 x 3 PCF, projection/bias math and configured resolution/budget selection remain unchanged. Fixed small snapshots/closures add unmeasured overhead; headless code has no new dependency.
