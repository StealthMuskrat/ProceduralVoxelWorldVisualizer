# Project, Editor, Visualization and Debug settings

Status: **uncompiled and untested** on `codex/development-phase`, under the owner testing pause. This extends [Project Settings transaction ownership](PROJECT_CHANGE_FEEDBACK.md) and [measured settings chrome](APPLICATION_SETTINGS_LAYOUT.md). It does not certify the complete program, GUI/DPI acceptance or Windows 11 hardware. The validated baseline stays at 922 tests / 120 suites.

Project Settings now places Apply, Cancel, Discard and Reload, and Show Problem in a persistent measured row outside its scrolling body. All three labels wrap above available-width raw text inputs. Stable hidden field IDs remain independent of label size and scrolling. The bounded candidate diagnostic child uses measured text rows capped at 40% of the body rather than a fixed 110-pixel height. The existing eight-entry rendered/256-entry owned diagnostic limits remain unchanged.

Show Problem chooses an exact displayed/owned mismatch first, then a supported project field from local or attempt-owned candidate diagnostics in seed/minY/maxY order. It uses the existing owned focus request and requests body scrolling without parsing, normalizing, correcting bounds or applying a previous value. Resource/control diagnostics and unsupported metadata locations do not invent a field destination; their details remain available in Validation Results. Show Problem is disabled for stale sessions; Discard and Reload becomes available there, and explicitly replaces the entire private settings session. Apply retains all existing complete displayed-map, source/revision/identity, full candidate validation, one-transaction Undo and explicit-save rules. Closing or Cancel consumes only the settings session.

The production `LivePreferencesPanel` now owns the Editor and Visualization presentations. Their immediate preferences stay in the same User Config objects. Editor has a scrolling body, wrapped labels, an available-width opportunities slider and a persistent Save Preferences action. The slider publishes only 1–20; manually entered out-of-range slider values are clamped when submitted. Its description distinguishes regeneration opportunities from actual dirty-source regeneration.

Visualization has a scrolling body with bounded checkbox targets and wrapped labels. Directional-shadow resolution now offers only 512/1024/2048, and volume light sampling only 8/16/32, through explicit choices instead of coercing arbitrary integers. Disabling either shadow option retains its associated choice. Existing renderer/budget behavior is unchanged. Save Preferences, Edit Preview Limits and Retry Shadows remain outside the body; Retry is disabled while directional shadows are disabled. The limit callback still selects the retained Performance limits form, without applying its text. Shadow status is read from the real viewports in Desktop; the native fixture supplies descriptive statuses without constructing GPU resources.

Every active User Settings category now supplies its own save action through its existing production composition; Desktop no longer appends a second ordinary-save control after category content. Ordinary saves still write only active preferences, preserve private settings forms and project/resource drafts, and use the existing atomic writer and error handler. Resizing/navigation does not recreate the panels or change settings ownership. No schema, persisted preference key, registry range or engine API was added.

`DebugSettingsPanel` retains the eight specified diagnostic sections in a full-width selector. Its scrolling read-only body shows section-specific real engine/scene/scheduler/event values, rather than repeating both complete metric records beneath every expanded header. Configured LOD preferences are explicitly identified as configured values. Start/Stop Capture and Open Profiler use a persistent row. They share the same `ProfilePanel.start` callback and engine profiler as the dedicated window; no duplicate backing enable flag exists. Opening a section or Profiler does not start a capture. A displayed Stop action remains a stop request if the capture times out before activation, and a Start action does not replace a capture that became active after it was drawn. Limits, world-contribution options, frozen export review and percentile views remain in Profiler.

Six deferred `ProjectSettingsProblemNavigationTest` definitions cover unchanged raw spelling, oversized displayed mismatch priority, missing/equal-number display rejection destinations, coupled candidate/local locations, unsupported resource/metadata locations and exact project pointers. Three deferred `DebugSettingsOwnershipTest` definitions cover read-only section navigation, externally replaced/stopped/cleared capture observation and immutable supported-section selection. These definitions have not run.

`GeneralSettingsLayoutProbe` defines 24 production form/size cases across the four pages: wide, narrow at user scales 0.5/1/2.5, a 6.25 global/window font product and a short client. It defines real mouse/keyboard edits, complete private raw strings, stable IDs, horizontal input bounds and persistent action/category/body geometry. Additional phases define valid option selection, ordinary-save exclusion/failure/retry, disabled Retry, explicit callback routing, all eight diagnostic sections without instrumentation, one shared capture Start/Stop, candidate rejection with 300 details/eight drawn rows, narrow retry, one Apply/Undo/Redo and stale Apply/reload/Cancel. A separate private Properties ID and invalid seed stay unchanged. Synthetic rendering statistics and shadow descriptions exercise presentation only; the fixture creates no renderer or GLFW window and makes no GPU/physical DPI claim.

`scripts/verify_general_settings_layout.py` independently checks the geometry, action order, complete raw field maps, stable IDs and saved project/preference values. Future Linux/Windows commands and artifact paths are recorded with workflow triggers unchanged. No compilation, JUnit, native probe, replay, generator, build or GitHub workflow ran for this batch. Actual combo placement, every focus/scroll/IME/paste path, tiny clients smaller than a selector/action row, deep native font inheritance, full Profiler internal reflow, physical mixed-DPI/detached displays and complete interactive acceptance remain pending. This change does not add a verbose-log preference or expand instrumentation coverage.
