# Tooltip previews and fractional native fonts

Status: implemented on `codex/development-phase`, **uncompiled and untested**. Builds, JUnit/native probes, independent replay and GitHub testing remain paused. The validated baseline remains 922 tests / 120 suites. This batch does not certify A32, full GUI/DPI or Windows 11 hardware acceptance.

## Pinned native behavior and font measurement

The imgui-java [v1.89.0 binding declarations](https://github.com/SpaiR/imgui-java/blob/v1.89.0/imgui-binding/src/main/java/imgui/ImGui.java) declare GetFontSize with an integer return, while GetTextLineHeight returns a float. Its [native submodule](https://github.com/SpaiR/imgui-java/tree/v1.89.0/include/imgui) pins Dear ImGui commit `1d8e48c161370c37628c4f37f3f87cb19fbcb723` (native source identifies itself as 1.89.9). The [native implementation](https://github.com/ocornut/imgui/blob/1d8e48c161370c37628c4f37f3f87cb19fbcb723/imgui.cpp) returns the current floating font size from GetTextLineHeight. UI scope inheritance, status measurement and the existing deferred scale/DPI probes now use that float accessor. This avoids losing fractional height during nested normalization and removes integer-to-Float probe assignments. The dependency versions are unchanged.

The pinned native tooltip API has two distinct behaviors: SetTooltip replaces a prior tooltip, while BeginTooltip appends. During drag/drop, BeginTooltipEx also enforces its own replacement/position policy. Tooltips are independent windows; simply changing the parent window's font does not make every native tooltip inherit it. The binding's BeginTooltip declaration does not expose the native replacement flags. No new JNI entry point or direct native memory access is added.

## Owned text-only tooltip presentation

`UiTooltip` captures the caller's effective floating font and current content scale. It resolves the current viewport/client and monitor intersection through the existing popup work-area policy, with offscreen-owner recovery and main-DPI transfer. The mouse supplies a value-only anchor. A pure budget permits up to 36 font heights of width and 12 text lines, further constrained by current work area, insets and padding. It does not change user/window scale preferences.

`TooltipText` keeps complete source text with its original owner. For presentation it inspects at most 4,096 UTF-16 characters and uses bounded measured prefix search when the source will not fit. Prefixes preserve Unicode codepoint boundaries; an omitted suffix is indicated by `...`. The marker itself must fit both axes, otherwise the visible preview is empty. This is a hover preview, not a modification of a name, expression, trace value, diagnostic, path or copied value. The complete source remains available through its existing editor/details/copy path where one exists; no new universal full-text action is claimed. Grapheme-cluster and complete glyph coverage are separate from codepoint preservation.

Rendering first uses native SetTooltip with an empty placeholder to retain its replacement behavior, then BeginTooltip to append actual content after applying inherited font normalization. In a drag/drop source, the native second replacement hides the placeholder. The empty placeholder's cursor is reset before text, so it contributes no leading text row. Both native scopes receive the fitted viewport/position/size. Actual content wraps inside that fitted box. Font/IO/global scale, atlas and parent item data are not rewritten; The tooltip local font scale returns to 1 before EndTooltip, including observation/text failures, so later native color/drag helpers cannot inherit a stale scale from a reused tooltip slot. EndTooltip still runs if scale restoration fails. Native lifetime and hidden-for-sizing behavior remain owned by Dear ImGui.

The existing UiScale.tooltip entry point now uses this presentation. `UiScale.beginDragDropSource` also normalizes the automatic preview window after a successful native Begin; SourceNoPreviewTooltip leaves the caller alone. The paired end wrapper restores the automatic tooltip local scale before native EndDragDropSource and leaves SourceNoPreviewTooltip callers untouched. Resource tree drags use this pair, preserving payload type/value and existing selection/move ownership.

Outer Voxel Manager swatches, Voxel Type color editing and Themes color swatches suppress their native color hover tooltip and show a text RGBA summary through UiTooltip. Their primary color editor/picker, flags, buffers, editing decisions and drag/drop payload behavior remain native. In particular, inner color-picker popups/tooltips and native color drag previews are not converted by this change. Existing Theme rejected-channel guards still own publication.

## Deferred definitions and limits

Eleven pure definitions comprise seven TooltipTextTest and four TooltipLayoutTest cases. Independent cell-metric vectors describe complete Unicode/hash/percent/newline preservation, both-axis truncation, explicit line limits, 4,096-character inspection, supplementary character boundaries, unavailable-marker behavior, bounded measurement calls, invalid measurements and analytical layout budgets/extremes. These definitions have not run.

`TooltipProbe` defines 30 native ImGui cases: long text, color button, RGB editor, RGBA swatch and an actual pointer-driven drag source across six synthetic content/framebuffer/user/window combinations. The narrow fractional case expects font height 18.28125; another composes user scale 6.25 at content DPI 2. Cases record inherited root/three-deep/tooltip/return font metrics, bounded geometry, source/preview values and parent item rectangles. Additional definitions inspect a reused unwrapped native tooltip for restored local scale, compare rendered total vertices for one final tooltip versus a replaced first tooltip, and retain private Properties/raw seed, committed values, engine/profiler and native color buffers. Replacement vertex parity is scoped software draw-data evidence, not a screen capture of every pixel.

`scripts/verify_tooltips.py` independently describes font arithmetic, geometry, Unicode prefix/size bounds, RGBA preview values and replacement receipts. The prior UiDpiProbe/UiScaleProbe definitions now observe the corrected float accessor without changing receipt formats. Future Linux and bundled Windows workflow definitions include TooltipProbe/replay/artifacts; triggers remain unchanged and this development branch does not trigger them. None of these definitions or replay steps executed.

Physical DPI/monitor motion, detached backend windows, GPU font upload/sharpness, title/style dimensions, every production hover gesture, callback/native exception recovery, accessibility, internal multiline editor fonts and inner color-picker fonts remain pending. Extremely small work areas can be smaller than a readable glyph; bounded geometry does not make such a viewport usable. Native synthetic fixtures explicitly leave physical/GPU/multiline/picker certification flags false.
