## Active manual definitions

`HelpCatalog` freezes one active AppMetadata publication into immutable topic values. It includes the existing ordered feature/control definitions, immutable registry option keys with active display aliases, and semantic related-topic links. `HelpDefinitions` centralizes fixed manual guides for Help itself, Find, Workspace, update trust, Project Settings, Appearance, Visualization, traces and About. These help-only guides are separate from editable metadata; they do not introduce new persisted control keys or change a schema/format version.

Search includes topic IDs, feature names, groups, tooltips, descriptive guidance, canonical option keys, aliases and related topic names. Space-separated words all need to match; case and repeated ASCII whitespace normalize for a reusable projection. Topic values, options and related links retain no mutable metadata fields. Same-publication frames reuse the catalog and unchanged normalized queries reuse their result list. Application Settings publishes a new metadata object on Apply, at which point Help refreshes its snapshot. Private metadata text and future-item defaults are not consulted by Help before publication. An unsupported in-place mutation of an already published metadata object is outside that publication contract.

`HelpSession` retains the selected canonical topic independently of filtering. A zero-match search does not select another topic or copy a fallback. Explicit topic and related-topic navigation populate a 32-entry Back history; repeated navigation to the current topic adds no history. Metadata replacement keeps the same canonical topic and updates its displayed guidance. Unknown links retain the prior selection/history.

## Help presentation and context requests

Help retains Topics and Guidance pages beneath full-width search/page controls. Topics use whole-pixel measured clipped rows and canonical IDs; labels containing `##` are escaped only for native widget identity, while complete copying retains original Unicode/text. Guidance wraps descriptive text and canonical options, followed by related-topic links. Copy, page switching, Back and Clear stay in two measured persistent rows outside the scrolling body. Clear resets search and reveals the selected topic in the full topic list. It does not silently choose another topic. Long selected captions and clipped row/action labels retain tooltip access to their complete text.

Enabled Desktop menu items offer right-click Help routes, with unique popup identities for individual commands even when several commands link to Projects. Metadata-backed Inspector controls use the same bounded context popup where a matching definition exists; a hover tooltip advertises the gesture. The popup keeps Open Help outside scrolling explanation and uses current popup work-area fitting. Right-click Help does not invoke the item's primary command, repair a field or apply/discard a draft. This is explicit pointer-based context Help, not a new shortcut or a change to F1 recording/text/free-fly suppression. Disabled menu item context gestures and controls without a matching metadata definition are not covered.

A UI-thread `HelpRequests` mailbox connects supported source controls and About to Desktop's Help window. The last explicit request is consumed once. It selects the exact canonical topic, clears a hiding search and shows Guidance. Topic selection, history, copying and context requests do not alter project/history/engine/profiler state. Existing Workspace capture may retain Help visibility as a User preference. Draft decision guards are unnecessary for these read-only manual links because they do not replace the current authoring selection or private input.

## Runtime and license information

About retains Runtime and Licenses sections with a scrolling body and persistent Copy/Help actions. Desktop captures application/engine versions, Java runtime/VM and current OpenGL version/vendor/renderer/GLSL strings during initialized startup with the context current. Missing or blank environment values are explicit `Unavailable` entries. Values and their order are immutable in About; copying returns the entire displayed section, including long text and Unicode. These values describe the initial main context rather than querying every detached context or subsequent driver change.

The license section lists declared dependency versions, terms and scope, distinguishing build/test-only components and conditional bundled runtime/software-driver components. It points to `docs/LICENSES.md`, `docs/third-party`, runtime legal directories and conditional Mesa notices. It does not claim these summaries contain every full notice or that every listed conditional component is currently loaded. Project-owned source has no supplied open-source license grant; the existing ownership statement is retained. About's Help action opens the corresponding manual guide without closing About.

Window names remain `Help` and `About`, preserving native INI identity and existing scale keys. Preferred first-use sizes become 750 x 600 and 680 x 500; saved usable bounds continue to take precedence through the existing floating-window owner. User/App/Project formats, creation signatures, deterministic generation and explicit project-save rules are unchanged.
