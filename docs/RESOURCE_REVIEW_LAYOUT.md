# Import and membership review layouts

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This extends [owned import](IMPORT_WORKSPACE.md), [portable transactions](IMPORT_TRANSACTIONS.md) and [membership selection](RESOURCE_SELECTION_WORKFLOWS.md). The validated baseline remains 922 tests / 120 suites.

Import now separates Resources, Filters and Issues inside one scrolling body, with two persistent measured action rows. Import, Cancel, Reload and Validation occupy the first row; Resources, Filters and Issues occupy the second. Disabled actions retain their positions. The modal identity, Resources scale/viewport host, explicit reload behavior and owned transaction remain unchanged. Filters keeps the raw search, kind and resolution choices; Issues shows the transaction explanation, COPY/REUSE/SKIP totals, stale/blocker feedback and up to eight preview/eight rejected-candidate diagnostics. Existing bounded candidate storage, Validation and Logs retain their previous authority. No new diagnostic publication is fabricated merely by viewing a page.

Resources keeps an available-width search and compact row count above a measured list. Rows retain their incoming UUID, conflict/compatibility, resolution choice and preview target. Their clipper stride accounts for three text lines, one frame and four gaps, rounded up to a whole logical pixel with an explicit tail item. Resolution controls use available width; hidden row IDs remain tied to incoming UUIDs across reflow. Display labels and hover text use bounded codepoint-safe presentation without changing underlying IDs/UUIDs. Full transaction planning and package snapshots retain their existing costs; this is not a package-size or hardware latency certification.

`ImportRows` caches one immutable view by exact plan object and normalized filter, with unfiltered resolution totals. Queries now also match existing and target UUIDs. Projection never constructs an import candidate or changes choices. Ordinary scrolling reuses the view. Reload/reopen clears projection ownership and scroll intent. A changed choice still invalidates the exact reviewed plan; only a visible Resources list can acknowledge its successor. Filters and Issues alone cannot acknowledge it. A previously reviewed unchanged plan stays reviewed while navigating pages. Review still describes the displayed filtered/clipped view, not proof that every resource row has been visited. Reload explicitly returns to Resources for a subsequent review frame.

Membership now separates Members and Issues. Two persistent rows contain Apply Members, Cancel and the page toggle, then Select Matching, Clear Matching and Selected Only/Show All. Search, selected count and measured checkbox rows fill Members; the explanation and bounded rejection details scroll on Issues. Bulk edits are disabled outside Members and after cheap owner invalidation. Checkboxes are disabled for a changed owner. Filtered bulk operations still use the complete current projection, not only clipped rows, and preserve unrelated members/order. Changing pages retains raw search, temporary selection and the private parent draft. Stable hidden IDs remain UUID-based. The checkbox stride rounds frame-plus-gap to a whole pixel and submits an explicit tail.

Both dialogs collect decisions before publication and handle Cancel/Escape before Apply or other mutation actions in that frame. Rejected import/membership publication opens Issues, retains the same owned candidate/private selection and supports retry. Membership continues to commit only its members through its existing session and one ordinary Undo transaction; an unrelated drafted ID remains in Properties. Import still appends/reuses its reviewed resources, preserves exact separate Properties input and never replaces existing definitions. No persistence/schema/registry/API, inheritance, engine output or background scheduling semantics change. Export layout remains a separate follow-up.
