## CPU result and source ownership

Fixed previews, camera-relative volume sampling and streaming-source compilation already caught ordinary computation failures. They could still remain pending after failures before/after those catches, profiling finalization, unreadable exception messages or source cleanup. A normal Future exit alone could not distinguish these failures from a successful handoff waiting for UI acceptance.

BackgroundFailure centralizes terminal Future observation and bounded readable error descriptions. InspectorTask uses the same helper without changing its existing request authority. Observation returns no completion for unfinished work, distinguishes normal completion from exceptional/cancelled completion, preserves original execution causes, restores interruption and contains status/read faults. This uses the internal executor's normal completed-Future contract; it does not wait for unfinished work or grant success publication authority.

Viewports now observes the current fixed/volume CPU job before taking its ready mailbox. A known terminal failure drops its unaccepted CPU payload, cancels any pending volume upload, releases busy/working-byte state, advances request authority against late publication and preserves the accepted image/mesh/texture. The tab presents an actionable failure and explicit Regenerate guidance. Marking a request now drops the cancelled predecessor future so a later poll cannot attribute its cancellation to a successor. A completed normal worker still uses the existing mailbox, epoch, budget and upload acceptance checks.

Streaming-source futures are associated with their exact owned-mailbox version and requested source key. Known terminal failure is converted into the existing source-failure result before the mailbox is consumed, disposing any unaccepted source while retaining the prior CPU/GPU scene. Snapshot-copy and non-queue scheduling failures enter the same rejection path and revoke the rejected source version. Existing bounded-queue messages/retry behavior remains. Numerical/source failures block unchanged automatic resubmission until explicit Regenerate or the existing source/request-change rules rearm the tab. Late work after replacement or close still cannot repopulate a mailbox.

All three worker paths use robust error descriptions. OwnedPreviewMailbox now contains cleanup Errors as well as Exceptions outside its monitor; clearing/replacing/discarding an entry cannot strand a newer source solely because old cleanup throws. Interrupted cleanup still restores the interrupt flag. Cleanup remains a best-effort close, with no new promise to repair an arbitrary failing resource. The existing Inspector terminal-failure definitions continue to cover the shared observer.

Accepted data, camera/navigation, exact generation, project/history, private authoring and preferences retain their existing owners. A worker fault discovered after valid data was already accepted does not make that immutable data incomplete; this path protects pending handoffs and reports current task failure. Hardware/GL driver failure, blocked callbacks and every renderer/upload boundary are not certified by this scoped implementation. Central Visualization Help now describes retained displays and explicit retry. No serialized shapes, schemas, registry/defaults or public headless API changes.
