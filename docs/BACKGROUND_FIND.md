# Background committed Find

Development implementation on main; **uncompiled and untested** under the owner's testing pause. No compiler, Gradle, JUnit, native probe, consumer, Python checker or workflow ran. The last observed baseline remains **922 tests / 120 suites**. This is scoped implementation for Trees 4.4.1/18.1 and does not complete A22/A32/A33, GUI, Windows 11 hardware or final release acceptance.

## Index and query ownership

Production Desktop Find now captures committed project values and constructs ResourceSearchIndex on the existing bounded editor executor. A worker deserializes an owned snapshot rather than reading live project objects. Full filtering/scanning also runs on workers; the resulting immutable index can serve later queries without another source build. The legacy public ResourceSearchSession and direct ResourceFindPanel constructors retain synchronous search behavior. The existing constructor that injects background navigation remains compatible; production explicitly enables background search as well.

One desired filter and one worker slot replace a query queue. A source build continues through typing so its completed index can serve the latest query. Its old query results do not become current if text/scope changed. Query scans supersede predecessor scans, and a single owned CPU mailbox prevents retired queued UI callbacks from retaining full index/result payloads. Cancellation/interruption is best effort; canonical index construction and scanning are not hard-latency interruptible operations.

Typed text in indexes with at least 1,024 hits retains the 150 ms trailing quiet interval. Identical normalized text does not reset the interval. Explicit filters, Find References, empty text, non-text scope changes and a new committed source bypass typing delay, while still doing their CPU work on a worker. Returning to the accepted filter reuses its exact rows without a scan. Clock regression restarts the interval; elapsed subtraction retains ordinary nanoTime wrap behavior. During initial indexing, typing is coalesced and the accepted source index is reused for the latest scan.

UI adoption checks request/mailbox identity, exact document object/session lifetime/logical UUID/revision, complete captured committed values and the latest live filter. An index can be accepted for its exact source while superseded query rows are discarded. Text changed before another draw still prevents old rows becoming current. Unsupported in-place document mutation rejects publication and requires explicit recapture; it is never silently overwritten. Normal document replacement/revision change starts a fresh index automatically. A source rebuild retires the selected hit even at equal revision; it cannot borrow authority from a newer index. Query-only filtering preserves the existing current-source selected-hit/outside-filter workflow.

## Responsive inspection and failure recovery

Find keeps the last complete result set visible while building, waiting or scanning. Previous rows and Go To Selected are disabled until the exact current request completes. Native row identity includes presentation/request transitions, so held releases from predecessors cannot activate a new row. Existing Apply/Discard/Cancel navigation ownership, private Properties guards and resource reveal behavior remain in force. Search never applies or discards private edits on its own.

Queue rejection, worker index/scan exceptions or Errors, external Future cancellation and failed UI delivery expose bounded FIND_SEARCH_FAILED feedback with a body Retry Search action. Unchanged failed frames do not retry, including failed capture/admission. Changing filters or Retry Search explicitly requests recovery; Retry recaptures the source and rebuilds its index. Previously accepted rows cannot navigate while failure is displayed. A collapsed failed search retains its failure for explicit retry.

Collapse retires pending work while retaining an accepted index/rows. Closing Find clears source/index/results and queued authority; reopening begins from current committed values. Final panel shutdown closes worker ownership. Late and duplicate callbacks cannot repopulate a closed/replaced request. The Desktop smoke definition now waits at its existing bounded phase boundary for completed Find rendering instead of assuming a fixed number of frames proves asynchronous completion.

Private Properties IDs and provisional seed text, project/history/dirty state, User Config and deterministic engine outputs remain separate. Search does not serialize query state into preferences or modify resources. Public headless APIs, search matching/reference rules, registry/schema shapes and file versions are unchanged. Snapshot capture, publication comparison, selector metadata, row rendering and final navigation still cost owner-thread work; no measured large-document or memory/latency bound is claimed.
