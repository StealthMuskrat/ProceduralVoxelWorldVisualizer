# Native viewport input and cursor ownership

Status: implemented on `codex/development-phase`, uncompiled and untested. GitHub testing remains paused by owner instruction. Earlier orbit/free-fly evidence does not validate this extension.

Visualizers now resolves the ImGui viewport containing its current window and uses that viewport's GLFW PlatformHandle for native focus checks. The main application's handle is used only as a fallback when the main ImGui viewport has not yet populated its handle. Unknown/uncreated or retired detached handles are unavailable. Input additionally requires current ImGui window focus, no application focus loss and the existing image/text/popup eligibility rules. Detached Visualizers no longer requires the main native window to be focused.

When the hosting viewport ID or native handle changes, every image gesture releases its ownership, flight pauses and the old cursor lease is released before the new surface is adopted. Docking/undocking does not change camera pose or automatically resume paused flight. Ctrl+click remains the explicit entry/resume action. Image coordinate transforms remain ImGui screen coordinates; procedural computation, source epochs and project/history are unchanged by this ownership transition.

`FlightCursor` owns at most one `(ImGui viewport ID, GLFW handle)` pair. Capture requires a currently registered, focused native window. It records that window's original cursor mode and restores it when releasing a still-live capture, including an originally hidden cursor. A newer external cursor mode is preserved on release. Transfer restores the old owner before disabling the new cursor. A removed viewport identity, even when another viewport reuses its native handle, cannot be read or restored through the old pair. All registry checks and GLFW changes stay on the UI thread.

The pinned imgui-java 1.89.0 GLFW backend ordinarily resets secondary-window cursor modes during its frame update. Capture temporarily adds ImGui's `NoMouseCursorChange` flag, preventing that reset. Release clears only a flag added by this lease; a preexisting flag and unrelated configuration bits are retained. Capture failure restores its owned mode/flag before a retry. Viewports close is idempotent and releases the cursor in a finally block even when other teardown fails; drawing a closed Viewports instance does nothing.

The adapter uses the pinned upstream [viewport PlatformHandle contract](https://github.com/SpaiR/imgui-java/blob/v1.89.0/imgui-binding/src/main/java/imgui/ImGuiViewport.java) and [GLFW backend cursor update implementation](https://github.com/SpaiR/imgui-java/blob/v1.89.0/imgui-lwjgl3/src/main/java/imgui/glfw/ImGuiImplGlfw.java). It uses GLFW window pointers, not platform-specific raw handles such as HWND.

## Deferred verification and limits

Eight `FlightCursorTest` definitions cover focused secondary capture/main isolation, ordered transfer and prior-mode restoration, focus loss/explicit resume, destroyed identities and native-handle reuse, preexisting cursor policy, external mode preservation, failure cleanup/retry and idempotent close. These definitions use a backend that rejects native mode access after a window leaves its live registry.

The existing future WorldPickingProbe sequence now includes `CursorLeaseProbe`. This definition creates a second real GLFW window, captures its cursor while the main window is unfocused, checks main-mode isolation and ImGui cursor-policy suspension, transfers focus/capture back to main, restores a prior hidden mode, then destroys a captured secondary window and checks cleanup without dead-handle access. It uses an explicit fixture registry for the production FlightCursor service; it does not create or validate a detached ImGui layout. The independent report checker is called by the existing deferred world-picking verifier. No probe, checker, build or test has run during this batch.

Actual docking/undocking and secondary-window closure through ImGui, backend frame ordering, physical multi-monitor/DPI cursor behavior, focus arbitration on each OS, GPU context sharing and Windows 11 hardware acceptance remain pending. Identity safety uses the observed viewport/handle pair and platform registry, not an OS lifetime certificate for an unobserved identical pair reused between UI frames. This extension makes no complete multi-viewport or GUI certification claim.
