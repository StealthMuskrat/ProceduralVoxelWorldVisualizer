# Project file transitions

New, Open Project, Exit and native window close share one owned project transition. A modified Properties draft first prompts Apply Draft / Discard Draft / Cancel, including raw seed text on a clean document. A dirty committed document then prompts Save / Don't Save / Cancel. Clean documents without pending input proceed directly. This draft extension and stale-action ownership are unvalidated; see [development implementation and deferred checks](PROJECT_DRAFT_TRANSITIONS.md). An open guard or project path dialog owns its action: another project command cannot replace it.

Save writes the committed document, including its existing explicit-save semantics. Unapplied Properties text is a separate draft and is not silently committed by saving. Saving a named document uses its current path; a new document or Save As opens Project File Location. Both path and guard dialogs support Cancel and Escape.

A successful required save runs its queued action once. Canceling the save path aborts the action. Any failed save also aborts it, including a malformed path or a failed atomic replacement. The path dialog stays open with an inline error so the user can fix the destination. A subsequent successful retry saves only; it cannot unexpectedly create a new project, open another project or exit. The user can request that action again after saving. A failed named save reports through Logs/Notifications and leaves the current session intact.

Don't Save authorizes the requested transition without changing the document's saved baseline. If Open is subsequently canceled or fails, the old document remains dirty. Opening parses and validates a candidate before replacing the current project. Failed attempts retain the path, project, selection, unapplied draft, revision and Undo history. A successful open clears old selection/draft/multi-selection/validation state and history only after the candidate has committed. Source-link freshness still uses project identity.

The unvalidated [project parsing follow-up](PROJECT_PARSE_BOUNDARY.md) requires one complete JSON document, rejects trailing values/text, checks format-version range before narrowing, and escapes parser diagnostic keys containing slash/tilde. Legal surrounding whitespace is accepted. Rejection leaves the existing Open dialog/session owned for correction and retry; the shared mapper and saved format are unchanged.

The unvalidated [typed UUID follow-up](PROJECT_UUID_SHAPES.md) validates declared UUID fields and reference-array elements while preserving user input-map names such as uuid/reference. Raw overrides use the same UUID spelling rule before admission. Invalid references retain the active session for correction; successful retry still replaces it only after full validation.

The project writer serializes once, writes and syncs a temporary sibling, then requests atomic replacement. Unsupported atomic replacement rejects the save with guidance to choose another location; there is no non-atomic fallback. Failed staging attempts remove the temporary file, preserving the primary error if cleanup also reports IOException. Successful replacement performs no further filesystem cleanup, and the exact published JSON becomes the saved document checkpoint. This source follow-up is unvalidated; see [project save atomicity](PROJECT_SAVE_ATOMICITY.md). Project parsing and path creation are both inside error handling. Import/export retains its resource workflow and also catches malformed path construction.

The earlier validated file batch covered transactional state and malformed paths through `ProjectFileWorkflowTest`. The current definitions explicitly arrange a draft-discard decision before isolating those committed-document cases and have not been rerun under the testing pause. The native ProjectFileProbe runs the production dialog with real ImGui mouse/key/text events and real filesystem I/O. It checks all nine dirty New/Open/Exit decisions, all three save-path cancellations, guard/path Escape, three failed-save retries, failed-open retention/retry, named-save failure and clean exit. Exit uses a counted callback in this fixture; Desktop connects the same callback to GLFW close. These checks do not certify physical window-manager input, every file dialog gesture, every platform permission failure or Windows 11 hardware.
