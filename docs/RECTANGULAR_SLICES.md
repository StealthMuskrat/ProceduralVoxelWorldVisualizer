# Rectangular orthogonal slices — unvalidated implementation

The independent XYZ preview counts now extend from fixed mesh modes to orthogonal Slices, supporting specification 15.3.1–15.3.2. SlicePlane projects the full extent onto its actual image axes: X uses Y/Z, Y uses X/Z, Z uses X/Y. A 3×5×7 extent therefore produces 5×7, 3×7 and 3×5 images. Only sampled pixels count against the cell budget; image working-memory admission uses the existing conservative 64 bytes/pixel model rather than charging a cube and voxel-mesh storage. Unused normal-axis count changes are retained for future plane changes without restarting the current slice.

Accepted SliceImageView and requested SliceNavigation carry separate width/height. Pan scales each pointer axis by that plane's own world span; wheel zoom preserves the pointed world coordinate independently on both axes. Both dimensions participate in gesture identity, so a changed height cannot preserve an old held gesture just because width is unchanged. Square constructors and the internal legacy side accessor remain available to existing square fixtures; new production mapping uses width/height explicitly.

The background worker captures the extent with its owned epoch, centers the selected axes, allocates width × height raw/pixel arrays, samples the canonical field at the declared plane coordinates and uploads the same rectangular dimensions. Hover and picked bookmark coordinates still use immutable accepted geometry/sampler, so a pending shape/plane change does not reinterpret the previous image. Status displays both accepted dimensions. Existing 2D image behavior and the other render modes retain their owners; no project/schema/engine semantics change. Volume remains the outstanding uniform-size representation in the independent-extent audit.
