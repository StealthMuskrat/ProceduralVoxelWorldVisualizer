# Bounded GPU draw measurements

Starting a profiler capture now enables optional GPU_DRAW measurements for offscreen fixed meshes, streamed meshes and ray-marched volumes. Ordinary rendering allocates no query names and takes no GPU timing clock samples. 2D/slice ImGui images, chunk texture/vertex-arena transfers, the rest of the UI and presentation are outside this metric. Existing FRAME and UPLOAD_CPU measurements retain their CPU-side meanings. Timings never change procedural generation, display quality or project/history state.

Each viewport lazily owns a four-slot timestamp-pair ring, at most eight query names. A start/end GL_TIMESTAMP pair surrounds the offscreen rendering commands, including framebuffer allocation/clear when needed, optional [directional shadow depth passes](DIRECTIONAL_SHADOWS.md), and per-draw origin/indirect-command buffer updates. Completed results are polled on later editor frames, even if the visualizer/Profiler window is hidden. Both availability flags must be true before either 64-bit result is read. There is no completion wait loop, glFinish or synchronous timestamp read in the production path. Driver command overhead still exists; this is not a guarantee that every GL call has zero latency.

The optional backend requires OpenGL 3.3 or ARB_timer_query and a useful timestamp counter width of 30..64 bits. Unsupported contexts record no GPU samples, rather than inventing zero durations. Timestamp pairs do not begin/end an elapsed-query target, so they preserve a caller's active GL_TIME_ELAPSED query. These semantics follow the [Khronos timer-query specification](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_timer_query.txt). Raw timestamps use their full unsigned width; duration is the modular difference. Zero is a valid measured result.

Pending measurements expire after at most two CPU-wall seconds, or before a narrower counter's wrap interval. Invalid/negative/oversized differences are discarded. A full ring skips measurement for that draw while rendering normally. Expired names are deleted before successors allocate fresh pairs. Query allocation/dispatch/read exceptions suspend this optional instrumentation until a new capture; all owned names are reclaimed on stop, capture replacement and viewport/context closure. No incomplete result is exported as a timing. Arbitrary device reset/driver failure and physical hardware counter accuracy remain outside this functional contract.

Profiler.Scope.recordDuration anchors an externally measured nanosecond duration to its original capture issue stamp. It does not substitute a CPU elapsed interval. Scopes remain bound to one capture, so replacement/stop/sample/series/time limits reject late results. Capture ownership changes clear old pending query references before collection. GPU samples identify the UI project/context at submission and use a stable viewport label; sourceUuid is null because they describe physical viewport commands, not generator/operation provenance. Asynchronous completion order need not equal issue order; offsetNanos is the CPU issue offset, and the value is the separate GPU interval.

The Profiler shows pending, measured, skipped and discarded counts and capability/failure status. Its existing filters, plots, summaries, nearest-rank percentiles and JSON/CSV export accept GPU_DRAW/NANOSECONDS. The v1 profile schema gains this enum value while retaining all historical fields and fixtures. Older readers that hard-code the previous kind list must add GPU_DRAW. Live counters are scoped to the current/last capture; the query pool is reclaimed when collection stops.

GPU command intervals can include scheduling bubbles and CPU dispatch gaps between markers. They are not GPU utilization, exclusive shader execution time, total GPU frame time or display latency. Captures retain their existing bounded sample/series/duration controls. Representative hardware measurements and complete Windows 11/DPI/GUI acceptance remain separate.

Validation includes capture-bound duration API contracts and fake-backend checks for disabled/unsupported paths, bounded saturation, partial availability, nested/stale-end ownership, unsigned/wrapped timestamps, expiry, invalid clocks/deltas, stop/replacement/closure, retry after backend faults, exact zero and global capture limits. Native ordinary/actual strict-3.0 probes compare timed/untimed mesh/volume/streamed framebuffers, preserve a foreign elapsed query, export raw timestamp receipts and check real driver name deletion. Production Viewports/ProfilePanel coverage verifies actual GPU series/filtering/exports, stopped cleanup and unchanged accepted source/document/history. Measurements from software GL are functional evidence rather than hardware performance certification.
