# Two-phase viewport UI peer shutdown

W06-C21 reconstructs shutdown ownership in 1.4.1/14.1.3/14.1.5 and obsolete preview publication in 15.5.3. The restored Viewports.close interleaved peer detachment and callbacks: an Inspector/Future/source fault could skip later views, and cursor restoration in finally could replace an earlier failure. [Workspace recovery](WORKSPACE_RECOVERY.md) records the missing original batch; this is source reconstruction, not original commit recovery or runtime evidence.

## Detach before notification

UiShutdown.prepare captures a list of UI-thread detachers and attempts each independently. A detacher seals its owner and returns captured cleanup rather than invoking external cleanup. The returned once-only plan consumes its callbacks before execution, attempts every cleanup independently, and rethrows the first RuntimeException/Error by identity. Preparation failures retain priority within their plan, and later detach/cleanup attempts still run. No failure text or suppressed-list mutation is used. Nested plans preserve their own detachment failure and cleanup order. Helpers are UI-thread owned, not a concurrent shutdown service.

Viewports first marks itself closed and clears visible focus/hover/cursor-window intent. It retires Inspector request/task/publication state, then each of the three views: job/scene/GL references, epoch, preview mailbox, failure/adoption owners, pending volume/snapshot/display/picking/sampler data, worker probes and local gesture/flight state. Compiler mailboxes, CPU scene publication/jobs, renderer startup slots and row/volume caches are retired during preparation. Bookmark private state and the cursor lease are also detached. The UI thread runs captured cleanup only after all peer detachers have been attempted.

Cleanup cancels the captured Inspector/compiler/fixed-preview Futures, disposes compiler sources, closes captured CPU scenes and renderer resources, purges background work once and restores the captured cursor lease. A Future/source/native failure cannot skip another peer or the final cursor attempt. Shutdown no longer formats renderer failures through VIEWPORT_RENDERER_CLOSE_FAILED while other peers remain open. It propagates the original first cleanup failure after attempting the whole plan; the surrounding desktop lifecycle retains responsibility for application-level failure handling. Startup initialization failure invokes the same shutdown path and preserves its original primary without adding cleanup failures to it.

## Component transfer contracts

Package-private retireForClose methods in InspectorTask, SourceCompilerTask, OwnedPreviewMailbox, RendererStartup and FlightCursor seal ownership immediately and return a captured once-only Runnable. Ordinary close runs that plan immediately. Calling close again does not steal or replay a plan already transferred to a coordinator. Owners cannot reopen; late compiler sources are still rejected/disposed outside mailbox monitors. Owned source disposal retains its previous quiet-failure/interrupt-restoration policy, while Future cancellation failures remain observable to the shutdown coordinator.

ChunkScene adds public render-module retireForClose(): the UI thread immediately seals result/removal mailboxes, detaches every job/token/Future, empties entries/window/required state and zeros active/reserved/CPU accounting. The returned Runnable must be run on the UI thread to notify cancellation and close the captured source. Repeated/nested cleanup is harmless. Existing cancellation-notification failures remain contained, and source-close Exceptions retain the existing quiet policy; an Error still propagates. Ordinary close delegates to preparation followed by immediate cleanup. This additive API does not change the independent headless engine.

FlightCursor detaches its window and suspension ownership before native callbacks. Cleanup reads/restores only the captured live window whose mode is still the captured mode, then independently releases owned ImGui cursor suspension. Dead windows and foreign cursor modes are left alone. The first restore failure survives a later suspension failure. Physical restoration is unverified and a failed attempt is not replayed blindly.

The barrier covers synchronous cleanup initiated by the UI coordinator. A concurrently finishing worker can still dispose its rejected late source on that worker; mailbox gates prevent publication without requiring a UI drain. It does not wait for uncooperative host work or certify physical resource reclamation. Native GlViewport shutdown runs in the cleanup phase through the already-detached RendererStartup slot; native resource semantics retain [C20](NATIVE_RENDERER_SHUTDOWN.md) scope.
