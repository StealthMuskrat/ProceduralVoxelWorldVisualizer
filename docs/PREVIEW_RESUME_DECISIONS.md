# Preview Resume pause ownership

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. The validated baseline remains 922 tests / 120 suites. This follows [visualizer commands](VIEWPORT_COMMANDS.md), [volume pressure](VOLUME_PRESSURE.md) and [streaming fallback](STREAMING_AND_LOD.md). It does not advance A01–A36 or production sign-off.

RenderPressure now exposes an additive pauseVersion counter. Entering a critical or manual pause advances it once; repeated measurements and repeated pause calls in the same paused interval retain it. Resume followed by another pause receives a new counter even at the same severity. The new resume(expectedPause, now) overload admits only that still-active pause and returns whether it was accepted. Existing resume(now), escalation thresholds, fallback order, explicit level-3 recovery and low-pressure hysteresis retain their existing behavior. This is render-thread admission, not a new concurrent controller or persisted setting.

PreviewResumeContext freezes the existing view command review, recovery kind, exact pressure object/pause counter/level/paused state, exact accepted source object/key, requested extent, volume rejection flag and immutable configured performance values. Source/document/tab/mode/dialog changes, changed limits or another pause cannot borrow a held predecessor action. Moving camera/progress/allocation totals and clock values alone are outside ownership. Equal-valued limit snapshots retain a current presentation. Resume preserves the accepted manual source; it does not implicitly select a new generator or set Regenerate force.

PreviewResumePanel draws a wrapped pause explanation and width-capped Resume button under a per-instance presentation ID. Escape suppresses admission. It rechecks the complete live review after drawing, reads the recovery clock, then rechecks again before asking the controller to admit the exact pause. Clock failure keeps the unchanged paused presentation available for an explicit retry. Accepted Resume consumes its presentation before the preview refresh callback; a failed refresh records PREVIEW_RESUME_REFRESH_FAILED without repeating or rolling back the already admitted transition. A callback-created successor pause retains its new ownership. Pre-admission clock failures use PREVIEW_RESUME_FAILED; bounded required diagnostics distinguish the two cases. All callbacks run after native action ID cleanup.

Viewports uses this component for Resume Volume and both Noise/World Resume Streaming. It retains the existing volume rejection clear/invalidation after acceptance and the existing streaming policy-only resume. A frame-end sweep releases omitted/collapsed/inactive recovery controls while keeping paused policy state intact. The volume clock fixture and normal monotonic clock retain their authorities. Neither the panel nor pause counters publish generation results, modify configured preferences, write a project, or weaken memory admission. Existing render source/epoch, last-complete-display, upload and hard budget policies remain authoritative.
