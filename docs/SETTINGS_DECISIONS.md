Project Settings now collects `Apply`, `Cancel`, `Discard and Reload`, and `Show Problem` before executing any decision. Cancel takes precedence. Escape cancels this private form only while its root or child window owns keyboard focus, so Escape in another auxiliary editor does not discard Project Settings. Cancellation neither parses/applies its private fields nor changes another resource's Properties draft. Stale-only Reload remains explicit. Failed Apply preserves exact raw fields and requests feedback reveal inside the scrolling body; Show Problem keeps the existing session-owned field focus route. Successful Apply still changes only seed/minY/maxY in one document transaction and closes through the existing Desktop return path. Project saving remains separate.

Application Settings likewise collects its complete footer before persisting or resetting a profile. Revert precedes staging built-in defaults, which precedes Apply; Show Invalid Value retains its existing navigation. Apply still validates exact displayed creation inputs, writes a separate candidate safely, then activates it. Revert reloads the active profile; built-in staging changes only the private draft. Neither operation saves a project or User Config, and applied creation defaults affect concrete future user-created resources rather than loaded/existing definitions.

Releasing a scope drops its source/draft references but retains the counter, so reopening cannot reuse the first presentation's IDs. Footer scopes are outside the stable body/list children; input, pane and diagnostic child identities retain their established behavior. This is presentation ownership only: the original full-value settings-session validators still decide publication and staleness.
