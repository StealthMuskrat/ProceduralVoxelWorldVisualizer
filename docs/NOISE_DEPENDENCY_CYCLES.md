This source batch supports specification 2.7.8–2.7.9, 6.2.4, 6.13.2, 19.2.1/19.2.4 and 20.1.5, with A03/A09/A11/A22 coverage definitions. No compilation, JUnit, native probe, independent consumer, checker or workflow ran. The owner execution pause and last observed validated baseline of 922 tests / 120 suites remain unchanged.

## Iterative graph validation with exact closing locations

The model validator previously launched a fresh recursive traversal from every noise generator. A long reference chain could exhaust the Java stack before compiler validation; shared subgraphs were repeatedly visited. This also affects structurally valid disabled experimental chains: their references must remain acyclic, but the disabled processing never executes, so an otherwise valid large document should not fail because structural validation consumes call-stack depth.

Noise-cycle validation now builds one graph in authored 2D/3D resource order and visits it with an explicit stack, shared completed set and active-path index. It follows the same structural item inputs and noiseGeneratorUuid parameters in coordinate/processing stages, including disabled items. Named input edges use sorted names for repeatable diagnostics; array execution order is unchanged. Unresolved and malformed references retain their existing validation errors and are not invented graph nodes. Null bindings retain the precise MISSING_INPUT error instead of interrupting traversal with a generic structure error.

Each edge back into the active path produces NOISE_CYCLE at the actual input or parameter that closes that loop. The diagnostic owns the source resource UUID, item UUID, control key and real escaped JSON Pointer. Its message lists the complete UUID cycle route, starting at the loop rather than including an unrelated traversal prefix. A completed cycle is not reported again from every other root. Disconnected components are still all checked; multiple distinct closing edges can each be reported. This is cycle detection, not enumeration of every possible simple cycle in a graph.

The graph traversal visits each resource/edge once; named-input sorting and diagnostic route construction add their own costs. This does not make every validator pass linear or remove runtime compiler/sampling complexity limits. Other validators and JSON serialization retain their own contracts. Local identity, generated scalar/voxel semantics, disabled execution policy, schema and public method signatures remain unchanged. The machine code remains NOISE_CYCLE; its pointer/message/location are now more precise and repeated-per-root diagnostics are intentionally reduced. Central Help explains cycle correction and exact Go To Problem authority.
