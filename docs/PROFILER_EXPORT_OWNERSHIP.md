# Profiler export review and file publication

Status: implemented on `codex/development-phase`, uncompiled and untested. Owner instructions keep compilation and GitHub testing deferred. Historical profiler evidence applies only to its recorded baseline.

Prepare Export retains the exact immutable snapshot displayed by the production Profiler panel. The review shows its capture UUID, state, retained sample count and series count. Search and measurement filters affect the view, not this payload. Later samples, a replacement capture, Stop or Clear do not change the review. Closing/collapsing the window preserves it, while closed/collapsed content does not process controls or refresh the displayed snapshot. A review stays accessible even after Clear removes the live capture. Prepare again explicitly replaces it with the displayed snapshot; Discard Export Review consumes it without writing.

Export JSON/CSV writes only the reviewed token. A successful write consumes it before another button can publish again. Invalid paths, protected project targets, I/O errors and runtime writer failures retain the same review for retry; the output path and chosen format may be corrected. A reentrant write or cancellation during publication is rejected. Export failures have bounded, non-null UI details and receive stable `PROFILE_EXPORT_FAILED` entries in the shared Import/Export Error Center. Starting or clearing profiling does not silently discard the independent review. Reviews and snapshots are bounded by the existing capture limits; there is no unbounded export history.

The editor checks the latest active document path at each write, including normalized names, existing hard links, symbolic links, real parent aliases and dangling links to an absent active project location. This check is shared with resource package export without changing its existing repeated publication checks. It happens before delegating to ProfileIO; the synchronous UI write cannot change the active document mid-call. This is not a filesystem locking protocol: a separate process concurrently changing links or paths can race a check. Other saved projects are ordinary explicit destinations, and engine-only ProfileIO callers remain responsible for choosing their own destination because the engine does not know editor state.

ProfileIO keeps its public JSON/CSV signatures and version-1 formats. It creates a unique sibling temporary file, closes/flushes the writer, forces content, then requests atomic replacement. If the filesystem cannot provide atomic replacement, the writer reports failure and cleans temporary output without a non-atomic fallback. Earlier destination content remains in place when replacement fails before publication. Cleanup errors attach to the original failure instead of replacing it. Root destinations reject before temporary creation. This does not claim directory-metadata durability through arbitrary power loss. No engine dependency on desktop/GL/ImGui is introduced.

Profiler filter projections reuse the same immutable rows while the snapshot, normalized query and measurement kind are unchanged. Active snapshots still refresh at most four times per second; stopped snapshots no longer rebuild identical aggregations every quarter-second. The native list remains clipped. These changes do not alter timing collection, deterministic generation, work contribution semantics or source UUID navigation.
