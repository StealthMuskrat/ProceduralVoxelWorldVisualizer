# Popup monitor intersections and detached-owner recovery

Status: implemented on `codex/development-phase`, **uncompiled and untested**. Compilation, JUnit/native execution, independent replay and GitHub testing remain paused by owner instruction. No historical pass total or acceptance gate changes.

`DialogLayout` and `PopupLayout` now share a pure client/monitor work-area decision and a native value-acquisition helper. All sixteen covered modal presentations and the resource/bookmark selectors adopt the policy. Existing preferred sizes, per-lifetime measurement/drag behavior, anchored placement, action wrapping and private controller/buffer ownership remain unchanged.

## Coordinates and recovery

`UiMonitorWorkAreas` copies current backend monitor WorkPos/WorkSize into immutable rectangles on each call. It reads those values only when ImGui's multi-viewport absolute-coordinate mode is enabled. Native wrappers are used locally and never retained. Floating-tool fitting also uses this shared reader; its existing intersection/gap selection and docking/pointer policy are unchanged. See the [pinned platform inventory binding](https://github.com/SpaiR/imgui-java/blob/v1.89.0/imgui-binding/src/main/java/imgui/ImGuiPlatformIO.java).

With absolute multi-viewport coordinates, `PopupWorkArea` chooses a monitor by largest anchor overlap, then nearest Manhattan rectangle gap, retaining inventory-order ties. A selector uses its real trigger rectangle. A modal uses its last observed dialog rectangle, or the logical owner's latest native window rectangle for opening. `UiWindowHosts` now records those immutable owner rectangles alongside viewport IDs, including collapsed Begin results. Two docked owners on the same large main viewport can therefore open dialogs on different monitors. Missing bounds use the host client rectangle. Explicit clear/frame rewind discards both IDs and owner rectangles; an ID-only observation clears its old anchor.

The chosen monitor work rectangle is intersected with the hosting viewport's current client work area. Existing modal/selector geometry then applies its ordinary up-to-eight-unit margin inside that intersection. This prevents a covered popup from straddling monitor work edges/taskbars while preserving its actual native hosting viewport coordinate space. Monitor/work-area changes are recomputed without retaining an old intersection as the new client extent.

A detached owner completely outside current monitor work areas, or visible only as a clipped sliver smaller than `min(160, client width)` by `min(120, client height)`, falls back to the visible main client intersection. The native popup is explicitly assigned the main viewport. The owner itself is not moved, restored or unminimized. Genuinely small fully visible clients retain their existing small-area policy. A removed viewport falls back without dereferencing or reusing its removed native object.

If the main client is also completely offscreen or visible only as an unusable sliver, the helper retains the full main client coordinate space and reports `monitorConstrained=false`. Physical main-host recovery remains owned by [main-window placement](MAIN_WINDOW_PLACEMENT.md); this helper does not invent a standalone platform popup outside its actual rendering client or shrink private decisions into an unusable main sliver. Complete recovery while every host is offscreen remains a physical integration/acceptance limitation.

With relative coordinates or an empty backend monitor inventory, the current client-area policy remains active and reports `monitorConstrained=false`. In particular, relative `(0,0)` client coordinates are never intersected with absolute OS monitor positions. This mode does not claim independent physical monitor clipping. The native resolver retains the last valid raw client rectangle for a temporarily zero-sized same viewport, uses main work/full dimensions or a provisional preferred-size area when necessary, and clears that transient cache on frame-count rewind. Every call still reevaluates the current inventory.

## Private state and scope

Geometry never edits a draft, query, file path, selected UUID, trace, preference, project revision or history. Existing Apply/Cancel/Save semantics, stale/displayed-value guards, callback consumption and filesystem publication boundaries are unchanged. No schema, registry, generator or public engine API changes are needed. Package-local injection seams allow future integration definitions to supply a synthetic inventory; production constructors always use the live backend reader.

This batch covers the existing modal and resource/bookmark selector helpers. It does not redesign ordinary combo/context-menu/tooltip placement, add per-monitor fonts/atlas/style metrics, guarantee every tiny native control fits, or certify platform popup creation, physical monitor removal, minimize/restore, mixed-DPI migration or Windows 11 hardware behavior. A monitor-intersection implementation is not full specification 4.1.4/4.3/A32 acceptance.

## Deferred definitions

Twenty-two `PopupWorkAreaTest` definitions provide analytical relative/empty-inventory behavior; partial clients; anchor-based monitor selection; offscreen/sliver recovery; genuinely small clients; negative/taskbar origins; removed monitors/viewport owners; main-offscreen and main-sliver fallback; stable ties; touching edges; translation invariance; immutable inventory/invalid inputs; main-client work intersections; independent same-viewport logical owner anchors; ID-only replacement; context rewind/clear; and opening on the actual logical owner's monitor. They use no JNI or GL context.

`PopupMonitorProbe` defines actual production Project File Save As and ResourcePicker presentations in an isolated ImGui context at global scale 2.5. Seven scenarios change an explicitly synthetic inventory between left/right monitor partitions, a smaller taskbar-inset work rectangle, another monitor partition, empty inventory and relative coordinates. Native mouse/text enters a full private file path and resource filter; monitor changes must retain both, Cancel must not create the file, and Escape must not select a resource. Project/private Properties/raw seed, preferences, history and profiler state remain unchanged. The Python definition independently checks each declared client/monitor intersection and bounded native popup rectangle plus the text/cancel receipts.

The native fixture deliberately keeps one actual ImGui viewport. Its report labels the inventory source `synthetic`, and physical detached/DPI flags remain false. Offscreen detached-owner/main recovery and negative monitor coordinates are pure analytical definitions, not real OS monitor evidence. Existing native modal/selector/controller definitions remain queued. Future Linux/Windows steps and artifacts preserve the development trigger exclusions; none has run.
