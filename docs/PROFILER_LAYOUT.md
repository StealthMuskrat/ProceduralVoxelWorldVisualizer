# Profiler sections, exact limits and persistent actions

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This extends [profiler export ownership](PROFILER_EXPORT_OWNERSHIP.md), [attributed work](WORLD_WORK_CONTRIBUTIONS.md) and [general settings](GENERAL_SETTINGS_LAYOUT.md). It supplies no new passing evidence; the validated baseline remains 922 tests / 120 suites.

The production Profiler now retains Capture & runtime, Measurements and Export sections behind an available-width chooser. Only the selected section consumes body space. Each has its own scrolling body identity. Two measured persistent rows expose Start Capture, Stop, Clear, Show Invalid Limit, Prepare Export, Discard Review, Export JSON and Export CSV. Labels may clip in narrow/high-scale clients, with complete hover tooltips and bounded hit targets. Stop/Clear remain reachable from the export section; export review remains reachable after the live capture is cleared. Every section also identifies the current displayed capture, including its UUID, state and retained counts, so Prepare refers to that snapshot rather than an unlabeled live value. Opening/changing a section never starts instrumentation or writes a file.

`SettingsPageChrome` now accepts one to four explicit action-row counts. Existing single-row callers retain their budgets and order. The body reserves each row's measured frame height and gap, with finite double intermediates and a positive scrollable minimum. The Profiler uses two rows of four equal-width actions. It does not claim that clients shorter than the selector and both action rows can show all actions.

Next-capture limits now use four bounded exact raw strings in `ProfileCaptureInputs`, rather than native integer controls that silently clamp provisional values. Labels wrap above full-width inputs with stable hidden IDs. Validation requires a whole signed decimal integer within the unchanged engine ranges: duration 100–60000 ms, samples 64–65536, series 1–1024 and operation stride 1–65536. Leading signs/zeros remain as typed. Incomplete, overflowing, non-decimal or out-of-range text stays private and has no previous-value fallback. The provisional character limit is 128. If native displayed text exceeds that limit, the displayed/owned mismatch still blocks Start until corrected; rejection does not rewrite it to a previous value.

Start requires every displayed raw string to exactly match the owned complete map and valid cached options. The work-total checkbox configures the next capture only. Existing running/stopped captures retain immutable options and samples. The shared public `ProfilePanel.start` entry point used by Debug also performs these checks: rejected limits preserve the existing capture/export review, publish `PROFILE_CAPTURE_REJECTED`, select Capture & runtime and request invalid-field focus/scroll. Show Invalid Limit first chooses a displayed mismatch, then validation in duration/sample/series/stride order, without reparsing or repairing text. Stop/Clear remain available with invalid next-capture text. Private limits/sections are transient panel state, with no new preference or schema key.

Measurements keeps an available-width filter and kind selector, a five-text-row list capped at 40% of the body, and wrapped selected statistics/source details. Entering Measurements requests one-shot body scrolling to its list so long headers do not hide results. Series clipping uses an explicit whole-pixel stride and a tail item to reserve native rounding. Submitted row labels are bounded single-line text with full hover details. `ProfileSeriesKey` covers kind, unit, context, project UUID, source UUID and the complete label; filtering, sorting/summary refresh and duplicate-looking labels no longer reuse another series' position-based widget ID. UTF-16 code units are encoded without ImGui hash-marker characters, including unmatched surrogate units. This avoids logical key ambiguity, but does not claim that native 32-bit hash collisions are impossible.

The existing complete immutable snapshot, quarter-second live refresh, stopped projection cache, percentile and attributed-work semantics remain. Capture setup/runtime no longer rebuilds hidden measurement projections. Runtime strings wrap, and the GPU compaction request is bounded to available width; actual compaction and instrumentation remain owned by the same renderer/engine services. GPU collection still runs through the ordinary frame integration outside the window.

Export shows the owned review and a full-width retained path. Prepare freezes the displayed complete snapshot and selects Export; filtering never limits its payload. Start, Stop, Clear, section changes and invalid next-capture text do not retarget that review. JSON/CSV still use the same active-project alias guard and forced atomic writer. Failure selects Export, logs a bounded error and retains review/path for correction. Success consumes before the next format action can publish; a completed review is explicitly identified. Discard consumes only the review. The older `ProfileExportProbe` definition now explicitly selects Measurements before its cached-row phase, then uses the same export-path hook to select Export; its file/report formats and assertions are unchanged.

Seven deferred `ProfileCaptureInputsTest` definitions cover engine defaults and exact spelling, inclusive boundaries/neighbors, unfinished/overflow/non-decimal rejection, complete displayed agreement, bounded unchanged feedback, mismatch-first correction and immutable already-running options/samples. Three `ProfileSeriesKeyTest` definitions cover every identity dimension, marker/separator/Unicode disambiguation and summary-independent identity. Two additional `SettingsPageLayoutTest` definitions cover multiple-row budgets, finite extremes and row-count rejection. All twelve definitions remain unexecuted.

`ProfileLayoutProbe` defines eighteen production section/size cases across six wide/narrow/short/user-scale combinations, including the 6.25 global/window font product. It defines actual filter/limit/path text editing, persistent two-row geometry, exact hidden private input/cache retention, stable field/logical row IDs, a clipped 200-series stopped capture, invalid shared Start preserving that capture, corrected Start/Stop/Clear, review survival, protected-project rejection, occupied-path retry after narrow reflow, consumed-format inactivity and unchanged project/history/private Properties/engine ownership. The fixture creates no GLFW/GPU instance. A companion API CSV export freezes the same reviewed token for independent replay.

`scripts/verify_profile_layout.py` independently checks geometry, order, raw maps, logical IDs, measured clipping and all 200 exported sample values. The existing independent capture verifier also checks JSON/CSV agreement and recomputed summaries. Future Linux/Windows commands/artifacts are wired with development branch trigger exclusions unchanged. No compilation, JUnit, native probe, verifier, generator, build or GitHub workflow ran for this batch. All focus/scroll/IME/paste paths, combo/popup fitting, native internal font inheritance, physical mixed-DPI/detached displays, actual GPU behavior and complete GUI/Windows 11 acceptance remain pending.
