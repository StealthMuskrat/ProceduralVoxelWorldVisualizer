# Responsive Curve Editor and floating window ownership

Status: implemented on `codex/development-phase`, **uncompiled and untested**. Builds, JUnit/native execution, independent replay and GitHub testing remain paused by owner instruction. No historical pass total or acceptance gate changes.

The Curve Editor now separates scrollable authoring controls from a persistent Apply/Cancel area. `CurveLayout` reserves two full action rows, allowing those buttons to wrap at large font scales. The inspector, diagnostics, grid controls and plot scroll inside one child; action centers do not move with that scroll. Buttons cap hit widths to available content. Numbers and mode choices use the remaining row width when the label plus a 160-unit input fits, or put a wrapped label above a full-width field. Existing logical focus destinations and probe control names remain unchanged. Explicit native field IDs remain stable between wide and stacked presentations; numeric editing and validation still use the existing UiFields/session behavior.

The plot no longer imposes a 150-unit minimum width beyond narrow content. It uses the available width and caps height at 65 percent of the visible body, retaining the existing 170-unit preferred minimum when that fits. This keeps it possible to reveal the complete plot by scrolling even when controls above it are taller than the window. Layout changes only screen geometry, never curve samples or domain metadata. Existing frozen plot ownership cancels an active point/tangent/pan gesture when that geometry changes. Wrapped status, locked-endpoint and Auto-tangent explanations remain visible inside the body.

The body disables automatic native wheel scrolling. A wheel over the plot follows its existing zoom path; a wheel over other body space scrolls the inspector, without also changing zoom. Active gestures, held mouse buttons and popups suppress manual body scrolling. Native scrollbars and one-shot Go To Control scrolling remain available. The child uses a neutral local font multiplier, inheriting the Curve Editor's root multiplier exactly once; its mode/context popup uses that logical scale as well. This accounts for the pinned native implementation's immediate-parent font multiplication, rather than recursively multiplying each ancestor. See [CalcFontSize](https://github.com/ocornut/imgui/blob/v1.89/imgui_internal.h) and [binding declarations](https://github.com/SpaiR/imgui-java/blob/v1.89.0/imgui-binding/src/main/java/imgui/ImGui.java).

## Floating geometry and monitor coordinates

`FloatingWindowLayout` preserves the existing 840 x 760 FirstUseEver default and native INI restoration. It observes actual window bounds after Begin and corrects them at the next eligible frame boundary. It does not replace native settings before the first measurement; the initial frame may therefore show pre-correction geometry. It never writes User Config directly or publishes project/private state. The desktop's existing workspace capture continues to own ordinary INI persistence.

The pure `FloatingWindowBounds` retains the last expanded floating rectangle. Docked observations leave sizing to the dock node, collapsed title-bar height does not overwrite normal height, and any held mouse button defers correction/constraints. This permits dragging, resizing and detaching without a forced competing position. Valid measured user size/position remains stable. Releasing a drag permits a later fit. The current work area's up-to-eight-unit inset and minimum constraints use the existing modal geometry policy. An undocked tool resumes observation from its real current floating rectangle.

Without multi-viewport absolute coordinates, the helper fits to the main ImGui client work area and ignores OS monitor coordinates. With multi-viewport enabled it reads the backend's current monitor work rectangles on every frame, selecting the largest intersection with the measured floating window, then the nearest Manhattan rectangle gap, with inventory-order ties. Double intermediates avoid float edge/area overflow. It fits to the selected monitor work area, rather than a detached viewport's own client rectangle; fitting a window repeatedly inside its own shrinking client area would be incorrect. A removed monitor can therefore lead to a remaining monitor's correction plan. An empty monitor inventory uses the main client fallback only for a main/missing host; a live detached host with no monitor data receives no invented self-fitting plan. Missing viewport wrappers can be reassigned to main on correction. Monitor and viewport wrappers are temporary, never retained between frames. See [platform monitor binding](https://github.com/SpaiR/imgui-java/blob/v1.89.0/imgui-binding/src/main/java/imgui/ImGuiPlatformIO.java).

The Curve Editor first adopts this floating-tool policy here; a separate [status/utility follow-up](STATUS_AND_UTILITY_LAYOUT.md) extends it to thirteen utility/settings presentations. Modal and resource/bookmark selector policies remain as documented separately. Native platform frames, detached-host creation/migration, user dragging across mixed-DPI monitors, physical monitor removal/maximization and initial ready-editor presentation remain unverified. This is not complete specification 4.1.4/4.3 or Windows 11 acceptance. Extremely small work rectangles can be smaller than native title bars/fonts/action rows, so full control containment/usability cannot be guaranteed there. Per-monitor fonts/atlas/style metrics remain separate.

No model/schema/registry/generator/public engine API changes are needed: all new geometry and scrolling state is editor-local. Curve Apply retains its source/selection ownership and accepted-once staging; Cancel retains its private-discard behavior, with no project Undo entry or implicit file save.

## Deferred definitions

Sixteen `FloatingWindowBoundsTest` definitions cover first native observation, stable user size, oversize recovery, held-pointer deferral, docking, collapsed measurements, undocking, absent work, relative/absolute coordinate separation, largest overlap, nearest gap, stable ties, missing inventory, removed monitor recovery without repeated shrink, invalid ownership and finite extreme coordinates. Eight `CurveLayoutTest` definitions cover two-row footer reservation, overfull budgets, font-row changes, narrow width, short plot caps, spacious inspector allowance, invalid sizes and finite extremes.

`CurveLayoutProbe` defines actual production private Curve Editor scenarios at 720 x 600/scale 1, 360 x 240/global 2.5 and 720 x 480/global 2.5 times window 2.5. It uses real body wheel events to reveal the plot, checks zoom without body scrolling and body scrolling without zoom, measures window/body/plot/Cancel geometry, and clicks persistent Cancel. A held native pan is interrupted through an actual named ImGui window resize, followed by collapse/restore and Cancel. Private Properties values/raw seed, project/history/dirty state and profiler state must remain unchanged. The independent Python definition checks the case matrix, finite work margins, plot budgets and footer location plus ownership receipts. Future Linux/Windows workflow steps/artifacts are wired without changing trigger exclusions. None has run.

The probe has no GLFW window, renderer or real detached viewport and explicitly reports physical detached-window/DPI verification false. Monitor topology cases are pure synthetic definitions, not hardware evidence. Existing larger native curve gesture/navigation/publication definitions remain queued for the later full validation pass; screenshots, every focus/input/scroll combination, mixed-DPI monitor migration and full GUI acceptance remain pending.
