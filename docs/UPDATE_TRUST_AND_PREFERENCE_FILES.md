# Manual update trust and configuration publication

Status: implemented on `codex/development-phase`, uncompiled and untested. Owner instructions continue to defer compilation, native probes, independent validation and GitHub testing. Existing evidence belongs to its recorded baseline.

## Private manual-update settings

User Settings > Performance now uses UpdateTrustPanel and a separate UpdateTrustSession. Endpoint and approved-origin text remains private across Settings navigation, closing, hidden/collapsed hosts and failed writes. Periodic/general preference saves and manual Check for Updates read applied UserConfig values only. Editing or applying trust never requests a URL, downloads or installs anything. Normal startup still has an empty endpoint; the example hosts below exist only in controlled fixture definitions.

Apply checks exact displayed strings for both fields, cached validation and the complete opening active endpoint/ordered-origin values. A stale active base requires explicit Revert; unrelated preferences may change and are merged at publication. Successful persistence publishes owned canonical values and resets the private baseline. Failed writes preserve the active endpoint/list identity, exact raw draft and cached candidate for correction/retry. Errors have bounded non-null details and are sent to the shared Application Error Center as `UPDATE_TRUST_SAVE_FAILED`. Invalid private text blocks Apply instead of using a previous parsed configuration. Revert reloads the active values explicitly and retains the draft if that read fails.

The endpoint permits an HTTPS metadata URL with a path/query, but no credentials or fragment, and its origin must be explicitly approved. Approved entries must be HTTPS origins with no path other than an optional trailing slash, no query, credentials or fragment. Host case and the default 443 port canonicalize; repeated entries deduplicate in first-seen order. Invalid/empty port spellings, port zero and ports above 65535 reject. A blank endpoint explicitly disables checks while retaining any approved origins. This preserves the original manual-only TLS/no-redirect/allowlist policy. No endpoint is fabricated for the application.

New candidates are limited to 4096 endpoint UTF-16 units, 32768 origin-text units and 128 nonblank origin lines (duplicates also count toward that input limit). Complete native buffers reserve four bytes per provisional character plus a terminator, with exact displayed/private checks preventing truncation fallback. Historical oversized active text remains fully visible in an opening-sized buffer, but cannot republish until corrected within candidate limits. Existing historical user files are not rewritten or repaired; URL policy is checked at explicit Apply or manual Check. User Config shape/version 1 and schemas are unchanged.

UpdateChecker also rejects trailing metadata documents, overflowing format versions, non-text version/link values and over-64-KiB string metadata input before interpretation. Its network path retains bounded reads, explicit TLS certificate trust, timeouts, no redirects and no executable download/install. The request uses an immutable applied endpoint/allowlist snapshot. Actual TLS/HTTP/redirect/timeouts and public release-server integration remain unverified; the new native definition performs zero network calls.

## Shared configuration files

UserConfig and AppMetadata now use editor-only PreferenceFiles. Both readers consume at most 8 MiB plus the first excess byte from an opened stream; they no longer rely on an earlier file-size check that could race file growth. Both writers serialize an owned validated snapshot before creating directories or temporary files, reject output above the same 8 MiB limit, write a unique sibling, force its complete content and require atomic replacement. Unsupported replacement fails without a non-atomic fallback. Root targets reject before temporary creation. The writer is an implementation dependency and never appears in serialized preferences.

Failure before replacement preserves the earlier destination and does not publish new theme, bindings, trust or metadata. Cleanup removes only the writer's temporary file; if cleanup also fails, the original failure retains the cleanup exception as suppressed context. Application metadata version checks now reject integral values that do not fit the supported version representation. Startup default fallback and read-without-rewrite behavior remain intact. This is not an external-process locking protocol or a guarantee of directory durability through arbitrary device/power failure. Filesystems lacking atomic replacement now require another configuration location.

No project resource, raw Properties seed, document revision, dirty state, history or headless engine behavior is changed. Public UserConfig save/theme/binding entry points and AppMetadata save entry points retain their existing signatures; the update-trust publication helper is additive.
