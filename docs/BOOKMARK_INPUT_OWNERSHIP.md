# Bookmark and teleport coordinate input

Status: **implemented, awaiting validation** on `codex/development-phase`. No compilation, regression/native execution or independent replay was performed. GitHub testing remains paused by owner instruction.

Add Bookmark and Teleport now keep bounded raw X/Y/Z text rather than relying on integer-widget fallback values. Apply parses all required axes together as signed ASCII decimal 32-bit cells. Empty input, lone signs, overflow, fractional/exponent/hex syntax, whitespace and non-ASCII digits reject without creating a bookmark or calling navigation. Both integer endpoints are exact. A 2D dialog has X/Z only and keeps Y absent; 3D/world dialogs require Y. The existing Rename workflow edits only the name.

Each axis retains up to 128 characters in its pure editor model, with a bounded native input buffer. Invalid input stays visible until corrected or canceled. The owning tab and dialog cannot be replaced by another Add/Teleport request. Successful Apply and Cancel/Escape release input ownership. Active bookmark dialogs now block project file transitions, project history and package entry through the existing shared private-interaction predicate. Project/World UUID checks and the model bookmark draft's existing stale-target validation remain authoritative.

Coordinate validation precedes a navigation callback. A runtime callback failure keeps the dialog and entered text available for retry. Callback implementations remain responsible for side effects they perform before throwing; this change does not promise rollback of arbitrary external callbacks. Teleport remains view-only, while bookmark Apply remains one explicit parent transaction. There is no project autosave, new schema, coordinate saturation or implicit rounding.

`CoordinateTextTest` defines four deferred contracts for lexical/overflow retention, all-axis atomic parsing and integer endpoints, 2D/3D shapes and bounded/unknown-field rejection. `BookmarkInputProbe` defines production mouse/text correction, rejected sign/overflow, retained tab ownership, exact world endpoints, one bookmark Undo/Redo, injected callback rejection/retry and User Config isolation. It calls document Undo/Redo directly to isolate the bookmark transaction. `verify_bookmark_inputs.py` defines schema, exact persisted 2D bookmark and native-report checks. Linux/Windows workflow entries and artifacts are prepared without changing development trigger exclusions. None has run.

Physical keyboard/IME/DPI behavior, full viewport/camera endpoint handling, all private-dialog interactions, arbitrary callback side effects and Windows 11 acceptance remain pending. Existing bookmark/navigation evidence remains scoped to its recorded source, and no passing count advances.
