# Anchored resource and bookmark selectors

Status: implemented on `codex/development-phase`, **uncompiled and untested**. All builds, regression/native execution, Python replay and GitHub testing remain paused by owner instruction. No historical pass count or acceptance gate changes.

Resource reference selectors and the bookmark toolbar now use a shared bounded popup presentation. Their preferred sizes are 420 x 340 and 480 x 340 screen-coordinate units. Both dimensions shrink together to the hosting ImGui viewport's current client work rectangle, with the same up-to-eight-unit work margin as the modal policy. `PopupBounds` independently computes placement: align with the trigger's left edge, prefer below with a four-unit gap, flip above when that fits, and clamp to the work rectangle when neither side has enough space. In the last case the popup can overlap its trigger so that it retains its full fitted searchable list. Negative work origins and anchors outside the visible work rectangle use the same geometry.

`PopupLayout` queries and uses the current native hosting viewport locally each frame; it retains only measured value rectangles. Missing/invalid wrappers fall back to the main viewport, and invalid main work dimensions use a provisional preferred-size area. It does not retain a pointer, alter the host's position or save popup geometry. It submits explicit position, size and maximum constraints before BeginPopup only when the exact ID is open at the current popup-stack level. Closed selectors submit no NextWindow data. Explicit dimensions also bound the pinned BeginPopup implementation's automatic-size behavior. See the [pinned binding](https://github.com/SpaiR/imgui-java/blob/v1.89.0/imgui-binding/src/main/java/imgui/ImGui.java) and [native popup implementation](https://github.com/ocornut/imgui/blob/v1.89/imgui.cpp).

The search field fills available content width. A short wrapped result count leaves more room at large font scales, and the clipped scrolling list fills the remaining width/height instead of imposing a fixed 380/440 x 220 child. Full resource/bookmark labels and UUIDs are available on hover when they exceed their row. Trigger hit widths no longer impose a 100-unit minimum beyond narrow content. The resource field's adjacent label wraps onto another line when needed. Bookmark toolbar actions wrap and cap their hit widths to the remaining content, with a full-label tooltip when clipped.

The existing resource widget cache and per-tab bookmark query buffers still retain filters across closing. Drawing, searching, resizing and Escape do not invoke selection/navigation callbacks or alter the model. An actual selected UUID keeps its existing compatibility check, explicit callback and close behavior. Bookmark navigation continues to update selection only after accepted navigation. Both selectors explicitly support Escape without choosing the first match or clearing the existing UUID. Private Properties and seed input, document/history, engine identity, User Config and file-save policy are unchanged. No schema, registry, generator or public engine API changes are needed for this transient UI-only presentation.

The original scope is **hosting ImGui viewport client-work-area fitting**, like [modal fitting](DIALOG_LAYOUT.md). A separate [monitor work-area follow-up](POPUP_MONITOR_WORK_AREAS.md) now adds absolute-coordinate client/monitor intersections and visible-main popup recovery. The original batch does not independently intersect an offscreen detached host with OS monitor work areas; the follow-up retains explicit relative/no-inventory and physical acceptance limits. Context menus, ordinary combo boxes, tooltips themselves, other standalone utility window fitting, per-monitor font atlases/style scaling and full specification 4.1.4/4.3 acceptance remain pending. The Curve Editor has a separate [floating window and persistent-action policy](CURVE_LAYOUT.md). Extremely small native work areas may be smaller than one font/control and cannot guarantee usable controls or complete native containment.

## Deferred definitions

Twelve `PopupBoundsTest` definitions provide analytical below/above/right-edge/overlap/narrow/negative-origin/edge-equality/outside/tiny vectors, translation invariance, invalid sizes/null inputs and overflow-safe extreme anchor arithmetic. These definitions use pure immutable value rectangles without JNI.

`PopupLayoutProbe` defines actual production resource and bookmark selectors over 96 resources/bookmarks in an isolated ImGui context. Eight cases use 360 x 240 at global scales .5, 1 and 2.5, and 720 x 480 at global 2.5 times window 2.5. It explicitly clears retained queries, measures popup/query/list rectangles, checks clipped unfiltered submission, types a last-row filter, clicks the exact UUID, reopens with an empty-result query, and sends native Escape events. It checks exactly four resource and four navigation callbacks and retains a private resource ID/raw seed, project, history and dirty state. `scripts/verify_popup_layout.py` independently checks the declared case matrix, finite bounds, eight-unit work margins, contained query/list rectangles and callback/ownership receipts. Future Linux/Windows steps and artifacts are wired without changing trigger exclusions; none has run.

The probe has no GLFW platform window or renderer. Physical detached-window and DPI verification are explicitly false in its report. It does not certify screen rendering, every resource-selector embedding, ordinary None choices, navigation failure/retry, detached viewport migration, tiny font/control overflow or physical monitor/hardware behavior; existing ownership definitions cover other selector semantics separately.
