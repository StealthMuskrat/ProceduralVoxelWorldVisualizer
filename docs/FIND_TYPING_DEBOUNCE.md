# Find typing debounce — unvalidated implementation

Specification 4.4.1 requires costly searches to be debounced. The committed Find index was already cached and its results virtualized, but each different normalized typed query still performed a full scan during drawing. `ResourceSearchSession` now keeps one displayed immutable result and at most one pending request. At 1,024 or more indexed hits, text-only changes wait for 150 ms of quiet before one final scan. This is a fixed policy rather than a measured hardware cost estimate. Smaller indexes update immediately.

An initial index, committed revision/project-object replacement, explicit `filter(...)`/Find References request, changed non-text scope and empty query apply immediately and supersede pending typing. Scope comprises kind, enabled flags, root, directory, reference, containing-resource option and match mode. Identical normalized text reuses the existing deadline; returning to the displayed request cancels its pending successor without another scan. No query queue, timer, background worker or partial result publication is introduced. A monotonic nano-clock is supplied by the caller; a backward elapsed reading restarts the quiet interval, and ordinary nanoTime wrap is handled by elapsed subtraction.

Find labels pending work with “Updating search...” and marks the retained count as previous results. Those rows and Go To Selected are unavailable while pending. Native row identity includes the panel instance and session presentation version; pending replacement, completion, cancellation and source replacement retire predecessor row gestures. Footer eligibility also requires that the complete current filter matches the completed session request. Existing independent Apply/Discard/Cancel decisions retain their exact source/draft ownership.

Collapse cancels pending work; reopening a retained index starts a new quiet interval for a still-different typed request. Closing releases the index and results, so reopening evaluates the current request immediately against a fresh index. Scrolling and repeated frames do not extend a current deadline or rebuild unchanged data. None of these view operations publishes project edits, replaces private Properties input, or writes search state into User Config.

## Deferred validation definitions

Nine `ResourceSearchDebounceTest` definitions cover a 100-request burst, exact quiet-boundary behavior, immutable result caching, normalization/cancellation, all seven non-query scope dimensions, explicit bypass, same-revision replacement, revision refresh, hidden cancellation/clear, clock regression/wrap, exact threshold behavior and an actual 1,024-resource production-policy fixture.

`FindDebounceProbe` defines a real native 1,100-resource workflow with an injected clock: a six-step typed burst, previous-row/footer blocking, three synthetic layouts, an old row held through completion, fresh-result activation through the existing draft guard, actual keyboard typing, explicit immediate filtering, collapse restart, close/reopen rebuild and Clear Filters. Complete project/private/raw-input/history/dirty invariance is retained. The independent Python checker compares entire project/preferences files, explicit resource IDs/constant values and native receipts. Engine-only `FindDebounceConsumer` defines 486 analytic scalar observations and 288 EMPTY cells across both saved documents, root sizes 2/4 and signed chunks. Future Linux/Windows manual workflow commands and artifacts include these definitions.

No compiler, JUnit, native probe, independent consumer, Python checker or GitHub workflow has run for this batch. The validated baseline remains 922 tests / 120 suites. Main is the only branch and the workflow remains manual-only under the owner's development/testing pause. Index construction and the eventual full scan are still synchronous and unmeasured; this does not establish latency bounds, asynchronous search, complete large-project responsiveness, physical DPI/input/GPU/Windows 11 acceptance, or final specification conformance.
