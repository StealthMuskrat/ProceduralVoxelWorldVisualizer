# Project transaction feedback and settings recovery

Status: implemented on `codex/development-phase`, uncompiled and untested. GitHub testing remains paused by owner instruction. This work does not add passing evidence to the recorded baseline.

`EditorState.changeResult` returns feedback belonging to one transaction attempt: accepted/rejected status, the complete diagnostic count, an immutable copy of at most 256 diagnostic entries, and a runtime-failure message capped at 2,048 characters. Validation rejection and runtime failure are distinct. A validator that returns the same list object on repeated attempts still supplies current rejection details. A later thrown exception carries no earlier candidate diagnostics. Null or blank exception messages fall back to the exception description.

Import, membership and Project Settings now consume that result directly. They retain their private input/selection and retry ownership on rejection or runtime failure. The shared Validation Results list remains separately scoped to its last validation; a runtime failure does not relabel those earlier results as the current attempt. Runtime failures publish an actionable `PROJECT_EDIT_FAILED` entry in the Project log category. The existing boolean `EditorState.change` delegates to the same path. Accepted edits retain ordinary validation, revision and delta-history behavior; rejected candidates never replace the active document.

Project Settings additionally belongs to its exact EditorState, opening project object/revision and logical project UUID. It retains an independent complete opening project value snapshot. Frame-time checks stay inexpensive; Apply compares the complete values and permanently marks the session stale if it detects unsupported in-place mutation. Explicit Discard and Reload is required after that detection, even if the external mutation is later reversed. An unrelated tracked document edit remains conservatively stale. Saving, preferences and separate Properties selection/draft edits remain independent.

The desktop Apply path supplies all three displayed raw strings. Missing, extra or mismatched fields reject before local validation or any document transaction, so no earlier parsed seed/bound can be used for a different displayed value. Matching invalid text remains private for correction. Repeated unchanged edits retain cached feedback; a changed field clears old attempt feedback. Project Settings retains up to 256 candidate diagnostics with a total count and draws at most eight bounded details in a fixed-height scrolling child. Runtime failures use a short retry/Logs message. Stale Apply is disabled; reload returns before drawing successor fields in that frame.

Successful Apply and Cancel consume the settings session. A later draw of a consumed panel returns completion without silently opening a replacement. Explicit menu/diagnostic Open creates a new session. The shared desktop Settings host respects ImGui Begin visibility: collapsed windows skip their controls; window-X cancels the private settings and shortcut-capture state before returning. Collapsing alone retains the private text. Properties IDs, provisional seed text, user preferences and explicit project saves remain separate from settings publication. Project format, numerical semantics and headless API are unchanged.
