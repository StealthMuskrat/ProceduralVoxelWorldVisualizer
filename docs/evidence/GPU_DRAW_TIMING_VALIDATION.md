Both contexts record GPU_TIMING_NATIVE_PASS / GPU_TIMING_PASS. Native tests render fixed meshes, volumes and streamed scenes with timing disabled and enabled, then compare entire framebuffers byte for byte. They preserve an independently active GL_TIME_ELAPSED query, delete actual pending driver query names, discard stopped/replaced capture results and retain at most eight names per viewport. Unsupported capability behavior is covered by the deterministic backend test; the observed native contexts both support timing. See [normal report](gpu-timing-native.json) and [strict report](gpu-timing-gl30-native.json).

Each context exports three original and one replacement measurements, their full-width hexadecimal driver timestamp pairs and JSON/CSV captures. Independent Python computes `(end - start) modulo 2^counterBits` and checks the exact nanosecond values, original capture/issue stamp, project/context identity, labels and outcomes. It independently recomputes bounds, series statistics and nearest-rank percentiles and compares CSV fields against JSON. The ordinary and strict Linux reports also have identical per-mode framebuffer hashes. These software-rendered intervals are functional evidence, not representative hardware latency or throughput measurements.

GPU_DRAW is an optional offscreen command interval, including dispatch/scheduling gaps. It is not utilization, exclusive shader cost, total GPU frame time, presentation latency or a promise that driver API calls never stall. No production completion wait, glFinish or unavailable-result read is introduced. Pending results expire at two CPU-wall seconds or the narrower wrap interval. Arbitrary device-reset recovery, exhaustive thread traces, exclusive layer totals, representative hardware measurements, full GUI/DPI and Windows 11 hardware acceptance remain separate.
