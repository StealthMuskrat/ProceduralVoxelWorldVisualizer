Streamed World picking previously recomputed a procedural ray independently of GPU coverage. A solid procedural cell near the camera could be selected even though its chunk was not displayed. The renderer now exposes an immutable copy of chunk versions submitted by its latest render, excluding zero-vertex, culled, non-wanted and retiring allocations. ChunkScene traverses only matching GPU-committed DisplayLod inputs; generated halo data does not extend coverage. Traversal is bounded to the existing 1,000-block limit on the UI thread over resident immutable cells. Only the selected coordinate and a small version map cross to background tracing; no per-pick chunk/LOD snapshot collection is retained.

Pending LOD remeshes retain the last GPU-committed cell input until replacement publication. The extra retained coarse-array bytes count toward CPU scene usage and are released when the new version commits or its display is invalidated/removed. Foreign scene epochs and older displayed acknowledgements cannot replace picking cells. Upload gained a DisplayLod record component while retaining the previous four-argument constructor; record-pattern/reflection users must account for the additional component.

An occupied display proxy can cover an exact EMPTY preview cell. For Only Changes, an empty preview cell means no change to display; the full world may still be occupied. Such a hit opens that coordinate's exact full trace with an explicit LOD-proxy hint; it does not invent exact occupancy or search through the proxy into other geometry. A streamed miss reports no occupied voxel in displayed chunks without procedural ray evaluation. Async hit/error publication requires the same CPU scene, GPU renderer and drawn versions as the click, in addition to the existing request/revision/camera guards.

Eight new ChunkScenePickingTest methods check matching acknowledged/drawn versions; unshown halo/camera cells; fine/coarse pending publication; proxy versus exact occupancy; retained-memory release; invalidation/foreign epochs/closure; signed integer limits; and required-halo loading/reclamation at the 27-chunk entry limit. Existing test methods group some related checks together.

The minimum-limit fixtures initially timed out because distance-only preload ordering filled the entry budget before all required halo chunks were present. Required data now sorts before optional preload. When missing required chunks need slots, optional data is reclaimed, considering already displayed entries last. Two explicit cases verify a complete 27-chunk halo and a negative-boundary crossing generating nine additional chunks while retaining at most 27 entries. The hard limit remains in force if the configured required window itself exceeds capacity.

WorldPickingProbe adds real World image mouse clicks against streamed After SET, Before CLEAR and Only Changes/removal-ghost views. The camera is outside the one displayed root: each positive-X click must hit (31,0,0), not an unshown procedural cell near X=60. An off-center ray into an unshown solid region must miss. A queued trace is rejected after GPU-budget replacement. Negative-boundary travel keeps the CPU scene epoch and selects (-1,0,0) after old GPU coverage is retired. Python independently checks the root-face formula, stage final EMPTY traces, miss and lifecycle observations. Project JSON, revision and history remain unchanged.

StreamingRenderProbe checks picking coverage for actual native rendered/cull/empty/non-wanted allocations and epoch replacement, on its normal and strict OpenGL 3.0 paths. Existing rendering/compaction/indirect pixel checks still run.

Scope: native World observations use solid/ghost roots under CI/software GL; coarse proxy behavior is covered by math/scene tests and production Inspector wiring, not a separate native proxy-hint fixture. Point sprites, occlusion/depth/fog edge cases, arbitrary camera/mesh/DPI/load paths, physical OS input, full A01–A36 acceptance and Windows 11 hardware remain separate. No exact engine, archive or authored-project format changes occur.
