# Rectangular fixed mesh previews — unvalidated implementation

Specification 15.3.1 requires editable X/Y/Z analysis extents with maximum-dimension and total-cell limits. Fixed 3D Threshold Voxels, Point Cloud and Isosurface previously used one cube side. They now expose independent Extent X/Y/Z slider/text pairs. Each edit changes only that axis, uses the existing configured view limits and invalidates the owned preview epoch. Centers remain existing world-coordinate controls. A first explicit edit freezes all three counts from the existing uniform extent; switching representations or streaming retains the explicit fixed box. Counts remain view state and never enter Project Config.

`GridExtent` validates each render-grid axis in 1..256 and supplies exact cell/corner counts. Existing cube overloads retain their traversal and vertex ordering. Greedy meshing uses the dimensions and row stride of each face plane; point clouds visit exactly width × height × depth cell centers; isosurface extraction samples the rectangular corner grid and uses its own exact worst-case output/working-memory formulas. Snapped picking boxes now also support per-axis sizes and coordinate-overflow checks. World callers still use their existing cubes.

The real fixed-preview worker captures an immutable shape with its epoch, centers/snaps each axis independently, allocates the exact cell buffer and samples canonical fields at actual world coordinates. Admission uses the product and the largest configured axis, rather than a cube enclosing the box. Thus 3×5×7 is 105 cells, not 343. Isosurface admission includes 192 corners and conservative output growth. Existing cancellation, previous-frame retention, background execution and owned mailbox/GPU publication remain. A fixture-only receipt copies accepted geometry only when its explicit probe is enabled; ordinary startup does not retain that copy.

This batch covers the three fixed mesh modes. Volume textures, orthogonal slice images, streaming windows and World analysis retain their existing separate uniform extent controls. Rectangular volume/image plumbing remains in the implementation audit; this does not declare complete Tree 15 or XYZ-control conformance across every representation.
