# Help, About and context decisions

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This follows [Help and About](HELP_AND_ABOUT.md), [diagnostic footer decisions](DIAGNOSTIC_DECISIONS.md) and [Find/Trace decisions](UTILITY_DECISIONS.md). The validated baseline remains 922 tests / 120 suites.

Help and About collect each complete persistent footer before executing at most one action in displayed order. Escape suppresses that frame's footer. Native action IDs include a per-panel UUID and presentation version, outside stable body/field/result scopes. Closing, hiding or collapsing either window releases its footer presentation while retaining page/section, query, selected topic and history.

Help's footer belongs to the displayed immutable catalog, topic, page, exact raw query and navigation-history version. HelpSession advances its version on a new metadata publication, actual topic changes and successful Back. Normalized search/cache reuse, unknown links, empty Back and repeated current-topic session navigation do not advance it. A round trip back to the same Topic object still changes the history version, preventing a held Back from consuming the successor history. Equal-valued metadata replacement also creates a new catalog/version. An explicit HelpPanel.openTopic request retires its footer even when that topic/page/query are already current; context requests cannot inherit the old held Copy.

The topic shown before body rendering remains the footer's reviewed topic. Related/result navigation during that body invalidates the prior footer until the new topic is displayed. Post-draw checks re-read the exact topic/page/query/version and catalog before acting. Ordinary Clear and page/Back semantics remain: Clear resets search and shows Topics while revealing a retained selection; Back clears search and shows Guidance. Private unpublished metadata does not replace the active catalog, and complete copy still uses the frozen catalog's canonical options and related names.

About's footer belongs to its immutable initialized AboutDetails instance and displayed Runtime/Licenses section. It remains independent of document lifetimes and Help metadata publications. A held action cannot cross a section change or a recreated AboutPanel instance. About now receives the owning EditorState, with Desktop and the existing native fixture updated, so callback failures can reach the shared diagnostic store. Runtime strings and license/ownership summaries remain unchanged; copying still returns the complete displayed section. Help retains the existing help.about mailbox route without closing About.

Help clipboard and About clipboard/Help RuntimeExceptions are contained after footer collection. The editor records required APPLICATION entries under HELP_COPY_FAILED, ABOUT_COPY_FAILED or ABOUT_HELP_FAILED. Details are bounded to 1,024 UTF-16 units, with the exception class name used for missing/blank messages. Unrelated failure entries preserve a still-current footer's retry IDs. A callback that explicitly opens another Help topic or About section before throwing retains that successor; the old callback's failure is a global log, with no subsequent old footer action or inline feedback written over the successor. This is containment, not rollback of external side effects or arbitrary callback reentrancy support.

ContextHelp retains the explicit right-click gesture and one persistent Open Help action. Every accepted opening gets a new version and per-instance action ID. Its request owns the canonical topic, popup identity and native source host. A changed mapping, recreated ContextHelp instance or omitted native source frame closes the old popup when it is next submitted; it cannot adopt a held Open Help release. Consecutive reflow submissions retain the same request IDs. Escape suppresses opening/activation and closes a displayed request. Acceptance publishes one canonical topic to the existing UI-thread HelpRequests mailbox and retires the request. Popup fitting, scope inheritance and all primary control/menu actions remain on their existing paths.
