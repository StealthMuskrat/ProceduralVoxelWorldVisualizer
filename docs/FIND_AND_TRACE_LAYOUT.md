# Find and shared trace workspaces

Status: **uncompiled and untested** on `codex/development-phase` under the owner testing pause. This extends [unified Find](UNIFIED_FIND.md), [trace source navigation](TRACE_EXPLANATIONS_AND_NAVIGATION.md), [local navigation guards](DRAFT_POPUP_LAYOUT.md) and [diagnostic workspaces](DIAGNOSTICS_LAYOUT.md). It adds no passing evidence; the validated baseline remains 922 tests / 120 suites.

Find now keeps an available-width search field and Results/Filters chooser above its scrolling body. Match, kind, root, enabled and directory/reference controls live in the retained Filters section, with wrapped labels and available-width choices. Results can use the body without all filter controls stacked above them. Both sections identify the selected committed hit, including when it lies outside the current filters. Go To Selected, Show Filters/Show Results and Clear Filters occupy one persistent measured action row. Changing sections retains raw search/filter values, selected hit and the existing cached committed index/query; it performs no Apply or navigation by itself.

Result rows keep their existing two-line label/breadcrumb presentation, now with bounded text, available-width hit targets and explicit whole-pixel clipped strides including a tail item for native rounding. Hidden IDs remain keyed by the existing immutable hit key rather than row position. Search and section field IDs remain independent of body reflow. Clear Filters returns to Results and resets all filter controls, including references, while retaining a still-owned selected hit. The normal row-click navigation behavior is preserved; the footer provides another entry point to the same request.

`FindSelection` owns the exact Hit object selected from the shown result list and its EditorState, document lifetime, project object/UUID and revision. Tracked source changes or document replacement clear it; filter changes alone do not substitute another hit. Pending navigation keeps its first hit and refuses a second activation. Its source decision checks the selected hit/context again before Apply/Discard, while Cancel remains available. Find's draft decision now uses `NavigationGuardDialog` with the Find logical host, a scrolling explanation and three persistent bounded actions, replacing its older inline/wrapping presentation. Failed Apply retains the same request and private draft; stale decisions close without applying it. The existing Properties blocking, raw-seed/draft ownership, source UUID resolution and reveal behavior remain.

The shared `TracePanel` now allocates a measured trace viewport with a five-frame minimum, a scrolling body and two persistent action rows: Copy Trace Details, Go To Voxel Type, Go To Control, Copy Selected Value, Previous Page and Next Page. The viewport uses the remaining logical parent space; when Inspector controls above it exhaust that space, the Inspector can scroll to the trace viewport. The actions are persistent within that viewport, not a guarantee that every outer Inspector control remains simultaneously visible.

The steps list uses up to three measured text rows capped at 20% of the body; observations use up to five rows capped at 30%. Both have whole-pixel clipped strides, bounded single-line labels and stable hidden IDs. The body scrolls through the summary, freshness feedback, lists and selected value. Query/step selection can request one-shot scrolling to observations; it does not change values. Copy Selected Value always uses the full immutable value, independently of the displayed 4,096-unit Unicode-safe page. Empty filters disable selected-value/source actions instead of copying a previous observation. Final-type and observation links keep the existing frozen source fingerprints and draft guard.

`TraceObservationSelection` caches a projection by exact snapshot, step and normalized query. As before, a changed projection initially selects its first match. Its Review records the exact snapshot, step, original row index and immutable Row object. Source decisions require that review, the exact shown query spelling and snapshot to remain current through any pending Apply/Discard decision. Native row/action scopes also include the trace publication, step and selected row, so a held gesture cannot silently activate another trace's reused index. Query IDs change with a new trace publication while remaining stable during resize. This does not change procedural tracing, source hashes, trace retention budgets or snapshot construction.

Four `TraceObservationSelectionTest` definitions cover normalized projection reuse, empty/changed queries, another step/snapshot and full-value selection/invalid indices. Three `TraceLayoutTest` definitions cover independent row budgets, finite workspace extremes and invalid measurements. All twelve definitions remain unexecuted.

It defines actual Find query/row/footer clicks, cached clipped results from 400 added resources, failed draft Apply/Cancel, a bounded narrow decision/Escape, a cached exact threshold observation, stable row IDs, persistent geometry, a changed-observation pending-link rejection, full large Unicode value copying after a real page advance, empty-filter copy inactivity and exact full-trace copy callbacks. The Copy fixture records payloads through the production callback seam; it does not certify an operating-system clipboard.
